# ボードのサブエージェントの共通の決まり

`board-loop` から立つサブエージェント（`board-planner` / `board-worker` / `board-task` / `board-reviewer`）が、始める前に読む。
各サブエージェントの定義（`.claude/agents/board-*.md`）は、このファイルの節を見出しの名前で指す。
節の見出しを変えるときは、`subagent-rules.md` で grep して参照する側も直す。

## 呼び名

| 呼び名           | 何か                                                                                                                                      |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 人               | ボードを使う人。着手・承認・否決・中止・並び順・マージ・動作確認をする                                                                    |
| 監視役           | `/board-loop` を動かすセッション。次の手を選んでサブエージェントに渡し、報告を人に伝える。カードの作業はしない                            |
| `board-planner`  | 監視役から計画提案中の手（`plan` / `revise-plan`）を受け、計画を書く・直す                                                                |
| `board-worker`   | 監視役から実装中の手（`implement` / `revise-impl` / `ready`）を受ける。`implement` では締めの段だけを受け持ち、サブエージェントは立てない |
| `board-task`     | 監視役から `implement` の手で `next.step` が `task` のカードを受け、計画の最初の未チェックのタスクを含む節を倒してコミットする            |
| `board-reviewer` | 監視役から `implement` の手で `next.step` が `review` のカードを受け、PR の指摘を計画の `## AI レビュー` 節に書く。コードは直さない       |
| サブエージェント | 上の 4 つの総称。どれも監視役が直接立て、サブエージェントの中から別のサブエージェントは立てない。人ではない                               |

- **手:** 監視役がサブエージェントに 1 回で渡す仕事。`ai-board status --json` の `next.action` で決まる
- **段:** `implement` の手の中で、計画の状態から決まる区切り（タスクを倒す段 / レビューの段 / 締めの段）。
  監視役は `ai-board status --json` の `next.step`（`task` / `review` / `close` / `null`）で渡し先を決める
- **周:** 監視役がボードを 1 回読んで、手を高々 1 つ渡すまで
- **まっさらな文脈:** 監視役は手ごとに新しいサブエージェントを立てる。これは別のカードの文脈（前のカードで読んだコードや決めた事柄）を持ち込まないためである。
  同じカードの中で、1 つの `board-task` が節の中のタスクをまたいで文脈を持つのは構わない（読み直しが減る）。
  節ごとに新しい `board-task` を立てる形は残し、節をまたいで 1 つのサブエージェントに続けさせることはしない

## カードの読み書き

カードは `node "$MAIN/dist/cli.js" card ... --root "$MAIN"` で読み書きする（各定義では `ai-board card ...` と書く）。
データのワークツリー（`$MAIN/.ai-board/data/`）のファイルを直接書き換えない。データ用ブランチ `ai-board/data` へ直接コミット・push もしない。
PR は `node "$MAIN/dist/cli.js" pr ... --root "$MAIN"` で読み書きする（各定義では `ai-board pr ...` と書く）。
クラウドのセッションでは GraphQL が 403 になり `gh pr` が動かないので、`gh pr` は使わない。
何を書いてよいかはサブエージェントごとに違い、各定義のハードルールに書く。

## ワークツリーに入る

4 つのサブエージェントがどれも使う。監視役はワークツリーのパスを渡さないので、`board-task` / `board-reviewer` も自分でカードのワークツリーに入る。
作業は必ずカードのブランチのワークツリーで行い、`$MAIN` では作業しない。
`ai-board card show <cardId>` で本文と `branch` / `mr` / `skipGates` を読んでから入る。

- **`plan` の手で `branch` が null:** カード ID と同じ名前のブランチを `origin/main` から切る。
  ```bash
  git -C "$MAIN" fetch origin
  git -C "$MAIN" worktree add -b <id> "$MAIN/.claude/worktrees/<id>" origin/main
  ```
  同じ名前のブランチが既にローカルかリモートにあれば、作らずに止まって報告する
- **それ以外:** `branch` のワークツリーを使う（`git worktree list` で探し、無ければ `git worktree add "$MAIN/.claude/worktrees/<id>" <branch>`）。
  `branch` が null なら止まって報告する。入ったら `git pull --ff-only`
- `node_modules` が無ければ `npm ci`
- ワークツリーに未コミットの変更が残っていたら、前の手のサブエージェントが途中で止まっている。手を付けずに止まって報告する

ワークツリーのパスは `WT="$MAIN/.claude/worktrees/<id>"`（`git worktree list` で見つけたものならそのパス）と決める。

## タスクの数え方と `## AI レビュー` 節

`board-worker` の段の判定、`board-task` の節の選び方、`board-reviewer` の前提の確かめ、`board-planner` の計画の立て直しで、同じ決まりを使う。

数え方はボードの進捗バーと実装中の段の判定と同じで、`src/board/models/plan-task.ts` の `TASK_PATTERN` と `linesOutsideCodeBlocks` にある。

- **コードブロックの中の行は数えない。** タスクも `## AI レビュー` の見出しも、フェンスで囲んだコードブロックの外の行だけで見る。
  フェンスは ` ``` ` か `~~~`（3 文字以上、後ろに言語名などがあってよい。字下げの深さは問わない）で開き、
  同じ文字で同じ長さ以上の連なりだけの行で閉じる。閉じていないフェンスは無いものとし、後ろの行を数える。
  4 つの空白で字下げしたコードブロックは扱わず、その中の行も数える（字下げしたサブタスクを数えるため）。細かい境界は `plan-task.ts` の docstring にある
- タスクは、コードブロックの外で、行頭（字下げを含む）が `-` か `*` で、続けて `[ ]` / `[x]`（`[X]` も、`-[ ]` のように詰めた書き方も含む）の行である
- `## AI レビュー` 節があるかは、コードブロックの外にある `## AI レビュー` の見出しの行で決める
- `## AI レビュー` 節の直す指摘（`- [ ]`）も、普通のタスクとして数える。レビュー済みかを表す専用の状態は無い

`board-task` が 1 回の起動で倒す単位を**節**と呼ぶ。節は次のように決める。

- 計画の上から最初の未チェックのタスクの行を、上の数え方で見つける
- その行から上へたどって最初に当たる見出しの行（コードブロックの外の、`#` で始まる行）から、次の見出しの行（同じくコードブロックの外）の手前までを節とする。
  見出しの深さは問わない
- 節の中の未チェックのタスクを、上から順にすべて倒す。節の中の `[x]` のタスクは飛ばす

この決め方から、次がそのまま出てくる。特別な扱いは足さない。

- `## タスク` を `### <番号>. <題>` で区切った計画では、その `###` の節が単位になる
- `## AI レビュー` 節の直す指摘は、`## AI レビュー` の見出しから次の見出し（`### 見送った指摘` など）の手前までの節になり、まとめて倒れる
- 節に区切っていない計画では、`## タスク` 全体が 1 つの節になる

## 指摘の分け方

`board-reviewer` と、`revise-impl` で自分で AI レビューをかける `board-worker` が使う。

指摘はうのみにしない。挙動についての指摘は、差分とソースを読んで本当に起きるかを確かめてから採る。確かめられなかったものは採らない。
採った指摘を、次の 3 つのどれかに分ける。

- **直す:** 次のどれかに当たるもの
  - 誤った振る舞い（バグ、境界の取りこぼし、握りつぶした失敗や想定外の例外）
  - セキュリティ（`REVIEW.md` の Important。コマンド注入、書き込み境界の崩れ、トークンを読む経路など）
  - データの破損や消失、戻せない変更（DB のマイグレーションの書き換えなど）
  - 計画の Decisions、`CLAUDE.md` のハードルール、`REVIEW.md` の Important との食い違い
  - 振る舞いを足したのにテストが無いこと
- **見送る:** 次のどれかに当たるもの
  - 名前や書き方の好み
  - 振る舞いを変えない小さな整理や重複の除去
  - この PR の目的（計画の Why / What Changes）の外にある改善
- **人に判断してほしい:** 直し方に人の判断が要るもの。計画の Decisions そのものが誤っているように見える、
  直すと計画の Non-Goals に踏み込む、直し方が 2 つ以上あってどれを採るかで振る舞いが変わる、など

迷ったときは、直さなかった場合に人が動作確認や PR で気づけるかで決める。気づきにくい壊れ方なら直す。

`REVIEW.md` の「報告しないこと」に当たるもの（CI が検査するもの、`package-lock.json`、archive への移動、計画の言い回し）は、どこにも書かない。

## 直しきれないとき — 保留を書いて止まる

`board-planner` の `revise-plan` と `board-worker` の `revise-impl` で使う。
否決を自分では直しきれないと判断したら、コードにも計画にも手を付けず、次を書いてから止まる。

```bash
ai-board card hold <id> --gate plan   --reason "<なぜ止まったか、人に何を決めてほしいか>"   # revise-plan のとき
ai-board card hold <id> --gate verify --reason "<なぜ止まったか、人に何を決めてほしいか>"   # revise-impl のとき
```

`## レビュー` に 保留 が残り、カードは判断待ちの区画に出て、ループは次の周からこのカードを飛ばす。
書かずに止まると、次の周も同じカードに同じ手が渡される。
理由には、人がボタン（実装を直させる / 計画から立て直させる / 計画を直させる / 中止）を選べるだけのことを書く。

保留は人の判断を待つ止まりにだけ使う。品質ゲートを通せない、未コミットの変更が残っている、カードやブランチが見つからない、
といった止まり方では書かない（人がワークツリーを直す話で、判断のボタンでは解けない）。

## 動かして確かめるとき

計画の `## 動作確認の手順` や CLI・API を動かすときは、共有のカードを汚さないよう `AI_BOARD_DATA` で別のデータのワークツリーを指す。
指さなければ、カードへの書き込みは本物の `origin` の `ai-board/data` にコミットされ push される。
`AI_BOARD_DATA` の指すディレクトリの `origin` へ push するので、スクラッチパッドに bare リポジトリを作り、それを `origin` にした clone を指す。

```bash
S=<スクラッチパッドの下の作業用ディレクトリ>
git init --bare "$S/origin.git"
git clone "$S/origin.git" "$S/data"
AI_BOARD_DATA="$S/data" node "$WT/dist/cli.js" migrate --empty   # 空のデータ用ブランチを作る（カードを持ち込むなら --from <board.db の複製>）
```

`server.json`・ロック（`data.lock`）・PR の状態の控え（`cache/`）は、`AI_BOARD_DATA` の指すディレクトリの親に置かれる。
clone は `$S/data` のように専用のディレクトリにし、スクラッチパッドの根そのものを指さない。
clone・bare リポジトリ・一時ファイルは `$WT` の外（スクラッチパッドなど）に置く。`$WT` の中に置くと未コミットの変更として残る。
自分で起動したサーバは止めてから終える。

## ハードルール

4 つのサブエージェントに共通する。サブエージェントごとの決まりは各定義のハードルールにある。

- 渡されたカードの、渡された仕事だけを行う。ほかのカードに触らない
- `startedAt` / `rank` / `skipGates` を書かない。アイデアの表の区切り線も動かさない
- `## レビュー` に 承認 / 否決 / 中止 を書かない（plan と verify のどちらでも人が書く）
- `board-decide` のスキルを使わない。共有のボードのサーバの人の API（`/api/...`）と `server.json` も使わない
  （人の判断を書く入口であり、人がチャットで頼んだときに人のセッションだけが使う）。`AI_BOARD_DATA` で試しの clone を指して自分で起動したサーバを試すのは構わない
- 計画レビュー / 動作確認 / PR中 のカードに触らない。PR をマージしない
- 品質ゲート `cd "$WT" && npm run typecheck && npm run lint && npm run format:check && npm test` を通らないままコミットしない。
  計画ファイルだけの変更でも走らせる（ブランチが既に壊れていれば、そこへ積まずに気づける）
- カード ID・ブランチ名・PR 番号を推測で作らない。見つからなければ止まって報告する
- コミットは日本語の Conventional Commits。コミットと PR 本文の末尾の署名は、そのセッションの指示に従う
