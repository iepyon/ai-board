# adr — 今も効いている設計判断を、短く残す

`docs/architecture.md` は**今どう作られているか**、`docs/specs/` は**何を満たすか**を書く。
ADR は**なぜそう決めたか・何を捨てたか**を 1 判断 1 ファイルで書く。
読み手は「この不変条件を外してよいか」を決めたい人（人も AI も）。実装の説明書でも、開発の年表でもない。

## 形

Michael Nygard の形（背景 / 決定 / 結果）に、MADR の「退けた案」を短く足したもの。ひな形は [`template.md`](template.md)。

- `docs/adr/NNNN-<英小文字のケバブケース>.md`。番号は 4 桁の連番で、既存の番号は振り直さない。
- 見出しは `# N. <判断を一文で>`。「〜する」「〜しない」と言い切る。
- 状態と日付は先頭の 2 行。根拠は末尾の 1 行。
- **1 ファイル 30〜40 行に収める。** 背景は 2〜4 行、決定は 3〜6 個、結果は 3〜5 個、退けた案は 1〜3 個。
- 一覧は `docs/adr/README.md` の表。足したら・消したら表も直す。

## 何を ADR にするか

**今も効いていて、崩すと困り、コードを読んでも理由が分からない判断**だけ。目安:

- 不変条件を作った（ステージを保存しない、トークンを扱わない、shell を介さない）
- データの置き場所・正本を決めた
- 人と AI の権限の境界を引いた
- ループやサブエージェントの役割分担を決めた
- 有力な代案があり、それを退けた

**ADR にしないもの:**

- もう効いていない判断（置き換えられた・機能ごと消えた）。git log と計画の archive に残っているので十分。
- 些細な判断（見た目・文言・依存の版の上げ下げ・リネーム・列を 1 つ減らした など）。
- 理由が記録に残っていない規約。理由を書けない ADR は読み手の役に立たない。

迷ったら「半年後に誰かがこれを外そうとしたとき、止める理由として読ませたいか」で決める。

## 書き方

- 日本語・常体。リポジトリの言葉（ステージ・ゲート・提出・否決・監視役 など）を使う。
- **背景**は決めた時点の困りごとと制約。経緯の年表にしない。
- **決定**は今の形を書く。後で改訂した判断も、最新の形だけを書く（経緯は背景に 1〜2 行）。
- **結果**は良いことも悪いことも。新しく生まれた制約・残った課題を必ず入れる。
- **退けた案**は実際に検討された案（計画の Decisions・Non-Goals、否決の理由、閉じた PR）だけ。無ければ節ごと省く。**代案を発明しない。**
- **根拠に挙げた材料に書かれていないことは書かない。** 推測で理由を補わない。
- 実装の手順・API の一覧・テストの話・コミットのハッシュの羅列は書かない（根拠の行に主なものを数個だけ）。

## 状態

`採用` / `提案`（計画レビュー中）の 2 つだけ。

## 判断が変わったとき

**古い ADR を残して置き換えの鎖を作らない。** 今の形に合わせて同じファイルを書き直す。

- 決定の一部が変わった: 決定と結果を今の形に直し、日付に `（YYYY-MM-DD に改訂）` を足す。経緯が理由として要るなら背景に 1 行。
- 判断そのものが不要になった: ファイルを消し、一覧から外す。番号は欠番のままにする。
- 別の判断に吸収された: 吸収した側に背景 1 行で書き、古い方を消す。

古い判断の全文は git の履歴に残る。

## 新しい判断を記録するとき

1. 既存の ADR に同じ判断の延長が無いか見る。あれば書き直す（上）。
2. 無ければ最後の番号 +1 で `template.md` を写して埋める。
3. 一覧に 1 行足す。不変条件を作ったなら `CLAUDE.md` の該当節からもリンクする。

計画（`.ai-board/plans/<id>.md`）の `### Decisions` に ADR にすべき判断があれば、マージの前後で ADR に起こす。

## 履歴から書き起こすとき

材料は上ほど「なぜ」が書いてある。

1. 計画: `.ai-board/plans/archive/*.md`（`### Why`・`### Decisions`・`### Non-Goals`）。
   書き直しの経緯は `git log --format='%h %ad %s' --date=short -- .ai-board/plans/<id>.md`。否決の理由はデータ用ブランチの `cards/<id>/log/`。
2. 仕様: `docs/specs/*/spec.md`（MUST / SHALL NOT の理由文）。
3. git log: `git log --reverse --no-merges --format='%h %ad %s' --date=short`。浅いクローンなら先に `git fetch --unshallow origin main`。
4. 今のドキュメント: `CLAUDE.md` の不変条件、`docs/architecture.md`。**今も効いているか**はここで確かめる。

候補を並べたら「何を ADR にするか」でふるい、同じ判断を何度も直した系列は今の形の 1 件にまとめる。

## 品質ゲート

ADR は Markdown なので `npm run format:check` に掛かる。`npm run format` してから
`npm run typecheck && npm run lint && npm run format:check && npm test` を通してコミットする。
コミットは `docs: 〜の判断を ADR に残す` の形。
