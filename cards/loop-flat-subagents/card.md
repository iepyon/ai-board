## アイデア

board-worker がサブエージェントを入れ子で立てる形をやめる。タスクを倒す段と AI レビューの段も、監視役（board-loop）が `board-task` / `board-reviewer` に直接渡す。

- **段を監視役に返す。** board-worker は、implement で計画からどの段（タスクを倒す / AI レビュー / 動作確認を頼む / Ready）を進めるかを決めるだけにする。
  タスクとレビューの段は自分で立てず、どの段かを返す。返し方は計画で決める（`status --json` の `next` に段とタスクの行を持たせるか、board-worker の報告に書かせるか）
- **監視役が直接渡す。** `next` の段が「タスクを倒す」なら `board-task`、「AI レビュー」なら `board-reviewer` を立てる。1 周で渡す手は高々 1 つのまま
- **切り離しは保つ。** どのサブエージェントもまっさらな文脈で 1 手だけ進める。実装した作業者とレビューする作業者は別のまま
- **手順 0 の判定を合わせる。** 動いているサブエージェントの判定から、入れ子を前提にした記述（board-worker を止めても入れ子が残る、など）を外す

## 背景

2026-11-01 にクラウドのセッションで `/loop 5m /board-loop` を回したところ、`node-lts` の implement で board-worker が止まった。
クラウドのセッションではサブエージェントが `Agent` の道具を持てず、board-worker が board-task を立てられなかった。
`.claude/agents/board-worker.md` は道具を絞っていないので、定義を直しても解決しない見込み。

止まったカードは次の周でも `next` に選ばれるので、ループは毎周同じところで止まり、そのたびに約 7.6 万トークンを使う。
スマホの Claude Code からクラウドでボードを回す使い方（`issue-store`）では、実装中のカードを 1 枚も進められない。

## 論点

- **段の決め方をどこに置くか。** 計画の未チェックのタスク・`## AI レビュー` 節の有無・動作確認の提出から段は決まる。
  これを `status` の純関数に移せば、board-worker を呼ばずに監視役が段を決められる。board-worker の役目がどこまで残るか
- **手元のセッションとの違い。** 手元では入れ子が動いている。両方で同じ手順にするか、入れ子が使えるときは今のままにするか
- **タスクを一気に倒す流れ。** `loop-impl-review` でタスクを一気に倒し切る形にした。1 周 1 タスクになると周の数が増える。完了の通知を受けて手順 0 から続ける流れで足りるか
