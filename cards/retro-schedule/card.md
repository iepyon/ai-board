## アイデア

週に 1 回、クラウドの定期実行（Claude Code の `/schedule`）で、その週の振り返り（`retro-artifact`）と差し戻しと止まりのまとめ（`retro-stop-reasons`）を出す。

- **間隔。** 週に 1 回（曜日と時刻は人が決める）。研修の期間中は 1 周ごとに変えられるようにする
- **やること。** データ用ブランチを読んで 2 つのページを出すだけで、カードにもデータ用ブランチにも書かない
- **知らせ方。** 出したページの URL を、プッシュ通知（`decision-notify` と同じ仕組み）か、決まった置き場所で人に渡す

## 背景

振り返りは、頼み忘れると溜まり、溜まるほど読む気が失せる。
研修では、回した結果を時間で振り返ることが学びの中心になるので、決まった間隔で手元に届いてほしい。
振り返りに要るのはデータ用ブランチだけで、マージ済みのカードの PR の控えもデータ用ブランチ（`snapshots/`）にあるので、GitHub に問い合わせずにクラウドで回せる。

## 探索メモ

- `retro-artifact` と `retro-stop-reasons` ができてから着手する
- 定期実行のセッションは、ループの許可ルール（ADR 0012）とは別のセッションになる。書き込みをしない許可で足りるかを計画で確かめる
- 毎週同じ URL に出し直すか、週ごとに別のページにするか（前の週と比べたいなら別のページを残す）
- 書き込みをしないので、ボードの導出やカードの書き込み境界には触らない
