## アイデア

`board-decide` のスキル（`.claude/skills/board-decide/SKILL.md`、303 行）を短くする。
やることは「人がチャットで頼んだ判断を、画面と同じ人の API で書く」だけなので、手順書の大半を占める環境の細部と確かめの規則を、手順書の外に出すか削る。

削る・外に出す候補:

- **サーバを起動して止める 60 行ほどのシェル**（`mktemp`・`trap`・起動待ちの `node -e`・pid のファイル・URL の読み出し）。決まった手順なので、`scripts/` のスクリプトか `ai-board` の内部のコマンドにして、手順書からは 1 行で呼ぶ。
  ただし CLI に人の判断の入口は足さない（ADR 0007）。足すのは「サーバを一時的に起動して URL を返す」までにとどめる
- **Windows / MSYS の注意書き**（`MSYS_NO_PATHCONV`、`$!` と OS の pid の違い、SIGTERM の扱い）。スクリプトに閉じれば手順書から消える
- **理由の扱いの例外の規則**（会話の中にしか無いものを指す否決の理由を、Claude が起こして人に選ばせる）。今のモデルなら「人の言葉に無い要求を足さない、迷ったら人に選ばせる」の 2 行で足りるか
- **判断待ちの一覧の聞き方の細則**（手順 7 の、選択肢の数の制約への対応など）

残すもの: 人がこの会話で自分の言葉で頼んだときだけ書く、`decisions` / `droppableStages` が許さない判断を書かない、中止・着手を戻す・承認と読ませる宣言は書く前に確かめる、否決の理由は人の言葉、書いた後に AI の番ができたらループを続ける（ADR 0013）。

## 背景

2026-11-03 に、今の Claude のモデルを前提に、要らないアイデアと実装を洗い出した。
`board-decide` は人の判断を書く大事な口だが、手順書の 303 行のうち、判断の決まりそのものは一部で、残りはサーバの起動と停止、OS ごとの差、聞き方の細則である。
手順書が長いと、判断を頼むたびにそれを読み込む。決まった処理はコードにして、手順書には判断の決まりだけを残したい。

## 論点

- **起動のスクリプトの置き場所。** `scripts/` のシェル / Node のスクリプトか、`ai-board serve --once` のような CLI か。CLI にすると、サブエージェントも呼べる口が増える（人の API の書き込みはしないので境界は崩れないか）
- **テスト。** スクリプトにすれば、起動・停止・URL の読み出しを単体で確かめられる。今は手順書の中のシェルで、テストが無い
- **`board-loop` との重複。** `board-loop` も `dist-check` とビルドの同じ手順を持つ。まとめるか
- ADR 0007 の書き直しが要るか
