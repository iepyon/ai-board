## アイデア

紐付いた PR がマージされずに閉じたカードを、判断待ちの区画に出す。
人はそこで 中止 するか、作業を続けさせるかを選ぶ。

- **ステージは足さない。** 中止は工程の進捗と直交する終端の軸であり、閉じた PR はその候補にすぎない。
  ステージの導出（`stage-resolver.ts`）は今のまま、`reason` に「PR #n がマージされずに閉じた」と出す
- **振り分けで扱う。** 判断待ちの区画への振り分けは `src/shared/dashboard-sections.ts` に足し、テストもそこに書く
- **画面。** 判断待ちのカードに「中止」と、続けさせるための操作を出す

## 背景

`MrLifecycleState` には `closed` があり、GitHub からはマージされずに閉じた PR が `closed` で届く
（`github-client.ts` の `toLifecycleState`）。しかし導出のルールはどれも `closed` を見ていない。
そのためカードは何事も無かったかのように、手前の列へ黙って落ちる。
plan が承認済みなら 実装中 に、そうでなければ計画ファイルのある 計画レビュー に落ちる。
計画ファイルがブランチにしか無いときは、計画提案中 まで落ちる。

どの場合も、AI から見ると「自分が進める番のカード」に見える。人が意図して閉じた PR を、
AI が作り直しに行きかねない。Mastra Factory は、マージされずに閉じた PR の Review カードを
Canceled に動かす。ai-board ではステージを持たない方針なので、自動で中止にするのではなく、
人の判断を待つ形で拾うのが筋である。

## 論点

- **続けさせる操作の中身。** カードの `mr` を外して `branch` から解決し直させるのか、`branch` ごと外すのか。
  同じブランチで PR を開き直したときの扱いも決める
- **AI 側の扱い。** 判断が付くまで、ループ（`board-loop-skill`）はこのカードを飛ばす。
  そのことをカードの導出結果からどう読み取らせるか
- **Draft の PR が閉じたとき。** 計画を読んだ人が PR ごと閉じた場合は、否決とほぼ同じ意味になる。
  否決と同じ扱いにするか、区別するか
