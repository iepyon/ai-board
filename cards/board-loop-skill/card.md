## アイデア

ボードを 1 周進める Claude Code スキル。`/loop 15m /board-loop` で間隔運転する。

1 周で行うのは優先順に 1 つだけ。優先順は列の上から（人がドラッグで並べた `rank` の順）。進める先はいずれも AI の列で、★ の列では止まる。

1. 実装中のカードがあれば → 計画のタスクを 1 つ倒してコミットし、チェックを付ける
2. 計画提案中のカードがあれば → Plan モードで計画を立てて `.ai-board/plans/<id>.md` に書いてコミットし、
   push して `gh pr create --draft` で Draft の PR を出す。`ai-board card branch <id> <branch>` でブランチを紐付け、
   `ai-board card submit <id>` で `## レビュー` に plan 提出を書く
3. どれも無ければ → 人待ちを報告して終わる

マージ済みまで進んだカードは、計画を `.ai-board/plans/archive/<id>.md` へ移す。

**ハードルール**（人の承認を代行しない）

カードの読み書きは `ai-board card` の CLI で行う（`list` / `show` / `body` / `branch` / `submit`）。
以下のうちカードに関わるものは CLI が入口を持たないことで強制される。

- `startedAt` を自分で打たない。着手の指示は人が出す
- `## レビュー` に書いてよいのは 提出 / 再提出 だけ。承認 / 否決 / 中止 は人が書く
- `skipGates` を自分で足さない
- `rank` を書かない。並び順は人が決める
- 計画レビュー / PR中 のカードに触らない
- 品質ゲートを通らないままコミットしない

## 背景

今は人がセッションを開くたびに「次はどのカードを進めるか」を AI に指示している。
ボードには優先順（`rank`）も、人の判断が要る列（★）も、AI が進めてよい列も揃っているので、
次にやることはボードを読めば決まるはずである。

手順を 1 つのスキルに固めれば、AI エージェントは指示を待たずに 1 周ずつ進められる。
1 周で 1 つに限るのは、コミットと人の判断の単位を小さく保ち、止めたいときにすぐ止められるようにするため。
ハードルールは、間隔運転で人が見ていない間に、人の判断を AI が代行してしまわないためにある。

## 論点

- **読み取りを既定にする。** Mastra Factory のエージェント向け Skill は、人が委任するまで状態を変えない。
  ループでも、1 周の最初は状態を読んで報告するだけにし、書き込むのは人が委任した範囲（どのカードの、どの操作か）に限るか
- **推奨は 1 つだけ出す。** 報告の最後に次にやることを 1 つだけ示し、頼まれるまで実行しない形を、手動で呼んだときの既定にするか
- **推測で作らない。** カード ID・ブランチ名・PR 番号を推測で作らず、見つからなければ止まって報告する
- **PR の指摘への対応。** `pr-feedback-ai-turn` で「PR中 のカードに触らない」を緩める場合、
  「指摘のあとに修正が push されていないときだけ修正を push してよい」をハードルールに書き足す
