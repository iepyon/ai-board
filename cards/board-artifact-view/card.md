## アイデア

「ボードを見せて」と頼むと、アイデアの一覧・AI 作業中・判断待ちの 3 つの区画を並べたボードを、Artifact の 1 枚のページで出す。

- **中身は `status --json` をそのまま使う。** 判断待ちは `waiting`（出せる判断つき）、AI 作業中は `working`（止まっているかつき）、アイデアの一覧は `ideas`（rank の順、区切り線つき）を描く。ページの側でステージや区画を導出しない
- **今日外したダッシュボードより絞る。** グラフ・ログ・振り返りの集計・更新ボタンは付けない。新しくしたいときはチャットで頼み直す
- **判断はページから書かない。** 判断待ちのカードには出せる判断を並べるだけにし、書くのは今までどおりチャットの `board-decide` で行う

## 背景

ボードを見る入口は、ADR 0017 で画面と `status --html` のダッシュボードを外してから、`ai-board status` だけになった。
人向けの数行には判断待ち・AI 作業中・次の一手は出るが、アイデアの一覧は出ないので、どのアイデアが次に来るかは `--json` を読まないと分からない。
ボードはスマホから Claude Code のクラウドのセッションで回すことが多く、ターミナルの数行よりも、3 つの区画を一目で見渡せるページで見たい。
外したダッシュボードは、グラフ・ログ・更新ボタンまで抱えて本体が考えることが多くなったので、今回は見渡すことだけに絞る。

## 探索メモ

- 外す前の形は、コミット 981587f の親にある（`src/board/cli/status-html.ts`、`.claude/skills/board-dashboard/SKILL.md`、消した ADR 0015）。更新ボタンの仕組みは `board-artifact-dashboard`（PR #71）
- 計画で決めること
  - HTML を本体（`status` の出力）で組むか、スキルが `status --json` を読んで組むか。本体で組むなら ADR 0017 の「`status --html` を外す」を書き直す。スキルで組むなら見た目が毎回ぶれないように、テンプレートの置き方を決める
  - ADR 0017 の「`board-dashboard` のスキルを消す」との関係。今回の形を ADR にどう書くか
  - PR中 のカードの状態は `gh` の問い合わせが要る（`status` が 1 回だけ `refresh()` する）。クラウドのセッションで `gh` が使えないときの見せ方
