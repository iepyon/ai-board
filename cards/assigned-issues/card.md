## アイデア

チームで共有している GitHub Issues のうち、自分にアサインされた open の Issue を、
アイデアカードとして手元のボードに取り込む。

役割を次のように分ける。

- **Issue（共有物）**：何をやるか、誰がやるか。ボードからは読むだけで、書き戻さない
- **ai-board（SQLite）**：どう進めるか。着手・計画・承認という HIL の痕跡と、自分用の並び順

取り込むのは、対応するカードがまだ無い Issue だけで、既存のカードは更新しない。
Issue を閉じるのは、PR の本文に書く `Closes #n` に任せる。

## 背景

チケット管理はチームの共有物であり、ボードの SQLite に置き換えるものではない。
一方で、自分に割り当てられたチケットをどう進めるかは個人の作業であり、
手元で AI と一緒に計画・実装・レビューを回したい。

カードの正本をまるごと Issue に移すと、HIL ゲートの痕跡を信用できなくなる。
エージェントも人と同じログイン済みの `gh` で Issue を書けるので、
今は `ai-board card` の CLI が構造で守っている書き込み境界（`startedAt`・承認・`rank` を書かせない）が崩れるからだ。
反映も即時ではなくなり（localhost には Webhook が届かない）、並び順と区切り線を置く場所も無い。

アサインという外から与えられる事実だけを取り込み、判断の痕跡はローカルに残す形なら、この問題は起きない。
Issue は、PR と同じ「導出の入力になる外部ソース」がもう 1 つ増えるだけになる。

## 論点

- **対応の取り方。** `cards.issue`（Issue 番号、UNIQUE）の列を足し、何度走らせても重複しないようにする。
  カード ID は `issue-<n>` とし、手書きのカードと衝突したら警告して読み飛ばす
- **取り込みの起点。** サーバが `ForgePoller` と同じ形で定期実行するか（間隔は 5 分程度）、CLI やボタンで明示的に走らせるか
- **取得方法。** `gh api user` でログイン名を引き、`issues?assignee=<login>&state=open` を
  `--paginate` で全ページ取る。`pull_request` を持つ要素は PR なので外す
- **有効化。** `config.yaml` の `github:` に `importAssignedIssues: true` を書いたときだけ動かす。既定は無効
- **並び位置。** Mastra Factory は取り込んだ作業を並べ替えないが、ai-board には `rank` と区切り線がある。
  `rank` の無いカードは `created` の時刻で並ぶ（`dashboard-sections.ts` の `effectiveRankOf`）ので、
  区切り線より後に取り込めば「あとで考える」の側に入る。ただし区切り線が未設定なら、すべて「次にやる」に入る。
  取り込みの処理にも `rank` を書かせず、優先度は人が並べ替えて決める。区切り線が無いときの置き場所は別に決める
- **初期の本文。** `## 背景` に Issue の URL と取り込み時点の本文を置く。取り込んだ後は Issue に追従しない
- **取り込み後の変化。** アサインが外れたり、Issue が閉じられたりしてもカードは消さない。
  不要なら人が中止する。Issue の状態をバッジで出すかは後で決める
- **エージェントの手順。** `card show` に `issue` があれば、PR 本文に `Closes #<issue>` を書く。
  CLAUDE.md の「1 周の流れ」と `board-loop-skill` に足す
- **スキーマの変更。** 共有 DB を上げるとメインの古い ai-board が開けなくなる。開発中は `AI_BOARD_DB` で別の DB を指す
- **Issue が閉じられた理由。** Mastra Factory は、Issue が not planned や duplicate で閉じられるとカードを Canceled へ移す。
  ai-board では中止を書くのは人なので、カードは動かさず、閉じた理由をバッジで出して中止を促すところまでに留めるか
- **自動開始の信頼ルールは持たない。** Factory は Issue の作成者がリポジトリに書き込めるときだけ自動で作業を始める。
  ai-board は取り込んでもアイデアに置くだけで、着手は人が打つので、このルールは要らない
