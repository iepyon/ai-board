## 手順（実装後）
Linux / macOS で（AI_BOARD_DATA でスクラッチの clone を指す。.claude/skills/board-loop/subagent-rules.md の「動かして確かめるとき」）
1. npm run build の後、node dist/cli.js status --json --only next,waiting,forge --root . が 3 項目だけを出す
2. status --json --only server,cards.id,cards.stage の cards の各要素が id と stage だけを持つ
3. --only nosuch / --only cards.id --html / --only next.id が使い方を出して終了コード 1
4. core.autocrlf=true の clone を AI_BOARD_DATA で指して card create し、card.md に \r が無い
5. （計画から追加）--pid-file に書けないパス（ディレクトリなど）を渡すと、起動をやめて終了コード 1。書けるパスなら OS の pid が書かれ、node -e 'process.kill(pid, "SIGTERM")' で止まる
Windows の Git Bash で（人が確かめる）
1. 既定の設定（core.autocrlf=true）で新しく clone し、npm ci && npm run typecheck && npm run lint && npm run format:check && npm run build が通る
2. node dist/cli.js を起動すると既定のブラウザ（rundll32 url.dll,FileProtocolHandler）でボードが開き、サーバは落ちない
3. Claude Code（Windows）で board-decide のスキルを使い、スクラッチのカードを 1 枚承認する。jq 無しで、サーバの起動（--pid-file）・書き込み・停止まで通り、止めた後に status の server が null
4. /board-loop を 1 周回し、ボードを読む手順（status --json --only next,waiting,forge）で止まらない

## 自分で動かした結果（Linux、スクラッチの clone）
- 1〜4: すべて期待どおり（1 は next/waiting/forge のみ、2 は [{"id":"verify-crlf","stage":"idea"}]、3 は 3 つとも終了コード 1、4 は \r が 0 件）
- 5: 書けないパスで終了コード 1 と「pid のファイルを書けないので起動をやめます」の 1 行。書けるパスでは pid が書かれ、ログに ai-board  http://127.0.0.1:5791 が出て、process.kill の SIGTERM で止まった
