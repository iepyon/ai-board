## アイデア

PR中 で人が読む証拠（PR の本文の `## 動作確認の結果`）に、CI の結果と、直したことの確かめを足し、書き方を表にそろえる。
人が PR を開いたとき、「AI が何を確かめ、何を確かめていないか、CI は通っているか」を 1 か所で読めるようにする。

- **CI を Ready の前に確かめる。** 締めの段で、PR の最新コミットのチェックの結果を引く（`ai-board pr checks <n>` を足す）。
  - 赤なら、締めの段のまま直して push し、CI を待ち直す
  - 走っている間は待つ（待つ時間には上限を置く）
  - 直せない、または上限まで待っても終わらないときは、Ready にせず `止まった` で手を終え、人に伝える
  - 結果（チェックの名前・成否・URL）を `## 動作確認の結果` の表に入れる
- **`## 動作確認の結果` を表にそろえる。** 「確かめたこと / コマンド / 結果」の表にする。結果は `通った` / `落ちた` / `走らせていない` のどれか。
  品質ゲートと CI も行に入れる。`走らせていない` 行には、理由と、確かめるのに何が要るかを書く。走らせていないものを `通った` と書かない
- **fix は直す前に落ちることを確かめる。** バグの直し（AI レビューの直す指摘を含む）では、足したテストが直す前のコードで落ち、直した後で通ることを確かめ、表に書く。新しい機能では書かない

## 今の形（2026-11-04 時点）

`merge-verify-into-pr` で動作確認の列は無くなり、人の確かめは PR中 の 1 回にまとまった。
締めの段（`.claude/skills/board-loop/implement.md` の 2.2）で、実装した本筋のセッションが計画の `## 動作確認の手順` を動かし、
PR の本文の `## 動作確認の結果` に、人が動かす手順・AI が動かした結果・計画から変わった点・確かめられなかったことを箇条で書いている。
書き直すときは節を差し替え、二重にしない。

足りないのは次のとおり。

- **CI の結果をどこからも取っていない。** `.github/workflows/ci.yml` は PR で走るが、ループも人の読む証拠もそれを見ない。CI が赤のまま Ready になりうる
- **結果の形がそろっていない。** 箇条書きで、走らせたものと走らせていないものの区別が書き手まかせになっている
- **直したことの確かめが無い。** fix のテストが、直す前のコードで本当に落ちるかを確かめていない

## 背景

Mastra Factory は、レビュー役が走らせたテストの結果を PR のチェックとコメント（Factory test report）に出す。
環境の失敗は合格としない、走らせていないものを成功と書かない、と決めている。
また、CI の結果ではセッションが起きないので、エージェントがツールで CI を確かめる設計にしている。

## 論点

- **チェックの出どころ。** GitHub には Checks API（`check-runs`）と Commit Status API（`status`）の 2 系統がある。両方を合算するか。全件を引く（`--paginate`）
- **待つ時間の上限と間隔。** CI は数分かかる。締めの段の中で何分まで待つか。`sleep` で待つか、別の周に任せるか
- **CI を直すのは締めの段。** 今の締めの段は「コードに触らない」決まりなので、CI を直すときだけ触ってよいと書き直す。直した差分は AI レビューをやり直さない（今の、直す指摘を倒した後と同じ扱い）でよいか
- **チェックが 1 つも無いリポジトリ。** CI を持たないリポジトリでは、表に `走らせていない（チェックが無い）` と書いて Ready にしてよいか
- **fix の判定。** 「バグの直し」をどう見分けるか（計画のタスク、コミットの型 `fix:`、AI レビューの直す指摘）

## 外したもの

- **ボードのカードに CI のバッジを出す** — `pr-checks` のカードに戻した。ポーリングの問い合わせがカードごとに増えるので、`forge-poll-budget` と合わせて考える
- **画面の変更のスクリーンショット** — `pr-screenshots` のカードに切り出した。クラウドから PR に画像を置く場所を決める必要がある

## 探索メモ

2026-11-03 のアイデアの整理で、`pr-checks` をこのカードにまとめた。

2026-11-04 に、`merge-verify-into-pr` の後の形に合わせて、人がチャットで次のように決め直した。

- CI の結果は、締めの段で Ready の前に AI が確かめる。ボードの表示とポーリングは増やさない（ボードのバッジは `pr-checks` に戻す）
- CI が赤なら締めの段で直してから Ready。走っている間は待ち、直せない・終わらないなら止まって人に伝える
- `## 動作確認の結果` は「確かめたこと / コマンド / 結果」の表にそろえる
- 「直す前は落ち、直した後で通る」テストは fix のときだけ書く
- スクリーンショットはこのカードから外し、新しいカード（`pr-screenshots`）にする
