## アイデア

「ボードを見せて」で公開するボードの Artifact に更新ボタンを付け、押すとその時点の最新の状態で描き直す。
ボードの見せ方の中心を、ローカルの Web 画面から Artifact のダッシュボードに移す。既存の Web 画面（`src/web/`）はいったん消してもよい。

- **更新ボタン。** 公開した HTML は書いた時点の写しで、今は新しくするたびにチャットで「ボードを見せて」と頼み直している。ボタン 1 つで最新にしたい
- **位置づけはダッシュボード。** 読むための写しではなく、開いたままにして状態を追う画面として扱う
- **Web 画面は消す候補。** クラウドのセッションには常駐のサーバが無く、Artifact がボードを読む唯一の手段になっている。手元でも Artifact で足りるなら、画面を 2 つ持ち続ける理由が薄い

## 背景

2026-11-01 にスマホの Claude Code からクラウドのセッションでボードを回したとき、カードが動くたびに「ボード見せて」を頼み直した。
`status --html` の出力をそのまま公開しているので、ページはひとりでには新しくならない。
同じ日に、ボードの PR のリンク（`target="_blank"`）が Artifact の中で開かないことにも気付いた。

## 論点

- **最新の状態をどこから取るか。** Artifact のページは、ボードのデータ（`ai-board/data` ブランチ）や `gh` にも、手元のサーバにも直接は届かない。
  候補: Artifact のランタイムの機能（ページから Claude に頼む・共有の状態を持つ・つながったデータを読む）で取り直す / ボタンでセッションに頼み、Claude が `status --html` を出し直して同じ URL に公開し直す / GitHub 上のデータ用ブランチを読む。どれがこのアカウントで使えるかを計画で確かめる
- **判断のボタンをどうするか。** 今の HTML には判断のボタンが無く、判断はチャットで `board-decide` に頼んでいる。ダッシュボードにするなら、ボタンを持たせるかどうか。持たせるなら書き込み境界（人の判断は人だけが書く）を崩さない形にする
- **Web 画面を消す範囲。** サーバは判断の書き込み（`board-decide` が叩く人の API）と PR 番号の書き戻しにも使っている。消すのは画面（`src/web/`）だけか、サーバごとか
- **リンクが開かない件。** `status-html.ts` の `target="_blank"` を、Artifact の中で開く書き方に直す。どの書き方が開くかは確認用のページで試している途中
- **Artifact の型。** 「ボードを見せて」の手順は今、型（Dashboard など）を使わないと決めている（型はアカウントごとに違い、手元のテストで形を確かめられないため）。ダッシュボードの型に乗せるなら、この決まりを見直す

## 探索メモ

2026-11-03 の対話で、人から次の 3 点を求められた。

- **ボタンを押すだけでダッシュボードが出る。** チャットで頼み直したり、Claude がその場で集計し直したりせずに、最新のダッシュボードが表示されるようにする
- **作る手順をスキルにする。** ダッシュボードを作る・作り直す手順を、`.claude/skills/` のスキルとして持つ
- **プログラムで生成する。** 集計とページは、Claude がその都度手で書くのではなく、コード（`ai-board` の CLI など）で生成する。同じデータからは毎回同じダッシュボードができるようにし、集計は `src/shared/` などの純関数にしてテストを書く

同じ日に、試作として Claude が手で集計したダッシュボードを Artifact（Dashboard の型）で公開した: https://claude.ai/artifact/3Uz2MmYZN34fdmErp3KM4K
`status --json` の `cards` / `timeline` / `loopSteps` から JSON を 3 つ作って添付し、ページの中で集計している。載せたもの:

- 主な数字: マージ済みの枚数、着手からマージまでの中央値と最長、1 枚あたりの人の番の割合（中央値）、否決されたカードの枚数と回数、アイデアの残り
- 列ごとの滞在時間（マージ済みのカードの 1 枚あたりの中央値。人 / AI で色分け）。合計は 1 枚の長いマージ待ちに引っ張られるので中央値にした
- 日ごとのマージ数、カードごとの人と AI の時間の割合、ループの手ごとの平均時間とトークン、手の結果の内訳、マージ済みのカードの表

試作で分かったこと:

- データは手元の CLI でしか読めないので、Artifact に載せたのは写しで、ひとりでには新しくならない。「ボタン 1 つで最新」には、ボタンから Claude に頼んで出し直す・データ用ブランチを GitHub から読む、などの経路が要る（論点の「最新の状態をどこから取るか」）
- 集計の中身は `bottleneck-chart`（区間の中央値・ボトルネックの判定・否決の回数）と重なる。どちらで持つかを計画で決める
