## アイデア

計画ファイルのタスク（`- [ ]` / `- [x]`）を数えるとき、コードブロック（```` ``` ```` で囲んだ範囲）の中の行を数えないようにする。

- **進捗バー。** `src/board/repositories/plan.repository.ts` の `TASK_PATTERN` で数える前に、コードブロックの中の行を外す。純関数にしてテストを書く
- **作業者の手順書。** `board-worker.md` の段の判定と `board-reviewer.md` の前提（タスクがすべて `[x]` か）を、同じ数え方に揃える
- **数え方を 1 か所に寄せる。** 手順書の文言で数え方を書き分けず、「進捗バーと同じ数え方」と参照する形にする

## 背景

2026-10-30 に `loop-impl-review` を実装していたとき、計画の中に `## AI レビュー` 節の書き方の例として、コードブロックの中に `- [ ] src/foo.ts の bar() で…` という行があった。
作業者は `board-worker.md` の段の判定でコードブロックの中を数えないことにしたが、既に入っている `board-reviewer.md` の前提と、ボードの進捗バーは、コードブロックの中の行も数える。

このままだと、タスクを全部倒しても例の行が未チェックのまま残り、レビューの段に入れず、進捗バーも 100% にならない。
計画にチェックボックスの書き方を例として載せるのは自然なことで、例を書くたびにカードが詰まるのは困る。
`loop-impl-review` では計画の例の行を書き換えてしのいだ。

## 論点

- **コードブロックの見分け方。** ```` ``` ```` と `~~~` の両方、言語名付き、入れ子のリストの中の字下げされたフェンスをどこまで扱うか。`src/shared/markdown.ts` の変換と見分け方を揃えられるか
- **字下げしたコードブロック（4 つの空白）。** 計画の書き方では使わないので、数えるままでよいか
- **既にある計画への影響。** archive 済みの計画で、コードブロックの中に `- [ ]` を書いたものがあるか。あれば進捗の見え方が変わる
