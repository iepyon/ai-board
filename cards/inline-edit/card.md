## アイデア

カードの詳細で、本文を整形した見た目に近いまま編集できるようにする。
`body-preview`（PR #33）で入れた「読むときは整形、書くときは Markdown の textarea」の、書く側を置き換える。

- **本文の Markdown は書いたとおりに残す。** 画面から Markdown を作り直さない。
  保存されるのは人が打った文字だけで、触っていない箇所の改行や記法は変わらない
- **やり方は 2 つの候補から計画で選ぶ**（下の論点）

## 背景

`body-preview` で本文を整形して読めるようになったが、直したいときは「編集」を押して Markdown の textarea に切り替える。
整形された見た目で読んでいた箇所を、記号の付いた等幅の文字の塊の中から探し直すことになり、読む画面と書く画面の行き来で目が迷う。
特に `## 論点` の長い箇条書きの 1 項目だけを直したいとき、全文の textarea を開くのは大げさである。

一方で、記号を一切見せない WYSIWYG（Notion 型）は避けたい。保存のたびに画面の状態から Markdown を作り直すので、
一文一行の改行がつながる、記法の書き方が揃え直されるなど、人が触っていない箇所まで本文が書き換わる。
`## レビュー` のエントリの文字が変わると CLI の差し替えは拒まれ、エージェントが本文を差分で読むときの邪魔にもなる。

## 論点

- **A. 節ごとの編集。** 整形した表示の節（`##` の見出しで区切った単位）を押すと、その節だけが Markdown の textarea になり、ほかは整形のまま残る。
  `src/shared/markdown.ts` の変換をそのまま使えて依存も増えない。節の範囲を元の文字列の行範囲として持ち、そこだけを差し替える
- **B. 書きながら整形する編集欄（Obsidian のライブプレビュー型）。** CodeMirror 6 などの編集部品で、見出し・太字・コードを整形して見せ、
  カーソルのある行だけ記号を出す。編集中もずっと見た目が近い。依存（数百 KB）が web に入り、`markdown.ts` とは別の解析器で整形することになる
- **節の単位。** A のとき、`## アイデア` のような大きい節で切るか、段落・箇条書きの項目まで細かく切るか。
  細かいほど直す所に近いが、行範囲の計算が複雑になる
- **`## レビュー` の扱い。** 承認 / 否決 / 中止の追記ログは人も書き換えてはいけない。A ならこの節を編集の対象から外せる。B では節の中を読み取り専用にできるか
- **外での書き換えとの関係。** `body-preview` の「編集中は書きかけを守り、外で書き換わったら知らせる」を、節ごとの編集や編集部品でも保てるか
- **全文の textarea を残すか。** 節をまたぐ大きな書き換え（節の並べ替え、見出しの付け替え）のために、今の全文編集も残すか
