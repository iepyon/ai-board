## アイデア

カードの詳細で、本文を Markdown として整形して表示する。直したいときだけ編集に切り替える。

- **既定は閲覧。** 見出し・箇条書き（入れ子を含む）・強調・インラインコード・コードブロック・リンクを整形して出す
- **編集は切り替え。** 「編集」を押すと今の textarea に替わり、保存か取り消しで閲覧に戻る
- **HTML を介さない。** 本文は人もエージェントも書ける場所なので、`dangerouslySetInnerHTML` は使わず、React の要素として組み立てる
- **変換はテストできる場所に置く。** Markdown を表示用の木に変える部分は純関数にして `src/shared/` に置き、テストを書く（`src/web/` はテストの対象外）

## 背景

今のカードの詳細は、本文を Markdown の生のまま等幅の textarea に出しているだけである（`BodyEditor.tsx`）。
アイデアカードの本文は `## アイデア` / `## 背景` / `## 論点` に分かれ、論点は太字の見出し付きの長い箇条書きになることが多い。
これが記号付きの等幅の文字の塊として並ぶので、どこからどこまでが 1 つの論点なのかを目で追いにくい。

ボードを開いて本文を読むのは、着手するか、並べ替えるかを決めるときである。
その判断のために読む場面の方が、本文を書き換える場面よりずっと多い。読む方を既定にしたい。

## 論点

- **ライブラリを入れるか。** `marked` や `markdown-it` は HTML の文字列を返すので、サニタイズ（`DOMPurify` など）と組で入れることになる。
  `react-markdown` は React の要素を返すが、依存が大きい。カードの本文で使う記法は限られているので、必要な分だけを自前で変換する手もある
- **`## レビュー` の見せ方。** 承認 / 否決 / 中止の追記ログも本文にある。ほかの節と同じに整形するか、判断の履歴として別の形で出すか
- **表示の幅。** 詳細パネルは幅が狭い。長いコードブロックや表を折り返すか、横にスクロールさせるか
- **編集中の外部の書き換え。** 今の `BodyEditor` は、外から本文が変わると編集中の内容を上書きする（`useEffect`）。編集を切り替えにしたとき、閲覧中は追従し、編集中は守るか
