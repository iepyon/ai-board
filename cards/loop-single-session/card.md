## アイデア

ループを本筋のセッション 1 つで回す。計画と実装は本筋のセッションが自分で行い、監視役と作業者（`board-planner` / `board-worker`）に分けるのをやめる。
別の文脈に切り分けるのは **AI レビューだけ** にする（書いた者が審査しない、はモデルの強さとは別の原則として残す）。

- **計画と実装。** `ai-board status --json` の `next` を読み、本筋のセッションがそのカードの手を自分で進める。カードが変わるときは、新しいセッションか `/clear` で始め、前のカードの文脈を持ち込まない
- **AI レビュー。** 次のどちらかにする（論点）
  - 案 A: 実装を終えた本筋のセッションが、レビューのサブエージェントを 1 つだけ立てる。入れ子にならないので、クラウドのサブエージェントが `Agent` を持てない制約にはかからない
  - 案 B: レビューは別のセッションで行う
- **消えるもの。** 監視役の手順（`ListAgents` で動いている作業者を確かめる、`prompt` を 3 行に絞る、報告と完了の通知の順番の扱い）、`board-planner.md` / `board-worker.md`、`subagent-rules.md` のうち作業者向けの部分
- **残すもの。** 人の判断を代行しない、書き込み境界（`ai-board card` の CLI の構造、提出 / 再提出 / 保留だけ）、`next` に従い 1 度に 1 手、品質ゲート、ステージの導出

## 背景

2026-11-03 に、今の Claude のモデルを前提に、要らないアイデアと実装を洗い出した。そのときの話し合いで人が「サブエージェントは要らない気がする」と言い、このカードを起票した。

サブエージェントに分けた理由（ADR 0011）は、今はほとんど効いていない。

- 監視役の文脈を膨らませない → 1M の文脈があり、1 周ぶんの作業で溢れることはまず無い
- 前のカードの文脈を持ち込まない → カードごとに新しいセッションか `/clear` で始めれば済む
- 自動の要約で前提が落ちても続けられる → 要約がほとんど入らない
- 人の判断を書く口から切り離す → frontmatter の hook はサブエージェントの中で一度も発火しなかった（`decide-guard`、PR #73 を PR #74 で戻した）。それでも作業者は決まりを破らなかった

一方、サブエージェントのせいで起きた問題が積み重なっている。

- **auto モードで止まる（`loop-ready-permission`）。** サブエージェントの操作は「人が会話で頼んだ」ことが分類器から見えず、手順書どおりの commit・push・Ready が拒まれた
- **`/code-review` が使えない（`reviewer-code-review`）。** クラウドのサブエージェントは入れ子にできず、呼べても指摘を受け取れない
- **報告の受け渡しの決まり（ADR 0014）。** 報告と完了の通知の順番、`loop start/finish` の記録の照らし合わせ、`ListAgents` の判定などの決まりが要った
- **繋ぎ込みのためのカード。** `loop-fresh-context`、`loop-three-roles`、`loop-flat-subagents`、`loop-continue-on-handback`、`loop-resume-after-decide` など、マージ済みのかなりの数が作業そのものではなくサブエージェントの繋ぎ込みのためだった

## 論点

- **レビューの切り分け方。** 案 A（レビューのサブエージェントを 1 つ）か案 B（別のセッション）か。案 A なら `board-reviewer` を残して呼び出し元を変えるだけで済む。案 B は人の手間が増える
- **メトリクスの記録の定義。** 今の `loop/` の 1 手の記録は「サブエージェント 1 回」を単位にし、トークンと時間を完了の通知の `usage` から取っている。
  サブエージェントを外すと、本筋のセッションが手の始まりと終わりを自分で書く形になり、トークン数は取りにくくなる。
  メトリクスとチャートは研修で改良する（`harness-metrics`・`bottleneck-chart`）ので、記録の単位と取れる値を一緒に決める
- **研修の題材。** 研修で伝える 3 つの観点の 1 つ「文脈の切り分け」の題材が、レビューの切り分けだけになる。「なぜレビューだけ切り分けるのか」を教える形にするか（`training-seed` の研修の資料にかかわる）
- **カードの区切り。** カードが変わるときに文脈をどう切るか（新しいセッション / `/clear` / 同じセッションで続ける）。間隔運転（`/loop 5m /board-loop`）とどう両立させるか
- **ほかのカードとの関係。**
  - `slim-worker` は `board-worker` の手順書を縮める案だったが、このカードで手順書ごと無くなるなら丸ごと書き直す
  - `loop-ready-permission` は本筋のセッションで回せば起きなくなる見込みがある。確かめてから閉じる
  - `slim-decide` の `board-decide` から `board-loop` へ続ける決まり（ADR 0013）も、続け方が変わる
- **ADR。** ADR 0011（3 役）と 0014（報告で次の周へ進む）を書き直すか消す。0012（許可ルール）と 0013 も見直す
