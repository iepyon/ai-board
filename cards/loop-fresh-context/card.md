## アイデア

ループの 1 手ごとに、まっさらな文脈で作業させる。ループを回すセッションは「監視役」に徹し、
`status` を読んで次の一手を選び、その手を新しい文脈の作業者に渡して、結果を受け取って報告するだけにする。

- **作業はサブエージェントに渡す。** `plan` / `revise-plan` / `implement` の 1 手を、カード ID と手の種類だけを渡した新しいサブエージェントに実行させる。
  サブエージェントはカード本文・計画ファイル・PR を自分で読み直す
- **監視役の文脈には要約だけを残す。** 監視役が受け取るのは「何をしたか・PR の URL・止まった理由」の数行だけにし、ファイルの中身や差分を持ち込まない
- **`/clear` には頼らない。** `/clear` は Claude Code 本体のコマンドで、スキルやエージェントから実行できない

## 背景

`/loop 1m /board-loop` で 1 つのセッションがループを回し続けると、複数のカードの計画・実装・レビューの記録がすべて同じ文脈に積み上がる。
前のカードで読んだコードや決めた事柄が残ったまま次のカードの計画を書くことになり、カードに書かれていない前提が紛れ込みやすい。
文脈が長くなると自動の要約が走り、どこまでが今のカードの情報なのかも曖昧になる。

計画を立てる前に文脈を空にしたいが、`/clear` はループから実行できない。
人がループを見守りながら回すこと自体は続けたいので、セッションを分けるのではなく、1 手ごとの作業だけを切り離したい。

## 論点

- **切り離す単位。** `plan` / `revise-plan` だけを渡すか、`implement` のタスク 1 つや `/code-review` まで含めて全部の手を渡すか
- **渡す情報。** サブエージェントには会話が見えないので、人がこのセッションで口頭で伝えた補足は届かない。
  補足は必ずカード本文（`## 探索メモ` など）に書く運用にするか
- **監視役が止まる条件。** サブエージェントが品質ゲートを通せずに止まったとき、未コミットの変更や理由を監視役がどう受け取り、人に伝えるか
- **別案: 1 周ごとに新しいセッション。** launchd などから `claude -p "/board-loop"` を起動すれば、監視役ごと毎回まっさらになる。
  この画面で経過を見られなくなるので、`loop-activity`（ループの様子をボードで見る）と組み合わせる前提になる。確認なしで動かす権限の設定も要る
- **`loop-activity` との関係。** 監視役が「今どのカードを触っているか」を書く場所と、並列ループの「宣言」をまとめて考えるか
