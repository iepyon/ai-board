## アイデア

`ai-board status --json` が出す形を、内部のモデルとは別の「外に出す形」として、型と Zod のスキーマで決める。内部のモデルを変えても、外に出す形は詰め替えの関数を直すだけで保てるようにする。

- **外に出す形を決める。** 今の `StatusReport`（`src/board/models/status-report.ts`）のうち、`cards` は `StatusCard = Omit<BoardCard, 'body'>` で内部のモデルをそのまま出している。これを、外に出す項目だけを並べた専用の型にする
- **詰め替えの関数を置く。** `BoardCard` などの内部のモデルから外に出す形へ詰め替える関数を 1 か所に置き、`get-status.query.ts` はそれを通して返す
- **Zod のスキーマを正にする。** 外に出す形はスキーマから型を引く。テストで、`status --json` の出力がスキーマを通ることを確かめる
- **今の出力は変えない。** 最初は今の出力と同じ項目で固める。項目を減らすかどうかは論点で決める
- **読む側を書き出す。** 外に出す形を誰が読むかを、スキーマの近くに書く（`board-loop` / `board-decide` のスキル、`board-view` の `render.mjs`、戻す React の画面）

## 背景

画面とサーバは ADR 0017 でいったん外したが、後で React の画面とバックエンドを戻す予定である。ADR 0018 は「画面と共有する API 専用の型を作るかは、サーバを戻すときに決める。今は `StatusCard` が内部のモデル（`BoardCard`）をそのまま出している」と先送りした。
`status --json` を読む側は既に 3 つある。`board-loop` / `board-decide` のスキルは `cards.latestReview`・`cards.prState`・`cards.skipGates` などを読み、`board-view` の `render.mjs`（PR #103）は `waiting`・`working`・`ideas`・`forge`・`loop` を読む。これに React の画面が加わる。
内部のモデルはリファクタリングのたびに変わり、そのたびに `status --json` の出力も知らないうちに変わる。出力の形を決めているものが無いので、項目の名前が変わったり消えたりしても、テストでは気付けない。スキルが判断を読み違えたり、ページが作れずに止まったりして、初めて分かる。
`board-view` の見た目を直す 4 枚のカードはどれもこの出力に寄りかかったページを触るので、先に形を固めておくと手戻りが減る。
この提案は 2026-11-11、React とバックエンドにするためのリファクタリングを洗い出したときに出た。

## 論点

- **項目を絞るか。** `cards` の全項目を出し続けるか、読む側が使う項目だけに絞るか。絞るなら `--only` で指せる項目も変わる
- **版を持つか。** 外に出す形に版の番号（例: `schemaVersion`）を付け、読む側が古い形を見分けられるようにするか
- **置き場所。** スキーマを `src/shared/`（ブラウザでも動くもの。ADR 0018）に置いて React からも import できるようにするか、`src/board/` に置いて型だけを `import type` で引かせるか
- **スキルの文書。** スキルが読む項目を、スキーマの項目名と照らして確かめる手順を足すか
