## アイデア

「ボードを見せて」で公開するページ（`ai-board status --html`）を、今の実装が持っている情報に追いつかせる。
手元の Web 画面と `status --json` には出ているのに、このページには出ていないものを載せる。

- **載っていない見込みのもの**（2026-11-03 に `src/board/cli/status-html.ts` と `status --json` の項目を見比べた範囲）
  - カードごとの区間の時間（`timeline`。人を待った時間と AI が使った時間）
  - カードごとのループの手の一覧（`loopSteps`。1 手ごとの時間とトークン）
  - 実装中のカードの段（`next.step`: タスクを倒す / AI レビュー / 締め）
  - 飛ばす宣言（`skipGates`）
- **今あるもの**: 判断待ち・AI 作業中・アイデア（区切り線つき）・マージ済み・中止、ヘッダのループの一行、「AI 稼働中」の印、タスクの進み（n/m）、PR、最新のレビュー
- **ページは今のまま 1 枚の自己完結の HTML** にする。更新ボタンやダッシュボード化は `board-artifact-dashboard` の範囲で、このカードでは扱わない

## 背景

2026-11-03、クラウドのセッションで loop-permissions を回しながら「ボードを見せて」でボードを公開した。
`status --html` は 2026-11-01 に入り、11-02 にループの稼働の印が足されたが、そのあとに入った区間の時間やループの手の記録は載っていない。
クラウドのセッションにはボードの画面（サーバ）が無く、このページがボードを読むほぼ唯一の手段なので、画面と同じことが読めてほしい。

## 論点

- **画面との揃え方。** Web 画面（`src/web/`）にあってページに無いものを洗い出し、何を載せるかを決める。全部は載せず、スマホで読める量に絞るか
- **ずれを防ぐ。** 今後 `status --json` に項目が足されたとき、ページの更新を忘れないようにする手（テストで項目の網羅を見る、など）を入れるか
- **リンクが開かない件。** `target="_blank"` が Artifact の中で開かない件は `board-artifact-dashboard` にある。こちらで一緒に直すか

## 探索メモ

- **ループの手の記録にトークンと時間が残らないことがある。** 2026-11-03、作業者の報告（SubagentHandback）が、`usage`（トークンと時間）の入った完了の通知より先に届いた。
  監視役は報告を受けた時点で `ai-board loop finish` を書くので、`--tokens` と `--duration-ms` を付けられなかった。
  ページに 1 手ごとの時間とトークンを出すなら、記録が欠ける件も一緒に直したい（完了の通知を待ってから finish を書く、後から数字を足せるようにする、など）
