【手順】
共有の DB を汚さないよう AI_BOARD_DB で別の DB を指す。5673 はメインのサーバが使っているので、ポートは 5799 にする。
1. ワークツリーで `npm run build`、`export AI_BOARD_DB=$(mktemp -d)/board.db`、`node dist/cli.js --port 5799 --no-open`（画面は http://127.0.0.1:5799）
2. `node dist/cli.js card create --title 試し --id try-hold < /dev/null` → 画面で「着手」。R=localhost:5799/api/cards/try-hold/reviews
   - `card submit try-hold` → `curl -X POST $R -H 'content-type: application/json' -d '{"gate":"plan","kind":"承認"}'`
   - `card submit try-hold --gate verify` → `{"gate":"verify","kind":"否決","reason":"検索が遅い"}`
3. `node dist/cli.js card hold try-hold --gate verify --reason 直すには大きすぎる`
   - 期待: `status` で try-hold が判断待ちに出て、次の一手に選ばれない
   - 期待: 画面の判断待ちの区画に try-hold が出て、保留の理由と「実装を直させる」「計画から立て直させる」「中止する」が見える
4. 「計画から立て直させる」に理由を書いて押す → 期待: 計画提案中に戻り、次の一手が `revise-plan try-hold`
5. `card submit try-hold --resubmit` → API で plan 承認 → 期待: 実装中に戻り、次の一手が `implement try-hold`（revise-impl ではない）
6. 動作確認の列のカードの詳細パネルに「計画から立て直させる」が出る
7. `curl -X POST $R ... -d '{"gate":"verify","kind":"保留","reason":"x"}'` → 期待: 400
8. （新）保留は否決のゲートにしか書けない: plan 未提出・plan 提出（計画レビュー待ち）・plan 承認済み・verify 提出（動作確認待ち）で `card hold` が 1 で終わり、何も追記しない

【計画から変わった点（AI レビューの指摘を受けて）】
- `card hold` は、そのゲートの最新の判断が否決のときだけ書ける。以前は verify を plan 承認前に拒むだけで、承認済みの plan に保留を書いて人の承認を打ち消せた
- 「提出済みなのに計画ファイルも Draft の PR も見えない」止まりは、PR の状態を引けているとき（GitHub に接続し、初回の取得を終えたとき。`MrStateProvider.synced`）だけ立つ。github: の無いボードや起動直後に、計画レビュー中のカードが中止のボタンだけで判断待ちに並ぶのを防ぐ
- Draft に戻された止まりの文言を「GitHub で Ready に戻すか、下の判断のボタンで差し戻すか中止してください」にした（verify を飛ばすカードでは「実装を直させる」が出ないため）
- 止まっているカードに `## レビュー` のエントリが無いとき、「提出の記録がありません」の文言を出さない
- 作業者の手順書: revise-plan で計画が archive 済みなら plans/ へ git mv で戻す
