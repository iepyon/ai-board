## アイデア

人の判断（承認 / 否決 / 中止、着手 / 着手を戻す、ゲートを飛ばす、並べ替え）を書く人の API を、サブエージェントの中からは呼べないようにする。
今は「サブエージェントは board-decide を使わない」が手順書の決まりだけで、技術的には止めていない（CLAUDE.md、ADR 0007）。

- **hook で止める。** Claude Code の PreToolUse の hook で、人の API への書き込み（board-decide が叩く口）を調べ、サブエージェントの中からの呼び出しなら拒否する
- **チャットからの依頼は今のまま。** 本筋のセッションで人が「〜を承認して」と頼む流れは、確認なしで通す
- **同じ段への戻りの上限。** AI が同じゲートで差し戻しを受けて戻ってくる回数に上限を設け、超えたら AI の番にせず人の判断に回す（無限の往復を止める）
- **書き込みの境界は今のまま。** CLI（`card-cli.ts`）が AI に承認を書かせない構造はそのまま残す。これは CLI の外の、人の API の側の穴を塞ぐもの

## 背景

Mastra Factory は「人の承認はプロンプトで頼むのではなく、遷移ポリシーで強制する」を中心に置いている（`transitionPolicy` の `isHumanTransition`、`approval_required` の拒否）。
エージェントへの指示は破られ得るが、仕組みで拒否された操作は実行されない。

ai-board は CLI では同じ考え方を構造で守っているが、人の API は「手順書を読んだ AI が使わない」ことに頼っている。
研修で「HIL をどの部品が担っているか」を示すときにも、ここが手順書だけだと説明が弱い。

## 論点

- **サブエージェントの見分け方。** hook の入力でサブエージェントの中かどうかを判別できるかを、今の Claude Code で確かめる。判別できなければ別の手（サブエージェントに渡す環境変数など）を考える
- **ループの監視役は止められない。** 監視役は本筋のセッションで動くので、この案だけでは監視役が手順書を破るのは止められない。中止・承認にだけ人の確認（許可の ask）を足すかは別に決める
- **hook の置き場所。** `.claude/settings.json` に置くと、fork した研修のリポジトリにも同じ守りが入る。Windows でも動く書き方にする（`windows-shell` の方針）
- **上限の値と数え方。** 否決の回数で数えるか、`loop/` の手の記録で数えるか。上限を超えたときに `status` の次の一手と判断待ちにどう出すか
- **ADR。** ADR 0007 の「技術的には止めていない」を書き直す
- **harness-guide との関係。** HIL を担う部品の案内は、この守りができてから書く方が正確になる
