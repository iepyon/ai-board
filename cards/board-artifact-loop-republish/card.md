## アイデア

ループが 1 手を終えるたびに、ボードの Artifact（`board-artifact-view`）を同じ URL へ出し直す。開けばいつも最新のボードが見え、「ボードを見せて」と頼み直さずに済む。

- **出し直すのはループの手の終わりだけ。** 手を終えて `loop finish` を書いた後、ボードのページが公開済みなら同じ URL へ出し直す。公開していなければ何もしない
- **人の判断の後も出し直す。** `board-decide` で判断を書いた後も、カードの区画が変わるので出し直す
- **ページにボタンや状態は持たせない。** ページから Claude に頼む入口は作らない

## 背景

`board-artifact-view` のページは、頼んだ時点の写しで、ひとりでには新しくならない。
ADR 0017 には、判断待ちに気付くのは「ループが手の終わりにチャットで伝えるか、人が `status` を見たとき」とある。
ボードはスマホから Claude Code のクラウドのセッションで回すことが多く、カードが動くたびに頼み直すのは手間がかかる。
ボードが変わるのはほとんどがループの手の終わりと人の判断の直後なので、そこで出し直せば、開いたままの画面に近い使い方ができる。

## 探索メモ

- 外した ADR 0015（コミット 981587f の親の `docs/adr/0015-dashboard-refresh-via-session.md`）は、ページの更新ボタンからセッションへ `send_message` で頼む形だった。ページから頼む入口を持たせると、`mcp` を宣言したページは共有できず、ページを見ている人がセッションへ送れる入口もできた。今回はページから頼まず、セッションの側から出し直すので、その入口は要らない
- ADR 0015 で退けた「ページの中でステージを導出する」は、今回も採らない。ページは `status --json` の写しを描くだけにする
- 計画で決めること
  - 出し直す先の URL をどこに覚えるか（セッションの中だけか、セッションをまたぐか）
  - 出し直すのに失敗しても手は止めない（記録は見るためのもの、という ADR 0008・0014 の考え方に揃える）
  - 出し直すたびに Artifact の承認が要るなら、ループの許可ルール（ADR 0012）に足すか
- `board-artifact-view` の後に着手する
