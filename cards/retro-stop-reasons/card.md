## アイデア

「差し戻しと止まりをまとめて」と頼むと、指定した期間の差し戻しの理由とループの止まりを Claude が読み、傾向と手順書の直しどころを Artifact の 1 枚にまとめて出す。

- **計画の差し戻しの理由。** `status --json` の `cards[].reviews` のうち、plan の 差し戻し の理由を集め、似たものをまとめる。差し戻しの後の再提出の理由も並べる
- **PR中 の指摘。** PR中 の差し戻しは今は PR のコメントで返す（ADR 0016）。`gh` で、期間内にマージされた PR の人のコメントを読む
- **ループの止まり。** 1 手の記録（`cards[].loopSteps`）のうち、結果が `advanced` でない手（`stopped` / `held` / `failed` / `unknown`）を、カード・手・段と並べる。保留（`plan 保留`）の理由も添える
- **直しどころ。** 傾向から、どの手順書（`.claude/skills/board-loop/` の `plan.md` / `implement.md` / `fix-pr.md` / `rules.md`、`.claude/agents/board-reviewer.md`）のどこを直すとよさそうかを書く。直すのは別のカードで行い、このページは提案に留める
- 本体（`src/`）には手を入れない

## 背景

数字の振り返り（`retro-artifact`）では、何回差し戻したかは分かっても、なぜ差し戻したかは分からない。
理由はカードの `## レビュー` と PR のコメントに文章で残っていて、読めば手順書のどこが足りないかの手がかりになるが、カードごとに散らばっていて通して読むことがない。
文章を読んで似たものをまとめるのは集計の関数より Claude のほうが向いているので、数字の振り返りとは分けて、読む仕事として切り出す。

## 論点

- **止まりの理由の置き場。** 1 手の記録は結果だけで、なぜ止まったかを持たない。理由はループがチャットに書いたものと、カードの `## 探索メモ`・計画・PR に散らばる。どこまで拾うか
- **廃止したゲートの記録。** 古いカードの本文に残る `verify` の差し戻し（6 件）は `reviews` に出ない（`RETIRED_REVIEW_GATES`）。本文を直接読んで含めるか、ADR 0016 より前は扱わないか
- **差し戻しの読み分け。** 計画の差し戻しには、手順書の不足によるものと、`## 人に判断してほしいこと` への既定と違う答えを返すためのもの（`board-decide` の決まり）がある。分けて読む
- **手順書の版。** 1 手の記録から手順書の版（`harness`）を外した（ADR 0014）ので、版ごとの内訳は出せない。必要なら、手順書を変えたコミットの時刻で期間を区切って比べる
