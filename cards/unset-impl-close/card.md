## アイデア

GitHub が未設定（`config.yaml` に `github:` が無い）のボードで、承認の後の実装の手を最後まで進め、PR の無いままマージ済みまで運べるようにする。

- 実装の手の節ごとの `git push` を、未設定のボードでは飛ばす（コミットだけ）
- 締めの段の `ai-board pr checks` / `pr edit` / `pr ready` の代わりに、動かした証拠をどこに書き、何をもって人の番（PR中 にあたるもの）とするかを決める
- 人がどうマージし、何をもってマージ済みとするか（メインのチェックアウトに計画の archive が入る、など）を決める

## 背景

研修はオフライン（GitHub に届かない環境）を前提に回せるようにしたい。
`forge-unset-decide` で未設定のボードでも判断と次の一手が出るようになり、`branch-plan-review` で計画レビューまでは立つ見込みになった。
ただ承認の後の実装の手は、節ごとの push と、締めの `pr checks` / `pr edit` / `pr ready` を前提にしているので、未設定のボードでは止まる。

## 探索メモ

- 2026-11-07、`branch-plan-review` の調べで見つけ、人の答えで別のカードにした
- 2026-11-07 の調べ（コードを読んで確かめた）
  - **マージ済みの判定は今の規則で足りる。** ステージの規則 1（メインのチェックアウトの `.ai-board/plans/archive/<id>.md` があればマージ済み）があるので、人がメインのチェックアウトでカードのブランチを `git merge` すれば、archive された計画が入ってマージ済みになる。`stage-resolver.ts` は変えなくてよい
  - **締めの後の「人の番」の印が無い。** PR が無いので PR中 の列は立たず、カードは 実装中 のまま。ブランチの計画が archive 済みなので、段は `close`（`resolveImplStep`、`src/board/services/impl-step.ts`）になり、`implement.md` の「archive 済み: `ai-board pr ready` だけをやり直す」が毎周選ばれて失敗し続ける
  - **証拠の置き場が無い。** 今は締めの段で PR の本文に `## 動作確認の結果`・`## 判断してほしいこと`・`## 見送った AI レビューの指摘` を書く（`implement.md` の 2.2 の 3）
  - 節ごとの `git push` と 5 の `branch.ab +0 -0` の確かめ、締めの段の `ai-board pr checks` は、未設定のボードでは飛ばせばよい（CI は無く、手元の品質ゲートが唯一の確かめになる）
  - 締めの後に人が直しを返す口（PR のコメントと `fix-pr`、Draft への戻し）は、オフラインでは無い。残るのは `decide reject`（計画から立て直させる）
  - ブランチの archive を読むのは、`branch-plan-review` の「ブランチの archive は読まない」（規則 1 で PR中 がマージ済みに見える）と関わる。止まりの判定にだけ使い、ステージの導出には渡さない形にする必要がある
- 人の答え（2026-11-07、チャットで）
  - 未設定のボードの締めの段は、動作確認の結果（と判断してほしいこと・見送った指摘）を、archive する前の計画ファイルの末尾に `## 動作確認の結果` などの節として書く
  - 締めを終えたカード（ブランチで計画が archive 済み）は、列を 実装中 のまま「ブランチをマージしてください」の止まり（`hold`）にして判断待ちに出し、ループは飛ばす。ステージの導出は変えない
  - カードのブランチを main へマージするのは人で、メインのチェックアウトで `git merge --no-ff <branch>` を打つ。手順書と README に手順を書く。AI はマージしない
  - 締めの後に人が直しを返す口は、このカードでは作らない。直したいときは `decide reject` か人が自分で直す。研修で要ると分かったら別のカードにする
