## アイデア

GitHub に届かないときも、データ用ブランチにある PR の控えを読んでボードを描く。描いたボードには、PR の状態を最後に取った時刻を出す。

- **届かなくても控えを読む。** 今は `checkAuth` に失敗するか `github:` が無いと、すべての PR を null として扱う。これを、手元にある控え（マージ済みの `snapshots/` と、最後に取った PR の状態）を読む形にする
- **取得時刻を出す。** `status` とダッシュボードに、PR の状態をいつ取ったかを出し、古い控えで描いていることが見えるようにする
- **ループと判断の検査は今のまま。** 次の一手は、GitHub につながっていないときは今までどおり出さない。手元の控えで描くのは表示だけにし、古い状態のまま人を待つカードをループが進めないようにする

## 背景

研修はオフライン（GitHub に届かない環境）を前提に回せるようにしたい。
今は GitHub に届かないと、`disabledMrStateProvider` がすべての PR を null で返し（`src/board/services/mr-state-provider.ts`）、データ用ブランチにあるマージ済みの控えも使わない。
そのため、マージ済みのカードの PR のリンクや Ready・マージの時刻が消え、区間の時間も PR の分が欠ける。
控えは手元にあるので、届かないときも読めば、最後に分かっていた状態でボードを描ける。古さは取得時刻で見せる。

## 探索メモ

- 2026-11-06 の調べ。マージ済みの控えはデータ用ブランチの `snapshots/<id>.json`、マージ前の控えは git に載らない `<dataDir の親>/cache/mr-snapshots.json`（`src/board/repositories/file-mr-snapshot.repository.ts`）
- 控えは PR の事実で、ステージではない。ステージは今までどおり読むたびに導出するので、ステージを保存しない決まりは崩れない
- 計画で決めること
  - マージ前の控え（`cache/`）も表示に使うか。使うなら、ループと判断の検査に混ざらない入口の分け方
  - 取得時刻を控えのどこに持つか
- `board-artifact-view` などダッシュボードのカードは、この上に載せる
