【直した点】（探索メモの 1:a、2:b、3:a）
1. `ai-board card submit` の plan の 提出 / 再提出 を、plan ゲートが none か rejected のときだけに絞った（宣言の有無によらず全カード）。plan を飛ばすカードの plan 再提出 で人の verify 否決 を消せなくなる
2. verify の approved は宣言の有無によらず `ready` を返すようにした（`judgeImpling`。`NextActionCard.skipGates` は使わなくなったので外した）。verify を飛ばすカードの revise-impl の再提出の後は締めの段を通らず、PR の本文の見送りを差し替えず、計画の判断してほしい点のコメントも重ねない。board-worker の `ready` は宣言のあるカードの AI の 提出 / 再提出 も通過として受け付け、計画が plans/ にあれば未チェックのタスクが無いことを確かめる。revise-impl は、宣言のあるカードでは自分の「人に判断してほしい」点を再提出の前に PR のコメントに書く
3. board-decide で、計画レビューのカードに plan、動作確認のカードに verify の宣言を入れるときだけ確かめる。アイデアと計画提案中のカードに入れるとき、宣言を外すときは確かめない
あわせて README・architecture・board-loop の手の表・仕様（card-gate-skip、card-review-authority）・計画の Decisions と Non-Goals を直した

【手順（直した点の確かめ方）】
共有の DB を汚さないよう、AI_BOARD_DB でワークツリーの外の DB を指し、空のディレクトリ $R（git init 済み）を --root にする。ワークツリーで npm run build の後、AI_BOARD_DB=$DB node dist/cli.js --root $R --port 5792 --no-open で起動する
1. plan を飛ばすカード: 宣言を入れて着手し card submit → 実装中。続けて card submit --resubmit は「plan が未提出か否決のときにしかできません（今の plan ゲート: approved）」で終了コード 1。verify 提出 → 画面か API で verify 否決 → card submit --resubmit がやはり 1 で、verify は rejected のまま（次の一手は revise-impl）
2. ふつうのカード: 着手して card submit → 続けて --resubmit は 1（submitted）。plan 否決の後の --resubmit は 0。plan 承認の後の --resubmit は 1
3. 動作確認を飛ばすカード: plan 承認 → verify 提出 → verify 否決 → card submit --gate verify --resubmit で gates が {plan: approved, verify: approved}、次の一手が ready（締めの段の implement ではない）
4. board-decide: 計画レビューのカードに「計画レビューを飛ばして」と頼むと、AskUserQuestion で確かめてから書く。アイデアや計画提案中のカードでは確かめずに書く
5. サーバを止める

【自分で動かした結果】
- 1〜3 を別の DB とポート 5792 のサーバで動かし、上のとおりの終了コードと gates になった。次の一手は GitHub に繋がないと status の next が null になるので、status --json のカードを dist の pickNextAction に直接渡して確かめた（try-skip: revise-impl、try-verify: ready）
- 品質ゲートと npm run build は通っている

【計画の手順から変わった点】
- ポート 5673 はメインのボードのサーバが使っているので止めずに 5792 で起動した。5791 には前の周の試しのサーバ（PID 98187）が残っていたので使っていない

【確かめられなかった部分】
- 4 の board-decide の確かめの出方は、手順書の変更で、動かしていない
- board-worker の revise-impl / ready の手順書の変更（宣言のあるカードの PR コメント、ready の受け付け）は、ループで実際には通していない
- 画面の見た目は今回の直しでは変えていない

【人に判断してほしいこと】
- 1 の絞り込みで、中止したカードを AI の plan 再提出 で再開する道が狭まった。中止を除いた plan ゲートが submitted / approved / held のカード（例: 計画レビューで中止したカード）には plan 再提出 を書けない（着手 → plan 提出 → plan 中止 → card submit --resubmit が終了コード 1 になることを確かめた）。docs/specs/card-abort の「中止のあとに再開する」は導出の規則としてはそのままだが、AI が CLI で再開できるのは plan が none か rejected のカード、または plan 通過後の verify の再提出に限られる。AI が人の中止を打ち消せないのは望ましいとも読めるので、今のままでよいか、再開の入口を人の API に足すかを決めてほしい
