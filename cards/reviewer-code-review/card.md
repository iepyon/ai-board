## アイデア

AI レビューの段（`board-reviewer`）で、`/code-review` をまた使えるようにする。

今の `board-reviewer` は `/code-review` を呼べないので、代わりに `ai-board pr diff <mr>` を `REVIEW.md` の観点で自分で読んでいる。
差分の読み手が 1 人だけになり、`/code-review` の観点（正しさ・再利用・簡素化・効率）や、指摘を確かめ直す手順が抜ける。
監視役の文脈に差分を入れないことと、サブエージェントを入れ子にしないこと（PR #56）は保ったまま、レビューの深さを戻したい。

## 背景

PR #56（`loop-flat-subagents`）で、サブエージェントの入れ子をやめた。クラウドのセッションのサブエージェントは `Agent` の道具を持たないためである。
2026-11-01 にクラウドのセッションで `skip-verify-scope`（PR #57）をループで回したとき、`board-reviewer` は `/code-review` を使わずに差分を自分で読んだ。
報告は「このスキルはサブエージェントを立てることがあり、この役目では立てられないため」というものだった。

軽く調べて分かったこと:

- クラウドのセッションのサブエージェントには `Agent` が無く、`ToolSearch` でも読み込めない（2026-11-01 に汎用のサブエージェントを立てて確かめた）。`Skill` の道具はある
- `.claude/agents/board-reviewer.md` の手順 3 は、まず `/code-review` にかけ、呼べないときだけ `ai-board pr diff` を自分で読む形になっている。
  今回は呼ぶ前に「呼べない」と判断しており、実際に `/code-review` を呼んで失敗したのかは分からない
- `/code-review` は組み込みのスキルで、強さ（low〜max）によって中でレビュー用のサブエージェントを立てる。max は多数立てると説明にある。
  low や medium でサブエージェントを立てずに済むかは確かめていない
- `.claude/skills/board-loop/SKILL.md` のハードルールは、`/code-review` を監視役で走らせることを禁じている（差分が監視役の文脈に入るため）
- `board-worker` の `revise-impl` も、手直しの差分を `/code-review` で見直す手順になっており、同じ制約を受ける

## 論点

- **まず確かめること。** `board-reviewer` と同じ条件のサブエージェントの中で `/code-review low <PR番号>` を呼ぶと、動くか、サブエージェントを立てようとして失敗するか。
  low で動くなら、手順書で強さを指定するだけで済む
- **サブエージェントの中で動かないときの置き場所。**
  - 監視役が `/code-review` を呼び、結果だけを受け取る。ただし差分や指摘が監視役の文脈に入り、`prompt` は 3 行だけという決まりとぶつかる
  - 指摘をファイル（例: 計画の横の一時ファイルや PR のコメント）に書かせ、`board-reviewer` がそれを読む。監視役は中身を読まない
  - 今のまま、自分で差分を読む形を正式な手順にし、`REVIEW.md` の観点を `/code-review` に寄せて厚くする
- **`/code-review` が動かせないことを報告にどう残すか。** 今は報告の「レビューの手段」に 1 行出るだけで、人は気付きにくい。PR の本文に出すか
- **`revise-impl` の見直し。** `board-worker` の手直しの見直しも、同じ形にそろえるか

## 探索メモ

2026-11-01 に `/code-review low 57` を試した結果:

- **サブエージェントの中でも呼べる。** `board-reviewer` と同じくクラウドのセッションのサブエージェントから `Skill("code-review", "low 57")` を呼ぶと、エラーにならず
  `Skill "code-review" completed (forked execution).` と `Result: (none)` が返った
- **メインのセッション（監視役の立場）から同じ呼び出しをしても、返り値は同じく `(none)` だった。**
  `/code-review` は別の文脈（fork）で動き、指摘は呼び出した側には返らず、人の画面（`ReportFindings` の一覧や、fork の最後の文）にだけ出る作りに見える。
  人がコマンドとして打ったときは、`(none)` の後にレビューの要約が人に表示された
- つまり「呼べない」のではなく、**呼べても指摘を呼び出した側が読めない。** `board-reviewer` が指摘を `## AI レビュー` 節に書き分ける今の手順には、そのままでは使えない
- 指摘を読める形で受け取る道は、今のところ次の 2 つしか見えていない。どちらも副作用がある
  - `--comment`: PR にインラインのコメントとして書かせ、`board-reviewer` が PR のコメントを読む。PR に書き込み、通知が飛ぶ
  - `--fix`: 作業ツリーに直させ、`git diff` を読んでから捨てる。`board-reviewer` はコードを直さない決まりなので、捨てる手順が要る
- 強さ low のときに中でサブエージェントを立てるかは、fork の中が見えないので分からないままである
