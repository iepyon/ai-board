# board-loop の監視役と作業者の 1 周を、ダミーのカードで確かめる

## 提案

### Why

PR #35（`loop-fresh-context`）で、`/board-loop` を回すセッションを監視役にし、1 手ごとの作業を
まっさらな文脈の作業者（`.claude/agents/board-worker.md`）に渡す形にした。
`ListAgents` による作業中の判定と作業者の型の解決は単体で確かめたが、実際のカードで 1 周回したことはまだ無い。

このカードは動作確認のためのダミーである。確かめたいのは次の 2 つである。

- 作業者がカードのワークツリーを切り、計画をコミットして Draft の PR を出し、`plan 提出` を書いて数行の報告を返すこと
- 作業者が動いている間に `/board-loop` をもう一度呼ぶと、「作業中」とだけ伝えて何も渡さないこと

この計画と Draft の PR が出て、カードが計画レビューの列に立った時点で、1 つ目は確かめられたことになる。

### What Changes

- README の末尾に 1 行足す（タスクは 1 つだけ）

### Impact

- 変更: `README.md` の 1 行だけ
- ただし、このカードは承認しない想定である。確認が済んだら人が中止し、PR を閉じる。実装には進まない

## 設計

### Decisions

#### タスクを 1 つの小さな変更に絞る

確かめたいのはループの流れであり、成果物ではない。計画のタスクを README の 1 行に絞り、
もし誤って承認されて `implement` に進んでも、品質ゲートを通る小さな差分で 1 手が終わるようにする。

#### 足す行は README の末尾に置く

既存の節の意味を変えない場所として、`## ライセンス` の後ろに 1 行足す。
中身はこのカードが動作確認用だったことを示す一文にとどめる。

### Risks / Trade-offs

- **ダミーの PR とブランチが残る。** 人が中止して PR を閉じたあと、ブランチとワークツリー
  （`.claude/worktrees/loop-worker-dummy`）を消す手間が要る
- **README に意味の薄い 1 行が入るおそれ。** 承認しない想定なので main には入らない。承認する場合は、その時点で行の中身を見直す

### Non-Goals

- 監視役・作業者の仕組み（`.claude/skills/board-loop/SKILL.md`、`.claude/agents/board-worker.md`）の変更
- 2 つ目の確認（作業中の再呼び出し）の結果を、この計画やコードに記録すること

## タスク

- [ ] README の末尾（`## ライセンス` の後ろ）に、board-loop の動作確認用カードで足した行であることを示す 1 行を足す
