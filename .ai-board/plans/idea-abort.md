# アイデアのカードを中止して片付けられるようにする

## 人に判断してほしいこと

- **まとめて中止する口を作るか。** 区切り線より下（後で）の 21 枚を片付けたいのが始まりだが、この計画では `ai-board decide abort <id>` を 1 枚ずつ呼ぶ形のままにし、複数の ID を受ける口は足さない（既定: 足さない。チャットで頼めば board-decide が 1 枚ずつ呼ぶ）
  - → 回答（2026-11-05、plan 承認）: 理由なしで承認（既定のまま進む）
- **中止したアイデアを戻す口を作るか。** 戻す口は作らない（既定: 作らない。間違えたら同じ内容でカードを起票し直す）。`## レビュー` は追記専用で、中止を打ち消す人のエントリの種類が今は無いため
  - → 回答（2026-11-05、plan 承認）: 理由なしで承認（既定のまま進む）

## 提案

### Why

要らなくなったアイデアのカードを、ボードから片付ける手段が無い。
2026-11-05 に区切り線より下の 21 枚を片付けようとしたが、`ai-board decide abort` はアイデアのカードを「出せる判断はありません」で拒んだ。
判断のボタン（`decisionsFor`）が 中止 を出すのは、計画レビューと、止まっている 計画提案中 / 実装中 だけだからである。
カードを消す入口は画面・API・CLI のどこにも無く、データ用ブランチを直接書き換えることは決まりで禁じている。
そのため、要らないアイデアはアイデアの表に溜まり続け、区切り線の上下を並べ替える手間も増える。

### What Changes

- アイデアのカードに「中止する」の判断を出す。画面の詳細パネルのボタンと `ai-board decide abort <id>` の両方から書ける
- 中止は今と同じく `## レビュー` の 中止 のエントリで表す。中止したアイデアはアイデアの表から外れ、畳まれた中止の区画に入る
- 詳細パネルでは、アイデアの中止のボタンを本文の後ろに置く。判断を待っているカードではないので、判断のボタンを本文より前に出す扱い（`awaitsDecision`）には入れない

### Impact

- 見せ方: `src/shared/dashboard-sections.ts`（`decisionsFor` / `awaitsDecision`）、`src/web/components/CardDetail.tsx`
- CLI: `src/board/cli/decide-cli.ts` は `decisionsFor` を読むので、コードの変更は要らない（使い方の文だけ見直す）
- テスト: `src/shared/__tests__/dashboard-sections.test.ts`、`src/board/cli/__tests__/decide-cli.test.ts`
- ドキュメント: `README.md`（判断のボタンの表）、`docs/architecture.md`（判断のボタンと画面の区画）、`docs/specs/card-abort/spec.md`
- 導出（`stage-resolver.ts`）・データ用ブランチの形・API の入出力は変わらない

## 設計

### Decisions

- **`decisionsFor` の `idea` に `abort('plan')` を返す。** 中止の判断の形（ゲート `plan`、種別 中止、ラベル「中止する」、理由は任意）は他の列と同じにする。中止のカードには今と同じく何も出さない
- **`awaitsDecision` はアイデアを除く。** 今は「`decisionsFor` が 1 つでもあれば判断待ち」としているが、アイデアに 中止 を足すとすべてのアイデアで判断のボタンが本文より前に出てしまう。
  `awaitsDecision` を「アイデアでなく、`decisionsFor` が 1 つでもある」に変える
- **詳細パネルでは、`awaitsDecision` でないカードの判断のボタンを本文の後ろに出す。** `CardDetail.tsx` で、判断待ちのカードは今どおり本文の前に、そうでないカードは `ReviewLog` の後ろに `ReviewActions` を置く。
  `ReviewActions` は出す判断が無ければ何も描かないので、アイデア以外の判断の無いカードの見た目は変わらない
- **区画・`status` の判断待ち・ループは変えない。** 判断待ちの区画は `hold` とステージで決まり（`sectionOf`）、`decisionsFor` を見ない。アイデアが判断待ちに出ることはない
- **`ai-board decide abort` は、他の列と同じく GitHub に繋がらないときは拒む。** アイデアの中止だけを例外にしない

### 仮定

- 中止のエントリのゲートは `plan` でよい。根拠: `isAborted`（`src/cards/services/review-log.ts`）は全エントリを通じた最新の種別だけを見てゲートを問わず、`DecisionGate` は `plan` だけである
- 中止したアイデアは、着手しても進めさせない。根拠: 中止のカードは区画で中止に寄り、アイデアの表（`ideaRows`）にも出ないので、画面から着手できない。導出と次の一手は今のまま（`docs/specs/card-abort/spec.md` の「中止のあとに再開する」は提出で外れる決まりで、アイデアには提出が無い）
- ADR は書き直さない。根拠: ADR 0002 の「中止は進捗と直交する終端の軸」はそのままで、どの列で中止を出せるかは ADR ではなく README と `docs/architecture.md` の表が持っている
- 手順書の振る舞いは変わらないので、`.claude/HARNESS_VERSIONS.md` の版は上げない。`board-decide` のスキルの操作の表（中止は確かめてから書く）は、アイデアにもそのまま当てはまる

### 退けた代案

- **カードを消す口（ファイルごと削除）を作る** — 導出の入力（`## レビュー`）と履歴を失い、間違えたときに戻せない。中止の区画に畳めば、表からは片付く
- **アイデア専用の「片付け」の種別を足す** — 中止と意味が同じで、ゲートの判定・区画・spec を二重に持つことになる
- **アイデアを判断待ちとして扱い、ボタンを本文より前に出す** — アイデアは人の判断を待っていない。すべてのアイデアの詳細でボタンが先頭に来て、本文を読みにくくする
- **`ai-board decide abort` に複数の ID を受けさせる** — 書くたびにコミットと push をする今の形では、途中で失敗したときの扱いを決める必要がある。1 枚ずつ呼べば足りる（人に判断してほしいこと）

### Risks / Trade-offs

- 詳細パネルを開いただけで中止のボタンが見えるので、誤って押しうる。ボタンは `btn ghost` で目立たせず、本文の後ろに置いて押し間違いを減らす。中止は確かめなしで書ける今の他の列と同じ扱いである
- 中止したアイデアを戻す口が無い（人に判断してほしいこと）

### Non-Goals

- まとめて中止する口
- 中止を戻す口
- 区切り線より下の 21 枚の中止そのもの（マージ後に人が画面か、チャットで頼んで board-decide で書く）

## 動作確認の手順

`AI_BOARD_DATA` でスクラッチパッドの試しのデータのワークツリーを指して動かす（`.claude/skills/board-loop/rules.md` の「動かして確かめるとき」）。

| 確かめること                                         | コマンド                                                                                                        | 期待する結果                                                          |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| アイデアのカードを `decide abort` で中止できる       | `card create --title t --id a1` の後に `decide abort a1`                                                        | `a1: plan 中止 を書きました` の 1 行が出て、終了コード 0              |
| 中止したアイデアがアイデアの表から外れる             | `status --json --only ideas,cards.id,cards.aborted`                                                             | `ideas` に `a1` が無く、`cards` の `a1` が `aborted: true`            |
| 計画提案中で止まっていないカードには今どおり書けない | `decide start a2` の後に `decide abort a2`                                                                      | 「出せる判断はありません」で拒まれる                                  |
| 詳細パネルでアイデアの中止のボタンが本文の後ろに出る | `npm run dev` で画面を開き、アイデアのカードの詳細を見る（AI は動かせない。共有のサーバを使わないため人が見る） | 本文・レビューの後ろに「中止する」が 1 つ出て、押すと中止の区画へ移る |

GitHub に繋がらない試しのデータでは `decide abort` が拒まれるので、`config.yaml` の `github:` をこのリポジトリに向けて `gh` のログインがある環境で走らせる。
