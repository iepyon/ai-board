# カード詳細の本文を、広い画面で整形された Markdown として読めるようにする

## 現状と、カードの想定からのずれ

- 詳細パネル（`src/web/styles.css` の `.detail`）は右端固定で幅 `min(560px, 100%)`。
- 本文は `BodyEditor.tsx` の `textarea` に生テキストで出る。整形されない。
- **計画の本文はボードに無い。** `PlanSection.tsx` は PR へのリンクとタスク数だけを出す。
  `<pre className="plan-body">` は既に無く（`GET /api/plans/:id` も廃止済み）、計画は Draft の PR で読む。
  カードの「計画も整形して読みたい」はこの前提が古い。

そこで今回のスコープは **詳細パネルの幅と、本文（`card.body`）の Markdown 表示**に絞る。
計画の本文をボードに戻すかどうかは別の判断になるので、末尾の「決めたいこと」に挙げる。

## 方針

### 1. 幅

- 既定幅を `min(560px, 100%)` から `min(840px, 100%)` に広げる。
- ヘッダに「広げる / 戻す」のトグルを置き、広げたときは `min(1280px, 100%)` にする。
  状態は `localStorage` に覚えるが、読めなくても動くようにする（try/catch）。
- ボードは横幅固定・縦スクロールの前提なので、パネルは今のまま `position: fixed` の右ドロワーで、
  モーダルやドラッグでのリサイズは入れない。

### 2. 本文は既定でプレビュー、「編集」で `textarea`

- `BodyEditor` に `mode: 'preview' | 'edit'` を持たせる。カードを選び直したら `preview` に戻す。
- 編集中の下書きは `BodyEditor` の state に残るので、プレビューへ切り替えても失わない。
  未保存（`dirty`）のあいだはプレビューに「未保存の変更あり」を出し、プレビューは下書きの方を描く。
- 保存・取り消しの動きは今のまま。

### 3. Markdown のレンダラ

- 依存に `react-markdown` と `remark-gfm`（表・取り消し線・タスクリスト）を足す。
- `react-markdown` は既定で生の HTML を描かず、`javascript:` などの URL も落とす。
  `rehype-raw` は入れない。カードの本文は人もエージェントも書ける場所なので、この既定を崩さない。
- リンクは `target="_blank" rel="noreferrer"` で開く。
- `- [ ]` / `- [x]` は無効化したチェックボックスとして出す（`remark-gfm` の既定）。画面から倒せない。
- 見た目は `styles.css` に `.md` のスコープで足す（見出し・リスト・コード・表・引用）。
  ダークテーマの変数（`--surface` / `--border` / `--text-2`）を使う。

### 4. `## レビュー` の見せ方

- 追記専用ログなので、プレビューでも本文の他の節と区別して出す。
- 本文を `## レビュー` の節とそれ以外に分ける純関数 `splitReviewSection(body)` を
  `src/shared/` に置き、vitest で書く（`src/web/` はテスト対象外のため）。
  節の見出しの判定は `src/cards/services/review-log.ts` と食い違わないようにし、可能なら定数を共有する。
- レビューの節は罫線で区切った枠に入れて、同じレンダラで描く。

## 決めたいこと

1. **計画の本文を詳細パネルに出すか。** 出すなら、計画ファイルはブランチにあり、
   ボードを動かすチェックアウトからは見えないことが多い、という問題が残る。
   今は PR へのリンクだけにしており、この計画でもそのままにする。
2. **幅は「既定を広げる + 広げるトグル」でよいか。** ドラッグでのリサイズや全画面表示は入れない。
3. **依存の追加（`react-markdown` / `remark-gfm`）でよいか。** 自前の変換は XSS の面で避けたい。
