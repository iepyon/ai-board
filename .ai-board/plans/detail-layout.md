# カードの詳細を広げ、本文を上に置く

## 提案

### Why

カードの詳細パネルは幅 560px で固定されており、本文はパネルの一番下にある。
タイトルを押してパネルを開くと、最初に目に入るのはステージ・計画・レビュー・紐付けで、本文を読むには毎回スクロールする。
アイデアカードの本文は `## 論点` の長い箇条書きになることが多く、狭い幅では 1 項目が何行にも折り返されて読みにくい。

パネルを開くのは、ほとんどの場合カードの中身を読むためである。
ステージや PR はボードの札や表の行にも出ているので、本文より先に置く理由は薄い。

### What Changes

- 詳細パネルの幅を、画面の幅に合わせて広げる（狭い画面では今と同じく画面いっぱい）。
- パネルの中の並びを変える。
  - 判断待ち（計画レビュー / PR中）のカードは、承認 / 否決 / 中止のボタンを先頭に置き、その下に本文を置く。
  - それ以外のカードは、本文を先頭に置く。「判断を待つ列ではありません」の一文は出さない。
  - ステージ・計画・紐付けは本文の後ろに置く。
- タイトルの下に、ステージ・タスクの進み・PR へのリンクを 1 行でまとめて出す。本文を先に置いても、カードがどこにいるかがスクロールせずに分かるようにする。
- API・DB・ステージの導出は変えない。

### Impact

- web
  - `src/web/components/CardDetail.tsx` — 並びの変更と、タイトルの下の 1 行
  - `src/web/styles.css` — パネルの幅、タイトルの下の 1 行のスタイル
- ドキュメント: `README.md` の詳細パネルの説明
- テスト: 変更は `src/web/` に閉じ、判定は `GATE_OF_STAGE` を引くだけなので、新しい純関数は作らない。typecheck と lint、実際の画面で確かめる
- API・DB・CLI・ステージの導出: 変更なし

## 設計

### Context

画面全体は `.app` の `max-width: 1040px` で中央に寄せてあり、詳細パネルは右端に `position: fixed` で重なる。
パネルを広げるほど後ろのボードが隠れる。パネルを開いたまま、ボードの別のカードを押して選び直す使い方がある。

判断待ちのカードの承認 / 否決は、ボードの「判断を待っている」の区画（`InboxSection.tsx`）でもできる。
詳細パネルのボタンは、本文を読んでから判断するときに使う。

### Goals / Non-Goals

**Goals:**

- パネルを開いたら、スクロールせずに本文の書き出しが読めること
- 広い画面では、本文の 1 行に今より多くの文字が入ること
- 判断待ちのカードで、承認 / 否決のボタンを探さずに押せること

**Non-Goals:**

- 境目をドラッグして幅を変えること、幅を覚えておくこと。使ってみて足りなければ別のカードにする
- 本文と、ステージ・計画・紐付けを左右に並べる 2 段組み
- 見た目のまま編集すること（`inline-edit` のカード）
- ボードの札や表の見た目

### Decisions

- **幅は `min(100%, clamp(560px, 55vw, 880px))` にする。**
  - 下限の 560px は今の幅で、これより狭くはしない。上限の 880px は、日本語で 1 行あたりの文字が多すぎて目で追いにくくならない程度にした。
  - 画面の幅が 1400px なら 770px になり、後ろのボードは左側の 600px ほどが見える。開いたまま別のカードを選び直せる。
  - 画面の幅が 560px より狭ければ、今と同じく画面いっぱいになる。
- **2 段組みにはしない。** 880px を 2 段に分けると、本文の列が今の 560px とあまり変わらない幅になり、広げた意味が薄れる。
  1 段のまま、並びの順番で本文を上に置く。
- **判断待ちのカードだけ、承認 / 否決のボタンを本文の前に置く。**
  理由の入力欄とボタンは 3 行ほどの高さで、本文の書き出しは画面内に収まる。
  判断待ちかどうかは、今と同じく `GATE_OF_STAGE[card.stage]` が決まるかで判定する。
- **判断待ちでないカードでは、レビューの欄そのものを出さない。** 今は「〜は判断を待つ列ではありません」の一文が出るが、読む人に何も求めておらず、本文を下へ押すだけである。
  `ReviewActions` は判断待ちの区画でも使っているので、部品には手を入れず、詳細パネル側で出すかどうかを決める。
- **タイトルの下に 1 行の要約を出す。** ステージの札（`StageSection` と同じ見た目）、`タスク n/m`（計画があるとき）、`PR #n ↗`（PR があるとき）を並べる。
  値はどれも `BoardCard` に既にあるものだけで、新しい判定は足さない。

### Risks / Trade-offs

- パネルが広がると、後ろのボードの右側が隠れる → 上限を 880px に抑え、1400px 幅の画面ではボードの左側が残るようにする。
  さらに狭い画面では、今と同じく画面いっぱいに重なる。
- ステージや紐付けが下に回るので、branch や PR 番号を直したいときはスクロールが要る → 本文を読む場面の方が多いので受け入れる。
  ステージと PR は、タイトルの下の 1 行で見える。
- 「判断を待つ列ではありません」を消すと、判断待ちでないカードでは承認 / 否決のボタンが出ない理由が画面に書かれなくなる → ステージの札と、ステージ欄の理由の文で読み取れる。
