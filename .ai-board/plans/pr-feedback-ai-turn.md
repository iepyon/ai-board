# PR の指摘に AI が応える番を、判断待ちと分けて見せ、ループに応えさせる

## この計画で使う言葉

- **PR中**：PR が Ready で開いているステージ。今は人の番（★）で、カードはすべて判断待ちの区画に並ぶ。
- **指摘**：PR に人が書いたコメント（会話のコメントと、差分の行へのコメント）。GitHub の review の本体（Approve などの総評）は今も引いておらず、数えない。
- **AI のコメント**：AI が人のアカウントで書いたコメント。本文の末尾に Claude Code のフッター（`_Generated by [Claude Code](https://claude.ai/code)_`）がある。
- **指摘に応える番**：PR中 のカードで、人の最新の指摘が、ブランチの最新コミットとも AI の最新のコメントとも後にあるとき。
  修正を push するか、直すものが無い理由を返信すれば、人の番に戻る。
- **再レビュー待ち**（`resubmitted`）：指摘の後に修正コミットが push された状態。今もバッジに使っている。

## 提案

### Why

今は PR中 のカードがすべて判断待ちの区画に並ぶ。人が PR に指摘を書いた後も、カードは人を待っているように見えたままで、
画面の文言（「レビューの指摘に対する修正を待っています」）と区画が食い違っている。
しかもループのハードルールが PR中 のカードに触ることを禁じているので、指摘に応える者がいない。
今 AI に直させるには、人が PR を Draft に戻して「計画から立て直させる」を押すしかなく、小さな指摘には重すぎる。

指摘を受けたカードを AI の区画へ移し、ループがその指摘に応えるようにすれば、判断待ちの区画には本当に人が見るべきものだけが残り、
小さな指摘は PR を Ready のまま往復できる。

### What Changes

使う人から見た変化:

- PR中 のカードに人が指摘を書くと、カードは判断待ちの区画から「AI が進めている」区画の**先頭**へ移る。ステージは PR中 のまま
- ループはそのカードを、計画提案中・実装中のカードより先に選び、新しい手 `fix-pr` で指摘に応える。
  直すものがあれば PR を Ready のまま修正を push し、直すものが無ければその理由を PR に 1 件だけ返信する。
  どちらでもカードは判断待ちの区画に戻る（push なら今と同じ「再レビュー待ち」のバッジが付く）
- AI が人のアカウントで書いたコメント（Claude Code のフッター付き）は、指摘として数えない（コメント件数にも入れない）
- 件数帯の PR中 のマスは、今までどおり判断待ちの区画へ飛ぶ
- PR を Draft に戻して「計画から立て直させる」道は今のまま残る（計画から作り直したいときに使う）

中の仕組みの変化:

- GitHub の取得で、フッター付きのコメントを人のコメントから外し、AI のコメントの最新時刻（`latestAiNoteAt`）を別に持つ
- 「指摘に応える番」を純関数 `awaitsPrFix`（`src/shared/`）で判定し、`BoardCardMr.awaitingFix` に載せる。ステージの導出（`stage-resolver.ts`）は変えない
- `groupBySection` が `awaitingFix` のカードを `work` に入れ、`work` の先頭に寄せる。`SECTION_OF_STAGE` は変えない
- `pickNextAction` が `awaitingFix` の PR中 のカードに `fix-pr` を返す（ほかの列より先）
- ループの手順書に `fix-pr.md` を足し、ハードルール「PR中 のカードに触らない」を「`fix-pr` の手でだけ触る」に緩める
- `ai-board pr comment` は、本文にフッターが無ければ末尾に足す（ローカルのセッションでもフッターで見分けられるように）

## 設計

### Decisions

#### 指摘の判定は時刻の比べ方で、AI のコメントを外す

`awaitsPrFix(mr)` は、PR中（`state === 'opened' && !draft`）で、`latestNoteAt`（人のコメントの最新）があり、
それが `latestCommitAt` とも `latestAiNoteAt` とも後にあるときに真を返す。

- **AI のコメントの見分け方はフッター。** PR は人のアカウントで出し、AI のコメントも人のアカウントで書かれるので、`user.type` や login では見分けられない。
  Claude Code のフッター（`_Generated by [Claude Code](https://claude.ai/code)_`）を本文に含むコメントを AI のものとする。
  文字列は `github-client.ts` に定数で 1 つだけ置き、`pr comment` もそれを使う
- **`CHANGES_REQUESTED` は使わない。** 自分の PR には Request changes を付けられないため（着手前に人と決めた）
- **質問や承認のコメントも指摘として扱う。** 粗さは受け入れる（着手前に人と決めた）。
  直すものが無ければ AI が理由を返信して人の番に戻すので、ループが同じカードで止まり続けることは無い
- **AI の返信で人の番に戻す。** 人は「push + 返信」ではなく「push だけ」を選んだので、返信は「直すものが無いとき」だけに使う。
  返信が無いと、質問だけのコメントでカードが AI の番に残り続け、`fix-pr` が最優先なのでループ全体が止まる。
  そのため判定に `latestAiNoteAt` を入れ、AI のコメントも「応えた」と読む（下の「判断してほしい点」(1)）
- `resubmitted`（`hasFixAfterReview`）の意味は変えない。人のコメント数が減る（AI のコメントを外す）ことだけが変わる

#### 区画と並び順

- `groupBySection` の `sectionOf` に「中止 → 止まり → `awaitingFix` なら `work` → ステージ」の 1 行を足す。`SECTION_OF_STAGE` は変えず、件数帯の飛び先は判断待ちのまま（着手前に人と決めた）
- `work` は今 `rank` の順を保つ。`awaitingFix` のカードだけを先頭へ寄せ、その中と残りは今の順を保つ（安定な並べ替え）
- 判断待ちの区画の PR中 のカードの文言に「AI が返信しました」の場合を足す（返信で人の番に戻ったとき）

#### 新しい手 `fix-pr`

- `NextActionKind` に `fix-pr` を足し、`LOOP_CURRENT_ACTIONS` にも足す（`loop start --action fix-pr` で書ける）
- `pickNextAction` は、まず `awaitingFix` の PR中 のカードを `rank` の順に探し、無ければ今の 実装中 → 計画提案中 の順に探す（着手前に人と決めた「PR の修正を先頭に」）
- `fix-pr` には段（`step`）を持たせない（常に null）
- `NextActionCard` に `mrState: { awaitingFix: boolean } | null` を足す。サーバの `BoardCard` と `status` のカードはそのまま満たす

#### ループの手順（`fix-pr.md`）

1. カードの `branch` のワークツリーに入り、`git pull --ff-only`（共通の決まりの「ワークツリーに入る」）
2. `ai-board pr view <mr> --comments` で、最新コミットと AI の最新コメントより後の人のコメントを読む。計画は archive 済みのものを読む（書き換えない）
3. 指摘ごとに「直す / 直さない」を決める。決め方は `rules.md` の「指摘の分け方」の「直す / 見送る」と同じにし、迷えば直す。
   直すと計画の Non-Goals に踏み込む・直し方が 2 つ以上あって振る舞いが変わる、なら直さずに返信で人に聞く
4. 直すものがあれば: 直す → 品質ゲート → `fix: PR の指摘に応える` のコミット（本文に応えたコメントの URL と、直した / 直さなかったの別）→ push →
   `ai-board pr checks <mr> --wait --sha <HEAD>`。CI の扱い（直すのは 2 回まで、`pending` や読めないときは止まる）は `implement.md` の締めの段と同じ
5. 直すものが無ければ（直さない指摘だけなら）: その理由を 1 件の返信にして `ai-board pr comment <mr> --body-file <f>` で書く
6. 直すものと直さないものが混ざれば、4 の push だけをする（コミットの本文に直さなかった理由を書き、返信はしない。push で人の番に戻る）
7. PR を Draft に戻さない、Ready / マージを触らない、計画とカードに書かない。PR の本文の `## 動作確認の結果` も書き換えない
8. `結果:` は `進めた`（push か返信をした）/ `止まった`（ゲートや CI が通らない、未コミットの変更が残る、ブランチが無い など）

#### ADR

新しく `docs/adr/0016-pr-feedback-ai-turn.md` を `adr` のスキルで書く（PR中 のカードに AI が応える条件、フッターで見分ける理由、返信で人の番に戻す理由、捨てた代案: `CHANGES_REQUESTED`・Draft に戻す道だけにする・専用の列を立てる）。
ステージの導出は変えないので ADR 0001 は書き直さない。ADR 0011（ループを本筋の 1 つで回す）に PR中 の手が増えたことを 1 行足す。

### Risks / Trade-offs

- **フッターの書き忘れ。** AI が `gh` などフッターを付けない道でコメントすると、人の指摘として数えられ、AI の番に戻る。
  ループの手順は `ai-board pr comment` だけを使い、CLI がフッターを補うので、手順どおりなら起きない
- **人がフッターを書くと AI のものと読まれる。** 人がフッターを貼ることはまず無いので受け入れる
- **人の承認のコメント（「LGTM」）でも AI の番になる。** AI は直すものが無いと返信して戻す。1 往復ぶん無駄になるが、着手前に人と決めた粗さとして受け入れる
- **CI が赤のまま止まる。** `fix-pr` の手が `止まった` で終わると、次の周も同じカードが最優先で選ばれ、ループ全体が止まる。
  `implement` の締めの段と同じで、人がワークツリーを直すまで止まるのが正しい（ほかのカードへ進むと、直されないまま忘れられる）

### Non-Goals

- ステージやゲートを足さない。`stage-resolver.ts` は変えない
- タイムライン（`stage-timeline.ts`）の PR中 の区間の持ち主（人）は変えない。指摘に応えている間も PR中 の区間のまま
- GitHub の review の本体（Approve / Request changes の総評）は引かない
- 指摘ごとに返信する（人が選ばなかった）。返信は直すものが無いときの 1 件だけ
- `board-reviewer` を `fix-pr` の後に立てない（AI レビューは実装の後の 1 回だけ）

## 動作確認の手順

ワークツリーは `$MAIN/.claude/worktrees/pr-feedback-ai-turn`（以下 `$WT`）。先に `cd "$WT" && npm ci && npm run build`。

1. 判定と振り分けの単体（AI が動かせる）
   - `cd "$WT" && npx vitest run src/shared/__tests__ src/board/services/__tests__`
   - 期待: `awaitsPrFix`（人のコメントがコミット・AI のコメントより後のときだけ真）、`groupBySection`（`awaitingFix` のカードが `work` の先頭）、
     `pickNextAction`（`awaitingFix` の PR中 のカードに `fix-pr` を、実装中より先に返す）のテストが通る
2. フッターの見分け（AI が動かせる）
   - `cd "$WT" && npx vitest run src/board/services/__tests__ -t 'フッター'`
   - 期待: フッター付きのコメントが `noteCount` に入らず `latestAiNoteAt` になるテストが通る
3. `pr comment` がフッターを補う（AI が動かせる。GitHub には書かない）
   - `cd "$WT" && npx vitest run src/board/cli/__tests__ -t 'フッター'`
   - 期待: フッターの無い本文に足し、ある本文はそのまま送るテストが通る
4. `status` の `next` が `fix-pr` になる（AI が動かせる。試しのデータと固定の PR の状態で）
   - `buildStatusReport` の単体で、`awaitingFix` の PR中 のカードと実装中のカードを渡し、`next.action` が `fix-pr`、`waiting` に入らず `working` の先頭に入ることを確かめる
5. 画面の見た目（AI は動かせない。人が開いて見る）
   - `npm run dev` でボードを開き、PR中 のカードの PR に人がコメントを書く
   - 期待: 次の取得でカードが「AI が進めている」区画の先頭に移り、PR中 の札と「PR の指摘に応える」の文言が出る。件数帯の PR中 のマスは判断待ちへ飛ぶ
6. ループが応える（AI は動かせない。本物の PR へのコメントが要る）
   - PR中 のカードの PR に、直せる指摘を 1 件書いて「ボードを進めて」と頼む
   - 期待: ループが `fix-pr` の手で修正を push し、カードが判断待ちの区画に「再レビュー待ち」で戻る。
     質問だけのコメントなら、フッター付きの返信が 1 件付き、カードが判断待ちに戻る
