# ループの 1 手を、まっさらな文脈のサブエージェントに渡す

## 提案

### Why

`/loop 1m /board-loop` では、1 つのセッションがループを回し続ける。
複数のカードの計画・実装・レビューで読んだコードや決めた事柄が、すべて同じ文脈に積み上がる。
前のカードの前提が残ったまま次のカードの計画を書くことになり、カードに書かれていない前提が紛れ込みやすい。
文脈が長くなると自動の要約が走り、どこまでが今のカードの情報なのかも曖昧になる。

`/clear` は Claude Code 本体のコマンドで、スキルからは実行できない。
人はこの画面でループの経過を見続けたいので、セッションは分けずに、1 手ごとの作業だけを新しい文脈に切り離す。

### What Changes

- ループを回すセッションを「監視役」にする。監視役は `status` を読んで次の一手を選び、
  その手をサブエージェント（作業者）に渡し、返ってきた報告を人に伝えるだけにする
- 作業者の定義 `.claude/agents/board-worker.md` を足す。今の `SKILL.md` の「ワークツリーに入る」「1 手」とハードルールを移す
- `.claude/skills/board-loop/SKILL.md` を監視役の手順だけに書き直す
- 作業者に渡すのはカード ID と手の種類だけにする。会話で伝えた補足は作業者に届かないので、カード本文の `## 探索メモ` に書く運用を CLAUDE.md と README に書く

### Impact

- 新規: `.claude/agents/board-worker.md`
- 変更: `.claude/skills/board-loop/SKILL.md`、`CLAUDE.md`、`README.md`
- `src/` には触らない。`status` の出力と `pickNextAction` もそのまま使う

## 設計

### Decisions

#### 3 種の手をすべて作業者に渡す

`plan` / `revise-plan` だけでなく、`implement` も渡す。
`implement` もタスクごとにコードと差分を読み、`/code-review` の指摘も文脈に積む。
文脈を汚すのは計画だけではない。
手の種類で分岐させないことで、監視役の手順も「選ぶ → 渡す → 伝える」の 1 本で済む。

#### 作業者は `.claude/agents/` の定義にする

監視役が手順の文章を毎回プロンプトに書き写すと、監視役の文脈に手順の全文が残り、写し間違いも起きる。
定義ファイルに置けば、手順は作業者のシステムプロンプトになり、監視役は `subagent_type: board-worker` を指定するだけで済む。
frontmatter に `tools` は書かず、セッションの道具をすべて引き継ぐ（`gh`・`git`・`npm`・`ai-board card` と `/code-review` を使うため）。

`subagent_type: "fork"` は使わない。fork は呼び出し元の会話をすべて引き継ぐので、切り離す意味が無くなる。
これは監視役のハードルールに書く。

#### 渡すのはカード ID・手の種類・`$MAIN` だけ

作業者は `ai-board card show`・計画ファイル・`gh pr view` を自分で読み直す。
監視役が要約を添えると、監視役の文脈にある前のカードの前提がそこから漏れる。

その代わり、人がこのセッションで口頭で伝えた補足は作業者に届かない。
補足はカード本文の `## 探索メモ` に書く（人が画面から書くか、エージェントが `ai-board card body` で書く）。
本文に書いておけば、ループの外で別のセッションが拾うときにも同じ情報が届く。

#### 監視役は `status` の 3 項目だけを読む

`status --json` は全カードの全項目を出す。1 分ごとに全文を読むと、それだけで監視役の文脈が膨らむ。
監視役は `node -e` で `next` / `waiting` / `forge` だけを取り出して読む。
カード本文・計画・差分は読まない。

#### 作業中の作業者がいれば、その周は何もしない

サブエージェントはバックグラウンドで動き、監視役の手番はすぐに終わる。
cron はセッションが手すきのときに発火するので、作業者が動いている間にも次の周が来る。
このとき `status` はまだ同じ `next` を返すため、ガードが無いと 2 人目の作業者が同じカードに入る。
2 人目はワークツリーの未コミットの変更を見て止まるが、「前の周が途中で止まっている」という誤った報告になる。

そこで、作業者には `board-worker-<cardId>` の名前を付けて渡す。
監視役は周の最初に `ListAgents` で `board-worker-` で始まる作業者が動いていないかを見て、
動いていれば「作業中: <カード>」とだけ伝えて終わる。
「さっき渡した」という監視役の記憶ではなく `ListAgents` を見るのは、自動の要約で記憶が落ちても判定が変わらないようにするためである。

作業者が終わると、監視役に完了の通知が届く。この手番では報告を伝えるだけで、次の作業者は渡さない。
次の手は次の周の cron が選ぶ。「1 回の呼び出しで 1 手」は「1 周で渡す手は高々 1 つ」と読み替える。

#### 作業者の報告の形を決める

作業者の最後の応答は、次の 4 項目を 5 行以内で返す。ファイルの中身や差分は含めない。

- 結果: 進めた / 止まった
- 何をしたか
- 人が見るもの（PR の URL、判断待ちになったカード）
- 止まった理由と、人にしてほしいこと（止まったときだけ）

監視役はこれを 3 行以内に縮めて人に伝える。作業者の主張を確かめ直すことはしない。
次の周の `status` が実態を映すので、それが確認になる。

#### `/code-review` を使えなければ、作業者が自分で差分を見直す

作業者が `/code-review` のスキルを呼べるか、そのスキルがサブエージェントの中からさらにエージェントを起こせるかは、動かしてみないと分からない。
呼べなければ、作業者は `gh pr diff` を `REVIEW.md` の観点で自分で見直し、指摘を直す。
監視役が代わりに `/code-review` を走らせることはしない（差分が監視役の文脈に入るため）。

### Risks / Trade-offs

- **作業者が終わらないと、ループ全体が止まる。** 作業者が固まると、`ListAgents` のガードで毎周「作業中」と報告するだけになる。
  監視役は、どのカードの作業者がいつから動いているかを報告に出し、人が `TaskStop` で止められるようにする
- **口頭の補足が届かない。** 本文に書く運用で補う。書き忘れると、作業者はカード本文だけを頼りに計画を書く
- **手のたびに読み直しの費用がかかる。** 作業者は毎回 CLAUDE.md・カード・計画を読み直す。
  前の文脈を引き継がないことの対価として受け入れる
- **別案: 1 周ごとに新しいセッションを起動する。** launchd などから `claude -p "/board-loop"` を起動すれば、監視役ごと毎回まっさらになる。
  ただし、この画面でループの経過を見られなくなる。確認なしで動かす権限の設定も要り、経過を見るには `loop-activity` が前提になる。
  人がこの画面で見守りたいので、今回はサブエージェントにする

### Non-Goals

- ループの稼働表示（`loop-activity`）。作業者の名前と監視役の報告は、後でその入力に使える
- 複数の作業者を並列に動かすこと（1 周で渡す手は高々 1 つのまま）
- `status` の出力の形を変えること（3 項目の取り出しは監視役の側で行う）
