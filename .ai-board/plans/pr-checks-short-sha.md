# `ai-board pr checks --sha` で短いハッシュを head と照らし合わせる

## 人に判断してほしいこと

- **直し方をどれにするか。** 既定は A。
  - A: 短いハッシュを PR の head の先頭と照らし合わせる
  - B: 完全なハッシュ（40 桁）だけを受け付け、短いハッシュは使い方の誤りとして拒む
  - C: 短いハッシュを GitHub に問い合わせて、完全なハッシュに直してから比べる
- **大文字の 16 進も受け付けるか。** 今は `--sha` の値を小文字の 16 進だけで受けている（既定: 今のまま、大文字は拒む）

## 提案

### Why

`ai-board pr checks <n> --sha <sha>` は、`--sha` に 7〜40 桁の 16 進を受け付ける（`src/board/cli/pr-cli.ts` の `parseChecksOptions`）。
ところが、見るコミットが PR の head かどうかは、PR の `head.sha`（完全なハッシュ）と `!==` で比べている（`src/board/services/github-client.ts` の `checks`）。
そのため短いハッシュを渡すと、head が同じコミットでも「まだこのコミットになっていない」と読まれる。チェックを引かずに `pending` を返し、`--wait` なら上限（既定 900 秒）まで待ってから `pending`（終了コード 2）で終わる。
ループは `git rev-parse HEAD` の完全なハッシュを渡すので当たらないが、人が手で短いハッシュを打つと当たる。2026-11-06 に PR #88 の動作確認で実際に当たった。

### What Changes

- `--sha` に短いハッシュ（7 桁以上）を渡しても、PR の head がそのコミットなら、そのコミットのチェックを読む
- 短いハッシュが head と別のコミットを指すときは、今と同じく走っているとして扱う
- 使い方の文と `docs/architecture.md` に、短いハッシュも受け付けることを書く

### Impact

- コード: `src/board/services/github-client.ts`（`checks` の照らし合わせ）、`src/board/cli/pr-cli.ts`（使い方の文）
- テスト: `src/board/cli/__tests__/pr-cli.test.ts`
- ドキュメント: `docs/architecture.md`
- 完全なハッシュを渡す今の使い方（ループの締めの段・`fix-pr`）の振る舞いは変わらない。手順書（`.claude/`）も変わらない

## 設計

### Decisions

- **head の完全なハッシュが、`--sha` の値で始まるかで照らし合わせる（A）。** `checks` の `sha !== headSha` を、`headSha.startsWith(sha)` の否定に置き換える。
  照らし合わせは `github-client.ts` の小さな関数（`isSameCommit(sha, headSha)`）に切り出す。完全なハッシュは自分自身で始まるので、今の使い方の振る舞いは変わらない
- **head と一致したら、出す `sha` は head の完全なハッシュにする。** 今と同じく、一致した後のまとめ（`summarizeChecks`）は `headSha` で作る。
  一致しない間の「走っている」のまとめは、今と同じく渡された値を出す（`--json` の `sha` が短いハッシュのままになる）
- **使い方の文を直す。** `--sha` の説明に「7 桁以上の短いハッシュも可」を足す。CLI の出力の文が変わるのは、使い方のこの 1 か所だけである
- **受け付ける値は今のまま。** 小文字の 16 進で 7〜40 桁（`/^[0-9a-f]{7,40}$/`）。大文字は今までどおり拒む（人に判断してほしいこと）

### 仮定

- **短いハッシュの取り違えは考えなくてよい。** 照らし合わせる相手は PR の head の 1 つだけである。7 桁の短いハッシュで、別のコミットが head と先頭まで一致する見込みは 16^7 分の 1（約 2.7 億分の 1）しかない。
  `git` 自身も、短いハッシュを一意に決まる範囲で受け付ける。根拠: `github-client.ts` の `checks` は PR の `head.sha` だけと比べ、ほかのコミットを探さない
- **ループの手順書は変えない。** 締めの段（`implement.md`）と `fix-pr.md` は `git rev-parse HEAD` の完全なハッシュを渡すので、振る舞いが変わらない。`.claude/HARNESS_VERSIONS.md` の版も上げない
- **ADR は書かない。** 照らし合わせの細部で、判断の理由を残す ADR に当たらない

### 退けた代案

- **完全なハッシュだけを受け付ける（B）** — 人が `git log --oneline` の短いハッシュをそのまま打てなくなる。今は受け付けているので、使える形を狭めることになる（人に判断してほしいこと）
- **GitHub に問い合わせて完全なハッシュに直す（C）** — `gh api` の呼び出しが 1 回増え、`--wait` では引き直すたびに増える。比べる相手が head の 1 つだけなので、先頭の照らし合わせで足りる（人に判断してほしいこと）
- **短いハッシュを手元の `git rev-parse` で完全なハッシュに直す** — `ai-board pr` は、手元のチェックアウトに無いコミットでも動く必要がある（クラウドのセッションなど）。手元の git に頼れない

### Risks / Trade-offs

- 先頭の照らし合わせなので、7 桁の短いハッシュが別のコミットを指していても head と一致したと読む見込みが、ごく小さく残る（仮定）
- 一致しない間の `--json` の `sha` は、渡された短いハッシュのままになる。一致した後は完全なハッシュになるので、待ちの途中と結果で桁数が変わる

### Non-Goals

- 大文字の 16 進を受け付けること（人に判断してほしいこと）
- `--sha` を省いたときの振る舞い（今どおり PR の head を見る）
- `checks` 以外のコマンドで、コミットを指す引数を足すこと

## 動作確認の手順

GitHub の PR を読むだけなので、共有のカードには書かない。`gh` にログインした環境で、計画を書いた時点で開いている PR（例: #88）に向けて走らせる。

| 確かめること                                     | コマンド                                                                  | 期待する結果                                                                                |
| ------------------------------------------------ | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 短いハッシュでも head のチェックを読む           | `ai-board pr checks <n> --sha <head の 7 桁>`                             | 「PR #<n> の最新コミット <7 桁> のチェック: …」が出て、「head はまだ…」が出ない             |
| 完全なハッシュでも今と同じに読む                 | `ai-board pr checks <n> --sha <head の 40 桁>`                            | 上と同じ判定が出る                                                                          |
| 別のコミットの短いハッシュは走っているとして扱う | `ai-board pr checks <n> --sha <head でないコミットの 7 桁>`               | `pending` と「PR の head はまだ <7 桁> で、このコミットになっていません」が出て終了コード 2 |
| 使い方の文に短いハッシュのことが出る             | `ai-board pr --help`                                                      | `--sha` の説明に「7 桁以上の短いハッシュも可」が出る                                        |
| 短いハッシュで待つときも head と一致して終わる   | `npx vitest run src/board/cli/__tests__/pr-cli.test.ts -t '短いハッシュ'` | 通る（直す前は落ちる）                                                                      |
