# 計画で、範囲の線引きも人に判断してほしいことに挙げる

## 人に判断してほしいこと

- **手順書の版を上げるか。** `plan.md` の振る舞い（計画に何を書くか、提出の前に何を確かめるか）が変わるので、`.claude/HARNESS_VERSIONS.md` に `v4` を足す（既定: 上げる）
  - → 回答（2026-11-06、plan 承認）: 理由なしで承認（既定のまま進む）
- **どこまでを「範囲の線引き」として挙げさせるか。** 既定は A。
  - A: `### Non-Goals` と `### 退けた代案` のうち、入れるか外すかで成果物の範囲（変わるファイルやコード）か、CLI の出力・振る舞いが変わるもの
  - B: `### Non-Goals` と `### 退けた代案` をすべて
  - C: 今のまま、範囲の線引きは AI が決めて `### 仮定` に書くだけ（この計画は直さない）
  - → 回答（2026-11-06、plan 承認）: 理由なしで承認（既定のまま進む）
- **AI レビュー（`board-reviewer`）にも、挙げ漏れを確かめさせるか。** 実装の後に、計画が範囲の線引きを人に判断してほしいことに挙げていたかを見る（既定: 足さない。レビューは実装と計画の食い違いを見る役目で、計画レビューは人が済ませているため）
  - → 回答（2026-11-06、plan 承認）: 理由なしで承認（既定のまま進む）

## 提案

### Why

`cli-rules-to-usecases`（PR #88）の最初の計画では、`## 人に判断してほしいこと` を「なし」として提出した。
実際には、人が決めるべき範囲の線引きが 5 つあった（`decide` の検査を `transact` の中へ移すか、ブランチの紐付けの usecase を入れるか、古い記述をどこまで直すか、保留の理由をどこで確かめるか、画面のためだけに残ったコードも消すか）。
人に「質問して」と言われてから問いを出し、回答を受けて 2 回否決・再提出することになった。
原因は、これらを `### Non-Goals` や `### 退けた代案` に AI の既定として書いて済ませたことにある。
`plan.md` は「人に聞くのは、人にしか決められないこと（製品の意図・互換を壊してよいか・優先度）だけ」としており、範囲の線引きがそれに当たるかが読み取りにくい。

### What Changes

- `plan.md` の「人に聞くのは、人にしか決められないことだけ」の例に、範囲の線引きを足す
- `## 人に判断してほしいこと` の決まりに、`### Non-Goals` と `### 退けた代案` のうち範囲の線引きに当たるものを、既定を添えて挙げることを足す
- 提出の前の確かめに、「`- なし` と書いたなら、`### Non-Goals` と `### 退けた代案` を読み直し、範囲の線引きに当たるものが無いことを確かめる」を足す
- `.claude/HARNESS_VERSIONS.md` に `v4` を足す（人に判断してほしいこと）

### Impact

- 手順書: `.claude/skills/board-loop/plan.md`、`.claude/HARNESS_VERSIONS.md`
- コード・テスト・CLI の出力は変わらない。`board-reviewer`（`.claude/agents/board-reviewer.md`）も変えない（人に判断してほしいこと）
- これから立てる計画の `## 人に判断してほしいこと` の項目が増える見込みがある。人が計画レビューで読む量も増える

## 設計

### Decisions

- **「人に聞くこと」の例に、範囲の線引きを足す。** `plan.md` の「人に聞くのは、人にしか決められないこと（製品の意図・互換を壊してよいか・優先度）だけにする」の例に、
  「範囲の線引き（入れるか外すかで、成果物の範囲か CLI の出力・振る舞いが変わるもの）」を足す
- **`## 人に判断してほしいこと` の決まりに 1 文足す。** `### Non-Goals` と `### 退けた代案` に書いたもののうち範囲の線引きに当たるものは、AI が選んだ既定を添えて、ここにも 1 項目ずつ挙げる。
  挙げたものは、`### Non-Goals` / `### 退けた代案` の行の末尾に「（人に判断してほしいこと）」と添え、どの問いの既定かを追えるようにする（PR #88・#89 の計画で使った書き方）
- **提出の前の確かめに 1 項目足す。** `plan.md` の 3 に、「`## 人に判断してほしいこと` を `- なし` としたなら、`### Non-Goals` と `### 退けた代案` を読み直し、範囲の線引きに当たるものが無いことを確かめる」を足す
- **`### Non-Goals` の書き方の説明を足す。** 今の `plan.md` の節の説明には `### Non-Goals` の行が無い。「この計画でやらないこと。範囲の線引きに当たるものは人に判断してほしいことにも挙げる」の 1 行を足す
- **版を上げる。** `.claude/HARNESS_VERSIONS.md` の先頭に `## v4 — <日付>` を足し、変わったことを箇条で書く（人に判断してほしいこと）

### 仮定

- **挙げる範囲は A にする。** 根拠: PR #88 で漏れた 5 項目は、どれも入れるか外すかで変わるファイルや CLI の出力が変わるもの（A）に当たる。B にすると、ファイル名の選び方のような人が決めなくてよいものまで挙がり、人の読む量が増える
- **`board-reviewer` は変えない。** 根拠: `board-reviewer.md` は、計画の Decisions・仮定と実装の食い違いを見る。計画の問いの立て方は、人が計画レビューで済ませている（人に判断してほしいこと）
- **`revise-plan` の手順は変えない。** 否決を受けて直した計画も `plan` の 2 の構成に従うので、足した決まりがそのまま効く
- **ADR は書かない。** 計画の書き方の細部で、ボードの不変条件や設計の判断ではない。版の記録（`HARNESS_VERSIONS.md`）に残せば足りる

### 退けた代案

- **`### Non-Goals` と `### 退けた代案` をすべて挙げる（B）** — 人が決めなくてよいもの（書き方の好み、明らかに要らない案）まで挙がり、計画レビューで読む量が増える（人に判断してほしいこと）
- **今のまま、AI が決めて `### 仮定` に書く（C）** — PR #88 で 2 回の否決・再提出を招いた形のまま残る（人に判断してほしいこと）
- **`board-reviewer` に挙げ漏れを確かめさせる** — レビューの段は実装の後なので、挙げ漏れに気づいても計画レビューには戻れない。気づくなら計画を提出する前がよい（人に判断してほしいこと）
- **`## 人に判断してほしいこと` の項目の数に上限を設ける** — 上限で削られた問いが、また `### 仮定` に埋もれる。数ではなく、何を挙げるか（A）で絞る

### Risks / Trade-offs

- 計画の `## 人に判断してほしいこと` が長くなり、人が計画レビューで読む量が増える。どの項目にも AI の既定を添えるので、既定のままなら「承認して」で済む
- 「範囲の線引き」に当たるかは、AI がなお読み分けることになる。PR #88 のような漏れは減るが、無くなるとは限らない

### Non-Goals

- `board-reviewer` に挙げ漏れを確かめさせること（人に判断してほしいこと）
- `## AI レビュー` 節の `### 人に判断してほしいこと` の書き方を変えること
- 手順書のほかの言い回しの直し（`skills-decide-wording` のカードで扱う）

## 動作確認の手順

手順書の直しなので、CLI を動かして確かめられるのは版の記録だけである。足した決まりが効くかは、次に立てる計画で人が確かめる。

| 確かめること                             | コマンド                                                                                                 | 期待する結果                                                                                                        |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `plan.md` に範囲の線引きの決まりが入った | `grep -n "範囲の線引き" .claude/skills/board-loop/plan.md`                                               | 「人に聞くこと」の例、`## 人に判断してほしいこと` の決まり、`### Non-Goals` の説明、提出の前の確かめの 4 か所に出る |
| 1 手の記録が新しい版を残す               | `AI_BOARD_DATA` で試しのデータを指し、`ai-board loop start --loop t --card <試しのカード> --action plan` | 出力に `v4` が出る（`status --json --only loop` の `running[].harness` が `v4`）                                    |
| 次に立てる計画が範囲の線引きを挙げる     | —                                                                                                        | 走らせていない（次のカードの計画で、人が計画レビューで確かめる）                                                    |
