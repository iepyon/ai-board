# 人が判断を書いた後、頼み直さなくてもループが続きを進める

## 提案

### Why

人がチャットで判断（着手・承認・否決）を頼むと、`board-decide` のスキルが人の API で書き、書いた中身を伝えて終わる。
判断の直後に `status` の `next` が AI の番を指していても、人が改めて「ボードを進めて」と頼むまでループは動かない。
2026-11-03 に loop-permissions を 1 周回したときは、この頼み直しが 5 回あった（着手・plan 否決・plan 承認・verify 否決・verify 承認）。

原因は手順書がそう書いているとおりに止まっていることで、カードの `## 探索メモ` で確定している。

- `board-loop/SKILL.md` の手順 4 は、周を続ける合図を「サブエージェントの完了の通知」だけにしている
- `board-loop/SKILL.md` のハードルールは、人に頼まれた `board-decide` を「周とは別に」書くとしている
- `board-decide/SKILL.md` の手順 5（伝える）は、書いた中身を伝えて終わる。その後に周へつなぐ決まりが無い

あわせて、`board-decide` には同じ 1 周で見つかった 2 つの使いにくさがある。

- 書くたびのサーバの起動・起動待ち・書き込み・停止で、Bash の呼び出しが 3〜4 回要る。
  起動待ちが前回のログの `ai-board  http` の行を読んで URL が空のまま進み、書き込みが失敗したことが 1 回あった
  （`$RUN` を毎回同じパスにしていて、起動の呼び出しの `rm -f "$RUN/log"` より先に起動待ちが走ると起きる）
- 人が「A で直して」と言ったときの A は Claude が会話で示した案で、作業者には見えない。
  手順書は「人の言葉をそのまま送る」とだけ書いており、この場合の扱いが無い

### What Changes

使う人から見た変化は次のとおり。

- 着手・承認を頼むと、書いた後にそのまま `board-loop` の 1 周が走り、次の 1 手がサブエージェントに渡る。
  以後は今の「完了の通知で続ける」でつながるので、間隔運転（`/loop 5m /board-loop`）をしていなくても止まらない
- 否決を頼むと、書いた後に AskUserQuestion で「続けて作業者に渡す / 待つ」を 1 回聞かれる。
  `## レビュー` は追記専用で理由を直せないので、言い直したいとき（PR のコメントや `## 探索メモ` に補う）の間を残す
- 「書くだけ」「進めないで」と言えば続けない
- `next` が判断したカードと別のカードを指すときも、`next` のまま続ける。伝えるときに「判断したカードではなく `<別のカード>` に渡した」とはっきり書く
- サーバを自分で起動して書くときの Bash の呼び出しが 1 回になる（起動・起動待ち・書き込み・停止を 1 本にまとめる）
- 否決の理由が会話の中の案だけを指すとき（「A で」「さっきの案で」）は、Claude が作業者にも読める文面に起こし、AskUserQuestion で人に選んでもらってから送る

中の仕組みは変えない。変わるのは手順書とドキュメントだけで、コード（`src/`）には手を入れない。

### Impact

- 手順書: `.claude/skills/board-decide/SKILL.md`、`.claude/skills/board-loop/SKILL.md`
- ドキュメント: `README.md`（「チャットから判断する」「AI ループ」「クラウドのセッションで回す」）、`CLAUDE.md`（書き込み境界の下の `board-decide` の段落）
- ADR: `docs/adr/0007-board-decide.md` を今の形に書き直し、判断の後に周を続ける決定を新しい ADR（`0013`）に書く。`docs/adr/README.md` の一覧に足す
- コード・API・データ用ブランチの形: 変わらない

## 設計

### Decisions

#### 続けるのは、AI の番を作る判断を書いたときだけ

`board-decide` の手順 5（伝える）の後に、新しい手順 6「続ける」を置く（今の手順 6「依頼に対象が無いとき」は手順 7 に繰り下げ、本文の「手順 6」の参照も直す）。

続ける判断と、続け方は次のとおり。

| 書いた判断                                                                       | 続けるか                                              |
| -------------------------------------------------------------------------------- | ----------------------------------------------------- |
| 着手                                                                             | 確かめずに続ける                                      |
| 承認（plan / verify）                                                            | 確かめずに続ける                                      |
| 待っている提出を承認と読ませる宣言（計画レビューへの plan、動作確認への verify） | 確かめずに続ける（手順 3 で既に確かめている）         |
| 否決（plan / verify）                                                            | AskUserQuestion で「続けて作業者に渡す / 待つ」を聞く |
| 中止 / 着手を戻す / それ以外の宣言の出し入れ / 並べ替え                          | 続けない                                              |

- 着手は AI に計画を始めさせる合図なので、そのまま `board-planner` に渡すのは人の意図に沿う（2026-11-03 に人と決めた）
- 中止・着手を戻す・並べ替えは AI の番を作らない。その判断の後に `next` が null でなくても、それは判断の前から AI の番だったカードで、
  頼んでいない手を走らせることになるので続けない
- 書いた後に `status --json --only next,loop` を読み直し、次のどれかなら続けずに、理由を 1 行添えて終える
  - 人が「書くだけ」「進めないで」と言った
  - `next` が null（`waiting` のカードを伝える必要は無い。手順 5 で書いた結果は伝えている）
  - `loop.running` に、このセッションと別のループ（`loop` がこのセッションの ID でない）の、`next.cardId` への終わっていない記録がある。
    別のセッションの間隔運転が同じカードを触っている見込みがあり、続けると同じワークツリーに 2 つのサブエージェントが入る
- 手順 7（判断待ちの一覧）で何件か書いたときは、全部書き終えてから 1 回だけ判断する。否決が 1 件でも含まれれば聞く

#### 続け方は `board-loop` の手順 0〜3 をそのまま 1 周走らせる

`board-decide` は続け方を自分では書かず、「`board-loop` のスキルを読み込み、その手順 0 から 3 を 1 周走らせる」とだけ書く。
手順 0 の `ListAgents` の確かめ、`ai-board loop start`、`Agent` への渡し方、`prompt` の 3 行は `board-loop` のものをそのまま使う。
渡した後は `board-loop` の手順 4 の「完了の通知で続ける」でつながる。

- `next` に従い、判断したカードに限らない（2026-11-03 に人と決めた）。rank は人が決めた優先度で、
  「判断したカードのときだけ」にすると、両方のカードが頼み直すまで止まる今の止まり方が残る
- `board-loop` 側は、手順 4 の「続ける合図」に「`board-decide` の手順 6 から入るとき」を足し、
  ハードルールの「周とは別に `board-decide` で書いてよい」に「書いた後、`board-decide` の手順 6 のとおりに 1 周を続けてよい」を足す。
  「周の中で人の判断を自分から書かない」は崩さない。判断を書くのは人に頼まれたときだけで、続けるのはその後の AI の手だけである
- 間隔運転は要らなくなるが、人のいない間の保険として案内は残す

#### サーバの起動から停止までを 1 回の Bash の呼び出しにまとめる

今の 3〜4 回の呼び出し（起動・起動待ち・URL の読み出し・書き込み・停止）を、1 本のスクリプトにまとめる。

- `$RUN` は呼び出しの中で毎回 `mktemp -d` で新しく作る。前回のログを読む余地が無くなる
- サーバは同じ呼び出しの中で `&` で起動し、`trap ... EXIT` で、書き込みが失敗しても、起動待ちで諦めても、必ず `--pid-file` の OS の pid に `node` の `process.kill` で SIGTERM を送ってから `wait` する
- 起動待ちは今と同じく、ログの `ai-board  http` の行と pid の生存を 60 秒まで見る。その後に `status --json --only server` の `server.url` を `URL` にし、null なら止める
- 書き込み（`curl` の 1 本以上）はスクリプトの中ほどに置く。手順 7 で何件か書くときも、同じ 1 本に並べる
- `run_in_background` は使わない。サーバは書き終えたら止めるので、呼び出しの終わりがサーバの終わりと同じになる
- 人が起動したサーバ（手順 1 で `server` が null でない）があるときは、今どおりその `server.url` に `curl` だけを叩く

#### 会話の中の案を指す否決の理由は、文面に起こして人に選んでもらう

「人の言葉をそのまま送る」を基本に残し、例外を 1 つだけ足す。

- 人の言葉が、この会話の中にしか無いもの（Claude が示した案の記号、「上の表の」「さっきの」）を指していて、
  そのままでは作業者（まっさらな文脈のサブエージェント）が読めないときは、Claude が指す先を展開した自己完結の文面に起こす
- AskUserQuestion で、起こした文面（1〜2 案）と「人の言葉のまま送る」を選択肢にして選んでもらう。自由入力（Other）で書き直してもらってもよい
- 送るのは人が選んだ文面か、人が書き直した言葉だけ。選ばれなければ書かない
- 迷ったら起こさずにそのまま送る（作業者は PR のコメントも読む）

ADR 0007 の「否決の理由は人の言葉をそのまま送り、Claude が作らない」を、「人の言葉か、人が選んだ文面だけを送る」に書き直す。

### Risks / Trade-offs

- **判断した直後にサブエージェントが走る。** 承認と着手は確かめずに続けるので、頼んだ瞬間に作業が始まる。止めたいときは「書くだけ」と言うか、`TaskStop` で止める
- **終わっていない記録が古いまま残ることがある。** 別のセッションが途中で死ぬと、その記録は同じループが次に `start` を書くまで閉じられない。
  それが `next.cardId` に掛かっていると、判断の後に続かない。続かなかった理由（どのループの記録か）を伝えるので、人は「ボードを進めて」で進められる
  （`board-loop` の手順 0 は `ListAgents` だけを見るので、頼み直せば進む）
- **別のカードに渡ることがある。** 判断したカードより rank が上の AI の番のカードがあると、そちらに渡る。伝える 1 行でそれを明示する
- **1 本のスクリプトは長くなる。** 手順書に載せる bash が増えるが、呼び出しの数と取り違えの余地が減るほうを採る。
  Windows の Git Bash でも `&`・`wait`・`trap` と `node` だけで動く形にする（`$!` を pid として使わない今の決まりは保つ）

### Non-Goals

- ステージの導出・`next` の選び方・CLI・人の API は変えない
- 間隔運転の待ち（5 分）を縮める仕組みは作らない。判断の後はこの変更で続くので要らない
- 監視役やサブエージェントが人の判断を書けるようにはしない。サブエージェントの報告を依頼として扱わない決まりも変えない
- サーバの起動を CLI の新しいサブコマンドにはしない（人の判断の入口を CLI に足さない ADR 0007 の線を保つため、手順書の bash に留める）

## 動作確認の手順

手順書の変更なので、ワークツリーの手順書を読ませて会話で動かす。ワークツリーは `$MAIN/.claude/worktrees/loop-resume-after-decide`（以下 `$WT`）。
始める前に `cd "$WT" && npm ci && npm run build` を済ませる。

1. サーバの 1 本化（試しのデータで）
   - 共通の決まりの「動かして確かめるとき」のとおりスクラッチパッドに bare リポジトリと clone を作り、`AI_BOARD_DATA` で指して `migrate --empty` し、`card create` でダミーのカードを 1 枚作る
   - 会話で「`$WT/.claude/skills/board-decide/SKILL.md` の手順で、`AI_BOARD_DATA=<clone>` のボードの <ダミー> を着手して。書くだけ」と頼む
   - 期待: サーバの起動から停止までの Bash の呼び出しが 1 回で、`card show` で `startedAt` が入り、`<clone の親>/server.json` が残っていない。「書くだけ」なので周は走らない
2. 続ける道（本物のボードで、次に人が判断を頼むとき）
   - 試しのデータではサブエージェントが本物のボードを読むので、続ける道は本物のカードで確かめる。次に判断待ちのカードを承認するとき（例えば別のカードの計画の承認）に、
     「`$WT` の board-decide の手順で <カード> の計画を承認して」と頼む
   - 期待: 書いた中身が伝わった後、続けて「<カード> の implement を board-worker に渡した」と出る。`next` が別のカードなら、そのカードの名前がはっきり書かれる
   - 否決を頼んだときは、書いた後に「続けて作業者に渡す / 待つ」が聞かれ、「待つ」なら何も渡らない
3. 否決の理由の起こし直し
   - 会話で Claude に案を 2 つ（A / B）出させてから、「<カード> を否決して、A で直して」と頼む（2 の否決と一緒に確かめてよい）
   - 期待: 書く前に、A を展開した文面と「人の言葉のまま」の選択肢が出て、選んだものが `## レビュー` の理由になる
4. `git -C "$WT" diff origin/main --stat` で、変わったのが手順書・README・CLAUDE.md・ADR だけであることを見る
