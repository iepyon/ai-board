# 手順書の「判断のボタン」を、今の判断の入口に合わせて書き直す

## 人に判断してほしいこと

- **どこまで書き換えるか。** 直すのは、今の形を書いた手順書のうち、無い画面のボタンを前提にした 4 か所だけにする。
  対象は `.claude/skills/board-loop/SKILL.md` の 2 か所と、`.claude/skills/board-loop/rules.md` の 2 か所である。
  次は残す。ADR 0007・0016 の背景の「ボタンを押す」と、`.claude/HARNESS_VERSIONS.md` の過去の版は、当時の経緯の記録である。
  `implement.md` の証拠の表の例の「ブラウザでの見た目」は、判断の入口ではなく、画面の変わる PR の確かめ方の例である（既定: この線引きのまま）
  - → 回答（2026-11-06、plan 承認）: 理由なしで承認（既定のまま進む）

承認は、回答の無い項目をすべて既定のまま進めると読む。既定と違う答えは、承認の理由ではなく差し戻しの理由で返してほしい。

## 提案

### Why

画面とサーバを外した（ADR 0017）後も、ループの手順書には「判断のボタン」という言い回しが残っている。
今は人がボタンを押すのではなく、`ai-board decide` か、チャットで頼んで `board-decide` で判断を書く。
意味は通じるが、手順書を読むエージェントが、無い画面を前提に人へ案内しかねない。
v2（`.claude/HARNESS_VERSIONS.md`）で画面のボタンの記述を消したときの取りこぼしで、PR #88 も `src/` だけを掃除し、`.claude/` は対象から外していた。

### What Changes

- `.claude/skills/board-loop/SKILL.md:41` の「上の 3 つは人が判断のボタンか GitHub の操作で解く」を、「人が判断（`ai-board decide`、チャットからは `board-decide`）か GitHub の操作で解く」にする
- `.claude/skills/board-loop/SKILL.md:155` の「判断のボタンでは解けないので保留にしない」を、「人の判断では解けないので保留にしない」にする
- `.claude/skills/board-loop/rules.md:119` の「人がボタン（計画を直させる / 中止）を選べるだけのことを書く」を、「人が判断（計画を直させる / 中止）を選べるだけのことを書く」にする
- `.claude/skills/board-loop/rules.md:122` の「判断のボタンでは解けない」を、「人の判断では解けない」にする

### Impact

- 手順書の言い回しだけが変わる。ループの振る舞い・CLI・データは変わらない
- `.claude/HARNESS_VERSIONS.md` の版は上げない（下の仮定）

## 設計

### Decisions

- **入口の名前は、初めに出る 1 か所（`SKILL.md:41`）にだけ書く。** ほかの 3 か所は「人の判断」「判断」とだけ書く。
  入口の名前を毎回繰り返すと、入口が変わったときの直し漏れが増えるためである。入口の詳しい説明は `board-decide` のスキルと CLAUDE.md にある
- **`rules.md:119` の判断の名前（計画を直させる / 中止）は残す。** `status --json` の `waiting[].decisions[].label` と同じ言葉で、保留の理由を読む人が、どの判断を選べばよいかを読み取れる
- 「GitHub の操作」（PR を Ready に戻す）はそのまま残す。画面とは関係が無い

### 仮定

- **手順書の版は上げない。** 根拠: `.claude/HARNESS_VERSIONS.md` の冒頭に「言い回しの直しなど振る舞いの変わらない変更では上げない」とある。
  `plan.md` の手順 2 にも同じ決まりがある。直す 4 か所は、どれもループが何をするか（保留を書くか、止まるか、続けるか）を変えない
- **直す箇所は上の 4 か所で全部である。** 根拠: `.claude`・`README.md`・`CLAUDE.md`・`REVIEW.md`・`docs` を「ボタン」「ブラウザ」「クリック」「押す」「画面」「サーバ」「ダッシュボード」「`--html`」で grep した。
  残りは ADR 0017 を説明する文、ADR 0003・0007・0011・0016 の当時の経緯と退けた代案、`.claude/HARNESS_VERSIONS.md` の過去の版、`implement.md` の表の例だけだった。
  どれも、人に判断の入口を案内する文ではない
- `src/` のコメントとテストに「ボタン」は残っていない（PR #88 で掃除済み。grep で確かめた）

### 退けた代案

- 4 か所とも入口の名前（`ai-board decide` / `board-decide`）を書く: 同じ説明が手順書に散らばり、入口が変わったときに直し漏れやすい
- ADR 0007・0016 の背景の「ボタンを押す」も直す: 当時の判断の理由を書いた文で、書き換えると、なぜその判断をしたかが読めなくなる（人に判断してほしいこと）
- `implement.md` の表の例「ブラウザでの見た目」を直す: 判断の入口の案内ではなく、画面の変わる PR で、人が目で見て確かめる行の例である。このカードの目的の外にある（人に判断してほしいこと）
- 手順書の版を上げる: 振る舞いが変わらないので、版ごとの成績の比較に意味のない区切りが入る

### Risks / Trade-offs

- 「人の判断では解けない」の 2 か所は、入口の名前が無くなる分だけ抽象的になる。ただし同じファイルの中で、`SKILL.md` は 41 行目、`rules.md` は「ハードルール」で入口を説明しているので、読み手が迷う見込みは低い

### Non-Goals

- ADR・`.claude/HARNESS_VERSIONS.md` の過去の版の経緯の記述を書き換えない（人に判断してほしいこと）
- `implement.md` の証拠の表の例を書き換えない（人に判断してほしいこと）
- 手順書の版を上げない
