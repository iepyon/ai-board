# 題材のカードの一式を、`ai-board card seed` でボードへ取り込む

## 人に判断してほしいこと

- なし

## 提案

### Why

研修では、受講者がチームで研修用のリポジトリを 1 つ fork し、手元の PC で用意された題材のループを回す。
研修用のリポジトリは、人がこのリポジトリから既に実装済みの機能を減らして後で作る。

カードの正本は `origin` の `ai-board/data` ブランチにある（ADR 0010）。GitHub の fork は既定で main しか写さないので、fork のボードは空になる。
題材を講師が毎回手で起票するのではなく、研修用のリポジトリの main に置いた一式から、コマンド 1 つで取り込めるようにしたい。

このリポジトリで作るのは、その取り込みのコマンドだけにする。題材と研修の資料は、削った形を見ないと書けないので、研修用のリポジトリを作るときにそちらへ書く。

### What Changes

使う人から見た変化は次のとおり。

- `ai-board card seed --from <dir>` で、`<dir>` に置いた Markdown のカードのうち、まだボードに無いものだけがアイデアのカードとして起票される
- 何度走らせても重複しない。既にある ID は「飛ばしました」と出る
- 取り込んだカードは `rank`・`startedAt`・`## レビュー` を持たない。並び順と着手は人が決める
- 1 枚でも読めないファイルがあれば、1 枚も起票せずに、読めないファイルと理由を全部出して止まる

### Impact

- コード: `src/cards/cli/seed-cards.ts`（新規。題材のファイルからカードの候補を作る純関数）、`src/cards/cli/card-cli.ts`（`seed` のサブコマンドと使い方の文）、
  `src/cli-main.ts`（`seed` が使うディレクトリの読み取りを io に渡す）
- テスト: `src/cards/cli/__tests__/seed-cards.test.ts`（新規）、`src/cards/cli/__tests__/card-cli.test.ts`
- ドキュメント: `README.md` と `CLAUDE.md` の CLI の一覧に `card seed`
- ステージの導出・API・画面・データ用ブランチの形・人の判断の入口: 変わらない

## 設計

### Decisions

#### `ai-board card seed --from <dir>`

- `<dir>` の直下の `*.md` を、ファイル名の順に読む（下の階層は読まない）。`<dir>` は作業ディレクトリからの相対で解決する
- 1 ファイルが 1 枚。形は `ai-board card show` の出力と同じ frontmatter 付きの Markdown
  - 読むのは frontmatter の `id` と `title` と本文だけ。`id` は省けばファイル名から補い、書いてあればファイル名と一致しなければならない（`parseCard` と同じ決まり）
  - `rank`・`startedAt`・`skipGates`・`branch`・`mr`・`created` は書いてあっても読まない（起票の時刻は取り込んだ時刻）。ほかの項目も無視する
- **先に全部読んでから書く。** 1 枚でも読めない（frontmatter が壊れている、`title` が無い、ID が不正、ファイル名と食い違う）なら、
  1 枚も起票せずに、読めないファイルと理由を全部出して 1 で終わる。`*.md` が 1 つも無いときも 1 で終わる
- 起票は 1 枚ずつ `createCardCommand`（`card create` と同じ口）で、1 枚 1 コミットにする（コミットの文は `data: <id> を作る`）
  - `DuplicateCardId` は失敗にせず、`<id>: 既にあるので飛ばしました` と出す
  - 起票したら `<id>: 起票しました` と出す
  - それ以外の失敗（push の失敗、本文の `## レビュー` に判断がある、など）は理由を出し、そこで止めて 1 で終わる。それまでに起票した分は残る（次に走らせれば続きから起票される）
- 書き込みの境界は `createCardCommand` と `planCardWrite` がそのまま守る。新しいカードの本文の `## レビュー` に判断があれば `planCardWrite` が拒むので、
  題材のファイルに承認を書いても取り込まれない
- 使い方の文（`CARD_USAGE`）に `seed --from <dir>` を足す

ファイルの読み取りは `CardCliIo` に `readMarkdownDir(dir)` を足して渡す（`readStdin` と同じく、テストで差し替えられるようにする）。
ファイルの中身からカードの候補を作る処理は `seed-cards.ts` の純関数にし、`card-markdown.ts` の `parseCard` を使って frontmatter を読む。

### 仮定

- **`seed` は `ai-board card` に置き、`decide` には置かない。** 題材の起票はアイデアのカードを作るだけで、人の判断ではない。`card create` と同じ書き込み境界で足りる（カードの探索メモ 2026-11-05「取り込みの口」）
- **1 枚 1 コミットにする。** 今の `transact` は 1 回の操作で 1 枚のカードを返す形で、まとめて 1 コミットにするには `transact` の形を変える必要がある。
  途中で止まっても、次に走らせれば続きから起票される
- **`created` は取り込んだ時刻にする。** 題材のファイルの時刻を使うと、ボードのタイムライン（ADR 0008）で研修より前にできたカードに見える
- **`<dir>` は作業ディレクトリからの相対にする。** `--root` からの相対にすると、ワークツリーで `--root` に main を渡したときに main のファイルを読み、目の前のファイルと食い違う
- **題材の置き場所の名前は決めない。** `--from` は必須にし、既定のディレクトリを持たない。置き場所は研修用のリポジトリを作るときに決める

### 退けた代案

- **題材の数だけ `card create` を呼ぶスクリプト:** 人と決めた（2026-11-05）とおり CLI に足す。スクリプトでは重複の扱いと全部読んでから書く検査をテストで守れない
- **全部を 1 コミットで起票する:** `transact` の形を変える必要があり、得るものがコミットの数だけである
- **読めないファイルを飛ばして残りを起票する:** チームで 1 つの fork を共有するので、一部だけ起票されると誰が何を直すかが分かりにくい
- **題材と研修の資料もこのリポジトリに置く:** 人と決めた（2026-11-05）とおり、研修用のリポジトリを作るときにそちらへ書く
- **`--from` に既定のディレクトリを持たせる:** 置き場所がまだ決まっていない

### Risks / Trade-offs

- 研修用のリポジトリはこのリポジトリから機能を減らして作るので、`seed` が頼る `card create` の部品（`createCardCommand`・`parseCard`）を削ると `seed` も動かなくなる。研修用のリポジトリを作るときに残す
- チームで 2 人が同時に走らせると、push の衝突は data-store が取り直してやり直し、2 人目には「既にあるので飛ばしました」と出る

### Non-Goals

- 題材のカード・研修の資料・答え合わせを書く（研修用のリポジトリの側）
- 研修用のリポジトリを作る、機能を減らす
- `config.example.yaml` の例の値を変える（研修用のリポジトリの側で決める）
- 準備を確かめるコマンドを作る
- `ai-board init` と `seed` を 1 つのコマンドにまとめる

## 動作確認の手順

ワークツリーは `$MAIN/.claude/worktrees/training-seed`（以下 `$WT`）。共有のカードを汚さないよう、`rules.md` の「動かして確かめるとき」のとおり
スクラッチパッドの bare リポジトリを `origin` にした clone（`$S/data`）を `AI_BOARD_DATA` で指し、`init` で空のデータ用ブランチを作ってから動かす。
題材の代わりに、スクラッチパッドに 3 枚の試しのカード（`$S/cards/*.md`）を置く。

1. 試しのカードが全部起票される
   - コマンド: `cd "$WT" && AI_BOARD_DATA="$S/data" node dist/cli.js card seed --from "$S/cards"`
   - 期待: 3 行の `<id>: 起票しました` が出て 0 で終わる
2. 2 回目は何も起票しない
   - コマンド: 1 と同じコマンドをもう一度
   - 期待: 3 行の `<id>: 既にあるので飛ばしました` が出て 0 で終わり、`git -C "$S/data" log --oneline | wc -l` が増えない
3. 起票したカードがアイデアの列にあり、判断も着手も持たない
   - コマンド: `cd "$WT" && AI_BOARD_DATA="$S/data" node dist/cli.js status --json --only ideas,cards.stage,cards.latestReview,cards.startedAt`
   - 期待: 3 枚がすべて `idea` で、`latestReview` と `startedAt` が null
4. 読めないファイルがあれば 1 枚も起票しない
   - コマンド: `title` の無いファイルを足したディレクトリで、新しい `$S/data` に対して `card seed --from <そのディレクトリ>`
   - 期待: 読めないファイルと理由が出て 1 で終わり、カードが増えない
5. 本文の `## レビュー` に承認を書いたファイルは取り込まれない
   - コマンド: `## レビュー` に `plan 承認` のエントリを書いたファイルだけのディレクトリで `card seed`
   - 期待: 理由が出て 1 で終わり、カードが増えない
