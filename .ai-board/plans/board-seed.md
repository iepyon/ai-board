# ワークツリーから、メインのチェックアウトの DB を共有する

## 提案

### Why

ワークツリーで並列に作業すると、ワークツリーごとに `board.db` ができ、カードの変更が別々の DB に散らばる。
`board.db` は git に載らないので、ブランチをマージしてもカードの変更はまとまらない。
新しいワークツリーではカードが 1 枚も無いボードが開き、メインの DB を手でコピーすると、
コピーし直したときに画面の並べ替え（`rank`）を上書きして失う。

先に、カードの変更をデータのマイグレーションとして git に載せ、マージでまとめる案を実装した（PR #20、閉じた）。
約 1,500 行になり、差分・再生・適用済みの記録・書き出し忘れの検知と、どれも「分かれたデータを後からまとめる」ための部品だった。

Claude Code のワークツリーは同じマシンの上にある。データを分けなければ、まとめる仕組みは要らない。
ワークツリーで起動されたら、メインのチェックアウトの `.ai-board/board.db` を開くようにする。

### What Changes

- `resolvePaths(root)` が DB の場所を決めるとき、`root` が git のリンクされたワークツリーなら、
  メインのチェックアウトの `.ai-board/board.db` を使う。それ以外（メインのチェックアウト、git でない）は今までどおり `root` の下。
- 設定ファイル `config.yaml` も同じくメインのチェックアウトのものを読む。DB と同じく各自のローカルに置く git に載らないファイルで、
  ワークツリーには無いため（今はワークツリーで GitHub 連携が「未設定」になる）。
- 計画ファイル（`.ai-board/plans/`）は今までどおり `root` の下を読む。計画は git でブランチに乗るもので、共有しない。
- 環境変数 `AI_BOARD_DB` で DB の場所を明示できるようにする。ai-board 自身をワークツリーで開発し、
  スキーマを変えるコードを動かすときに、共有の DB を上げてしまわないための逃げ道。
- 起動時のログに、DB の場所と、共有しているかどうかを出す。

### Impact

- `src/shared/config.ts` — DB と設定ファイルの置き場所の解決
- `src/shared/git-worktree.ts`（新規）— `root` からメインのチェックアウトを求める（`.git` ファイルと `commondir` を読む）
- `src/cli-main.ts` — 起動ログ
- テスト: ワークツリー / メイン / git でない / 壊れた `.git` / `AI_BOARD_DB` の各場合
- ドキュメント: `README.md` / `CLAUDE.md` の「タスクは board.db にある」
- DB のスキーマ・API・画面は変えない

## 設計

### Decisions

#### メインのチェックアウトはファイルから求める

リンクされたワークツリーでは `.git` がファイルで、`gitdir: <メインの .git>/worktrees/<名前>` を持つ。
その `commondir` ファイルがメインの `.git` を指す（`../..` のような相対パス）。
これを読めば `git` を実行せずに済み、外部コマンドの実行（`cli-runner.ts`）も要らない。

`.git` がディレクトリならメインのチェックアウト、無ければ git でないとみなし、どちらも `root` をそのまま使う。
`.git` ファイルや `commondir` が読めない・形が違うときも `root` にとどめ、警告を出す（ボードが開かないより良い）。
メインの `.git` がベアリポジトリの場合（`commondir` の先が `.git` という名前でない）も `root` にとどめる。

#### 共有するのは git に載らないものだけ

| ファイル      | 置き場所               | 理由                                       |
| ------------- | ---------------------- | ------------------------------------------ |
| `board.db`    | メインのチェックアウト | バックログはブランチに依らず 1 つ          |
| `config.yaml` | メインのチェックアウト | 各自のローカル設定。ワークツリーには無い   |
| `plans/`      | `root`（ワークツリー） | git でブランチに乗る。ブランチの計画を見る |

#### 同時に開いても今の仕組みで足りる

サーバと `ai-board card` の CLI が同じ DB を同時に開くことは今もあり、WAL と `busy_timeout` で扱っている。
複数のワークツリーのサーバが同じ DB を開いても同じ。別のプロセスの書き込みは `data_version` で拾われ、
どのワークツリーの画面にも届く。

### Risks / Trade-offs

- **別のマシン・別の clone とは共有できない。** 同じマシンのワークツリー間だけ。背景の並列作業はこれで足りる
- **スキーマの版のずれ。** ワークツリーで新しい ai-board を動かすと共有の DB が新しい版に上がり、
  メインの古い ai-board は「DB のスキーマが新しい」で開けなくなる。ai-board 自身を開発するときだけ起きる。
  `AI_BOARD_DB` で別の DB を指せば避けられる
- **ワークツリーによってステージが違って見える。** 計画ファイルはブランチごとにあるので、同じカードが
  あるワークツリーでは計画レビュー、別のワークツリーでは計画提案中に見えることがある
- **ポーリングの重複。** 複数のワークツリーでサーバを起動すると、それぞれが GitHub に問い合わせ、同じ PR 番号を書き戻す。
  値は同じなので害は無いが、問い合わせの数は増える

### Non-Goals

- 別のマシン・別の clone との同期（閉じた PR #20 の方式）
- ワークツリーごとに DB を分ける設定
- 計画ファイルの共有
