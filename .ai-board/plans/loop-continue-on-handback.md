# サブエージェントの報告を受けたら、完了の通知を待たずに次の周へ進む

## 提案

### Why

サブエージェントが手を終えると、監視役には別々の知らせが 2 つ届く。

1. **報告のメッセージ**（サブエージェントの hand-back。`結果:`・何をしたか・人が見るもの）。これが届くと監視役の手番が始まる
2. **完了の通知**（task-notification。`usage` の `subagent_tokens` と `duration_ms` が載る）。報告より後に届く

`board-loop/SKILL.md` の手順 4 は「サブエージェントが終わると、完了の通知が届く」と、知らせが 1 つだけのように書き、
トークンと時間は「完了の通知の `usage` を写す」としている。監視役は `loop finish` にそれを写すため、1 を受けたところで「完了の通知を待つ」と言って手番を終えた。
ところが 2 は、手番を終えて待っているセッションを起こさず、人の次のメッセージに添えられて届く。
2026-11-03 に loop-resume-after-decide を 1 周回したときは、5 つの手のうち 4 つでこの止まり方をし、人が「どうなった？」と聞くまで次の周に進まなかった。

あわせて、この書き方には今は表に出ていない 2 つの穴がある（どちらも手順 4 を「報告で続ける」に直すと表に出る）。

- 手順 0 は `ListAgents` で `running` のサブエージェントがいれば「作業中」で周を終える。報告を受けた手番で、報告したサブエージェント自身がまだ `running` に見えると、続けた周がそこで止まる
- 後から届いた完了の通知を受けて `loop finish` を書くと、すでに次の手の `start` を書いた後なら、次の手の記録を閉じてしまう（同じカードに続けて手を渡すことが多いので、`--card` の食い違いでも拒まれない）

### What Changes

使う人から見た変化は次のとおり。

- サブエージェントが報告を返すと、監視役はそのまま `loop finish` を書いて報告を伝え、手順 0 から次の周へ進む。「どうなった？」と聞き直さなくてよい
- 1 手の記録のトークンと時間は、報告と同じ手番に完了の通知が届いていたときだけ入る。届いていなければ「—」と出る（今の 4/5 の手と同じ見え方。今は「—」になるうえに止まっていた）
- 後から届いた完了の通知では、記録の書き足しも周の始め直しもしない

中の仕組みは変えない。変わるのは手順書とドキュメントだけで、コード（`src/`）と `loop finish` の振る舞いには手を入れない。

### Impact

- 手順書: `.claude/skills/board-loop/SKILL.md`（手順 0・手順 4・ハードルール）、`.claude/skills/board-decide/SKILL.md`（手順 6 の「完了の通知で続ける」の言い回し）
- ドキュメント: `README.md`（「AI ループ」と「ループの 1 手の記録」）、`docs/architecture.md`（「ループの 1 手の記録」の冒頭）、`docs/specs/loop-activity/spec.md`（シナリオ「1 手を渡して終える」の WHEN と、トークンと時間が欠けうること）
- ADR: 新しい ADR `0014`（報告で続け、完了の通知を待たない）を書き、`docs/adr/README.md` の一覧に足す。`0013` の「以後は完了の通知でつながる」を「報告でつながる」に直す
- コード・API・データ用ブランチの形: 変わらない

## 設計

### Decisions

#### 続ける合図は報告で、どちらの知らせが先でも 1 手につき 1 度だけ `finish` を書く

手順 4 の冒頭を「サブエージェントが終わると、報告と完了の通知の 2 つが届く。どちらが先かはハーネスの都合で変わりうる」に書き直し、次の決まりにする。

- **報告（`結果:` を含むもの）を受けた最初の手番で、`finish` を書いて報告を伝え、手順 0 から次の周を続ける。** 完了の通知を待たない。完了の通知が報告を含んで先に届いたときは、それを報告として扱う
- その手番の中にすでに完了の通知が届いていれば `usage` を写し、届いていなければ `--tokens` / `--duration-ms` を省く
- 「完了の通知を待つ」と言って手番を終えない。これをハードルールにも書く

#### 書く前に、閉じる記録が報告したサブエージェントのものかを確かめる

`finish` の前に `status --json --only loop` を読み、`loop.running` にこのループ（`--loop` が自分のセッション ID）の記録があり、その `agent` が報告したサブエージェントの名前と一致するときだけ `finish` を書く。
一致しなければ（記録が無い、別の名前の記録が開いている）、その知らせはもう閉じた手のもので、`finish` も伝え直しも次の周もしない。

- 後から届いた完了の通知（人の次のメッセージに添えられて届く）で、次の手の記録を誤って閉じないための確かめである。
  `finish` の CLI は `--card` の食い違いしか見ないので、同じカードに続けて手を渡したとき（implement の task → review など）を拒めない
- 名前は手順 3 で `--agent` に渡したもので、時刻が付いているので手ごとに違う。監視役の記憶ではなく記録で決めるので、自動の要約が入っても判定が変わらない
- `status` が失敗したときは確かめられないので、`finish` を書かずに報告を伝え、次の周へ進む（記録は次の `start` で「途切れた」で閉じる。記録よりループを止めないことを優先する手順 3 の決まりと同じ）

#### 手順 0 で、報告を返したサブエージェントは動いていないものとして扱う

報告を受けた手番から続ける周では、`ListAgents` に報告を返したサブエージェント自身が `running` で残っていても、それは数えない。
報告（hand-back）はサブエージェントの最後の手で、それを返した後に作業は続かないためである。
それ以外の `running` のサブエージェントがいれば、今までどおり「作業中」で周を終える。

#### 後から届いた完了の通知で、閉じた記録に値を書き足す入口は作らない

トークンと時間が「—」になりやすくなることは受け入れる。

- 書き足す入口（`finish` をもう一度呼ぶと値だけ足す など）は、`loop-activity` の仕様の「終わった記録を書き換えては SHALL NOT」を崩し、CLI とリポジトリの変更・テストが要る
- 書き足しの手番は、後の知らせが人の次のメッセージに添えられて届くときに走る。人の依頼の手番に、ループの記録の書き込みを毎回挟むことになる
- 記録はステージの導出にも次の一手にも使わない、見るためのものである（ADR 0008）。止まらないことを優先する

### Risks / Trade-offs

- トークンと時間の記録がほとんど「—」になる見込みがある。手ごとの重さを比べる手がかりが薄くなる。困ったら、書き足す入口を別のカードで足す（下の Non-Goals）
- `ListAgents` で報告したサブエージェントを除く判定を、監視役が名前で行う。名前を取り違えると、動いている別のサブエージェントを見落とす。
  名前は手順 3 で自分が決めたもので、報告の手番の知らせにも載るので、取り違えは起きにくい
- 報告と完了の通知の届き方はハーネスの都合で、手順書は両方の順に耐える形にする。どちらかが届かない場合は、報告が届かなければ今までどおり止まる（次の cron の周や人の頼みで拾う）

### Non-Goals

- 閉じた記録にトークンと時間を書き足す入口（`loop finish` の振る舞いの変更）
- `loop finish` の CLI に `--agent` の照合を足すこと（確かめは手順書で行い、CLI は今の形のまま）
- ハーネスの知らせの届き方そのものを変えること
- `board-decide` の続け方（ADR 0013）の判断の中身。言い回しを報告に合わせるだけ

## 動作確認の手順

手順書の変更なので、ワークツリーの手順書を読ませて会話でループを回す。ワークツリーは `$MAIN/.claude/worktrees/loop-continue-on-handback`（以下 `$WT`）。
サブエージェントは本物のボードを読むので、試しのデータではなく本物のカードで確かめる。

1. 報告で続く
   - 実装中のカード（または着手済みのアイデア）があるときに、会話で「`$WT/.claude/skills/board-loop/SKILL.md` の手順でボードを進めて」と頼み、そのまま待つ
   - 期待: サブエージェントの報告が届いた手番で、「完了の通知を待つ」と言わずに `loop finish` が書かれ、報告が伝わった後に続けて「<カード> の <手> を <サブエージェント> に渡した」と出る。
     人が何も打たなくても、`止まった` か `next` が null になるまで手が続く
2. 手順 0 で止まらない
   - 1 の続いた周で「作業中: <報告したサブエージェントの名前>」と出て止まらないこと
3. 記録が取り違えられない
   - 1 が何手か続いた後に、人が何か打って、後から届いた完了の通知が添えられたとき
   - 期待: その手番で `loop finish` が書かれない。`node "$MAIN/dist/cli.js" status --json --only loop --root "$MAIN"` の `running` に、今動いている手の記録が開いたまま残る
   - ボードのカードの詳細「ループの手」で、各手に時間・結果が入り、トークンと時間は「—」か値のどちらかになっている（前の手の値が次の手に入っていない）
4. `git -C "$WT" diff origin/main --stat` で、変わったのが手順書・README・`docs/`（architecture・spec・ADR）と計画だけであることを見る
