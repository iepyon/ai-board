# カードの無い計画の警告を、既定では折りたたむ

## 提案

### Why

ページ末尾の警告の帯に「カードの無い計画 8 件」が出ており、計画の ID が 8 つ横に並んで帯が数行に広がっている。
今の 8 件（`board-dashboard` / `board-lanes` / `board-seed` / `drop-explore-lanes` / `github-pr-provider` / `gitlab-docker` / `idea-tiers` / `order-card`）は、
どれも `.ai-board/plans/archive/` にある計画で、カードが残っていないものである。
急いで直すものではなく、毎回目に入る必要もない。
一方で件数が増えたこと自体には気付きたいので、帯は消さずに、件数だけを見せて中身を畳む。

### What Changes

- 警告の帯のうち「カードの無い計画」を、既定で閉じた折りたたみ（`<details>`）にする
  - 閉じているときは「▸ カードの無い計画 N 件」と、説明の 1 文（カードを消したか、名前を変えた可能性があります）だけを出す
  - 見出しを押すと開き、計画の ID の一覧が出る
- 「GitHub に接続できません」の帯は今のまま開いて出す（PR中 / マージ済み の件数が狂う理由なので、隠さない）

### Impact

- 変更: `src/web/App.tsx`（`Warnings`）、`src/web/styles.css`（警告の帯の折りたたみの見た目）
- サーバ、API（`GET /api/board` の `orphanPlans`）、ステージの導出は変えない
- `src/web/` はテストの対象外なので、型検査と lint で担保する。切り出すほどのロジックは無いので、`src/shared/` へは移さない

## 設計

### Decisions

#### 既存の折りたたみ（`details.fold`）にならって `<details>` で作る

マージ済み / 中止 の表は `FoldedTables.tsx` の `Fold` で、`<details className="fold">` を既定で閉じて出している。
同じく `<details>` を使い、開閉の状態は React で持たない（制御しない）。
SSE でボードが読み直されても `Warnings` は同じ要素のまま描き直されるので、人が開いた帯は開いたまま残る。
`useState` で持っても、ページの読み込み直しで閉じるのは同じで、得るものが無い。

#### 帯の横並びは `<summary>` に持たせる

`.warn-banner` は `display: flex` で、見出し・ID の列・説明を横に並べている。
`<details>` 自体を flex の箱にする書き方はブラウザによって効き方が揃わないので、
`<details>` に帯の枠（線・背景・角丸・余白）を、`<summary>` に今の横並び（見出しと説明）を持たせ、
ID の一覧は `<summary>` の下に置く。

開閉の印（▸ / ▾）は `details.fold` と同じものを使う。
ただし既存の規則は `summary h2::before` を対象にしており、この帯の見出しは `<b>` なので、警告の帯の側に同じ印の規則を足す。
ブラウザ既定の三角（`::-webkit-details-marker` と `list-style`）は `details.fold` と同じく消す。

#### ID の一覧は開いたときだけ出す

開いたときの一覧は、今と同じく `mono` の書体で `, ` 区切りに並べる。
件数が増えても、閉じていれば帯は 1 行に収まる。

### Risks / Trade-offs

- **ID が 1 件だけでも畳まれる。** 1 件なら開いて出しても邪魔にならないが、件数で見た目を変えると帯の振る舞いが読みにくくなるので、件数によらず畳む
- **開いた状態はページの読み込み直しで閉じる。** 状態を保存しない。見返す場所なので、閉じた状態から始まって困らない

### Non-Goals

- archive にある計画を「カードの無い計画」から外すかどうか（数え方の変更）。
  今の 8 件はすべて archive にあり、数えなければ帯そのものが消える。ただし、マージ済みの計画のカードを消したことに気付けなくなるので、別のカードで決める
- 今の 8 件の計画ファイルを消す、またはカードを作り直すこと
- 「GitHub に接続できません」の帯の見た目の変更
- 開閉の状態をブラウザに保存すること

## 動作確認の手順

共有の DB を汚さず、カードの無い計画を確実に出すために、`AI_BOARD_DB` で空の DB を指して起動する。
空の DB にはカードが 1 枚も無いので、ワークツリーの `.ai-board/plans/` と `.ai-board/plans/archive/` にある計画がすべて「カードの無い計画」として出る。
メインのチェックアウトの ai-board が 5673 で動いていることがあるので、別のポートで起動する。

1. ワークツリーで `npm run build` を実行する
2. `export AI_BOARD_DB="$(mktemp -d)/board.db"` の後に `node dist/cli.js --root . --port 5683 --no-open` で起動し、表示された URL をブラウザで開く
3. ページの末尾を見て、次を確かめる
   - 「▸ カードの無い計画 N 件」と説明の 1 文が 1 行で出ており、計画の ID の一覧は見えない
   - 見出しを押すと印が ▾ に変わり、計画の ID の一覧が出る。もう一度押すと閉じる
   - 開いたまま、同じ `AI_BOARD_DB` を指した別の端末で `node dist/cli.js card create --title 試し --root . < /dev/null` を実行してカードを足し、ボードが読み直されても帯が開いたまま残る
   - ライトとダークの両方で、帯の色と印が読める
4. 「GitHub に接続できません」の帯を出せる環境なら、その帯が畳まれずに今のまま出ることを見る（出せないときは見送ってよい）
5. 起動したサーバを止める
