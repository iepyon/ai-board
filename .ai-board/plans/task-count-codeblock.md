# 計画のタスクを数えるとき、コードブロックの中の行を外す

## 提案

### Why

計画のタスク（行頭の `- [ ]` / `- [x]`）は、ボードの進捗バー（`src/board/repositories/plan.repository.ts` の `countTasks`）と、
実装中の段の判定（`src/board/services/impl-step.ts` の `resolveImplStep`）が、`src/board/models/plan-task.ts` の `TASK_PATTERN` で数えている。
どちらもコードブロック（` ``` ` で囲んだ範囲）の中の行も数える。
サブエージェントの共通の決まり（`.claude/skills/board-loop/subagent-rules.md` の「タスクの数え方と `## AI レビュー` 節」）も、
食い違わせないために「コードブロックの中の行も数える。例にチェックボックスを書くときは行頭に `（例）` を付ける」と決めている。

計画に `## AI レビュー` 節の書き方などの例を載せると、例の中のチェックボックスが未チェックのタスクとして数えられる。
タスクを全部倒しても段が `task` のまま進まず、進捗バーも 100% にならない。`loop-impl-review` では例の行を書き換えてしのいだ。
例にチェックボックスを書くのは自然なことで、書き手に `（例）` の回避を覚えさせるより、数え方の側で例を外すほうがよい。

### What Changes

- タスクを数えるとき、フェンスで囲んだコードブロックの中の行を外す。進捗バーと段の判定の両方が、同じ純関数を通す
- `## AI レビュー` 節があるかの判定も、同じコードブロックの見分け方を使う（今は `impl-step.ts` に別の簡単な見分け方がある）
- 共通の決まりの「タスクの数え方」を「コードブロックの中の行は数えない」に書き換え、`（例）` を付ける回避を消す。
  `board-worker.md` / `board-reviewer.md` / `board-task.md` / `board-planner.md` は既にこの節を参照しているだけなので、文言は変えない
- `docs/architecture.md` と `README.md` の数え方の説明を直す

### Impact

- コード: `src/board/models/plan-task.ts`、`src/board/repositories/plan.repository.ts`、`src/board/services/impl-step.ts`
- テスト: `src/board/models/__tests__/plan-task.test.ts`（新規）、`src/board/repositories/__tests__/plan.repository.test.ts`、`src/board/services/__tests__/impl-step.test.ts`
- 手順書: `.claude/skills/board-loop/subagent-rules.md`
- ドキュメント: `docs/architecture.md`、`README.md`
- 既にある計画: `.ai-board/plans/archive/` の 25 件を走査し、コードブロックの中にチェックボックスの行を持つものは無かった。進捗の見え方は変わらない
- API の形・ステージの導出・データ用ブランチの形は変わらない

## 設計

### Decisions

#### 数え方を 1 つの純関数に寄せる

`plan-task.ts` に、本文の行のうちコードブロックの外にあるものだけを返す純関数（仮に `linesOutsideCodeBlocks(text): string[]`）を足す。
`countTasks` と `resolveImplStep`（未チェックのタスクの判定と `## AI レビュー` 節の判定）はどちらもこの関数の結果に `TASK_PATTERN` などを当てる。
`TASK_PATTERN` / `COMPLETED_TASK_PATTERN` 自体は変えない（字下げしたサブタスクや `-[ ]` を拾う緩さは残す）。
`impl-step.ts` の `CODE_FENCE_PATTERN` とその場の見分け方は消し、この関数に置き換える。

#### コードブロックの見分け方

画面の本文の変換（`src/shared/markdown.ts` の `matchFence` / `closesFence`）と同じ規則にそろえる。

- 開くフェンスは、行頭の空白の後に ` ``` ` か `~~~`（3 文字以上）が来る行。後ろに言語名などがあってよい。
  バッククォートのフェンスで、後ろにバッククォートを含むものはフェンスではない（インラインコード）
- 閉じるフェンスは、開いたものと同じ文字で同じ長さ以上の連なりだけの行。` ``` ` で開いた範囲を `~~~` では閉じない
- フェンスの行そのものも、コードブロックの行として外す
- 字下げの深さは問わない。箇条書きの中に字下げして書いたフェンスも拾う（`markdown.ts` も箇条書きの中では字下げしたフェンスを読む）

`markdown.ts` の関数を直接使い回さないのは、あちらは箇条書きの入れ子を組み立てる読み手と一体で、行の印だけを取り出す口が無いからである。
規則（フェンスの文字と閉じる条件）だけをそろえ、テストで同じ例を通す。

#### 閉じていないフェンスは、コードブロックとみなさない

閉じるフェンスが見つからないまま本文が終わったら、その開くフェンスは無かったものとして、後ろの行を数える。
画面の変換（`markdown.ts`）は閉じていないフェンスを本文の終わりまでのコードとするので、ここだけ食い違う。

食い違いを選ぶのは、フェンスの書き損じ 1 つで後ろのタスクがすべて消えるのを避けるためである。
タスクが消えると、進捗バーが 100% になり、段の判定が `review` / `close` へ進み、未着手のタスクを残したまま動作確認や Ready へ向かってしまう。
数えすぎて止まるほうが、数え落として先へ進むより気づきやすい。

#### 字下げしたコードブロック（4 つの空白）は扱わない

4 つの空白で字下げした行をコードブロックとはみなさない。
計画では字下げしたサブタスク（`    - [ ] …`）を親と同じく数えており、字下げのコードブロックを外すとそれが消える。計画の書き方でもこの形の例は使わない。

#### 共通の決まりは数え方の要点だけを書き、詳細はコードを参照させる

`subagent-rules.md` の節は「進捗バーと同じ数え方（`plan-task.ts`）。フェンスで囲んだコードブロックの中の行は数えない。閉じていないフェンスは無いものとする」とだけ書く。
サブエージェントは計画を目で読んで数えるので、規則の要点は文で残す。細かい境界（バッククォートを含む info など）はコードの docstring に置く。

### Risks

- **段の判定が変わるカードがある。** 実装中のカードで、計画のコードブロックの中にだけ未チェックの行があったものは、`task` から `review` / `close` へ進む。
  今そうなっているカードは、例の行を書き換えてしのいでいるはずで、影響は小さい
- **書き手がコードブロックの中に本物のタスクを書いた場合、数えられない。** 計画の書き方ではタスクを `## タスク` 節の箇条書きに書くので、起こりにくい
- **手順書を読む時点の食い違い。** 監視役とサブエージェントは `$MAIN` の `subagent-rules.md` を読む。マージ前のブランチで動くカードは、古い文言（コードブロックの中も数える）とコードの両方が main のものなので食い違わない

### Trade-offs

- 画面の変換と同じ関数を使えば見分け方が完全にそろうが、`markdown.ts` の作りを変える必要があり、変更が大きい。規則だけをそろえる
- 閉じていないフェンスの扱いだけ画面と食い違う（上の Decisions）

### Non-Goals

- 字下げしたコードブロック（4 つの空白）、HTML のコメント（`<!-- -->`）の中の行を外すこと
- `TASK_PATTERN` の緩さ（字下げ、`-[ ]`、`*`）を変えること
- ステージの導出（`stage-resolver.ts`）を変えること。進捗はステージを立てない
- archive 済みの計画を書き換えること

## 動作確認の手順

共有のカードを汚さないよう、`.claude/skills/board-loop/subagent-rules.md` の「動かして確かめるとき」に従い、`AI_BOARD_DATA` でスクラッチパッドの clone を指す。

1. `npm run build` の後、`AI_BOARD_DATA` を指したまま `node dist/cli.js card create --id demo-codeblock --title 例の数え方` でダミーのカードを作る
2. ワークツリーに `.ai-board/plans/demo-codeblock.md` を一時的に作り、次を書く
   - `## タスク` の下に、チェック済みのタスク 1 つと未チェックのタスク 1 つ
   - その後ろに ` ```markdown ` で開いたコードブロックを置き、中に未チェックのチェックボックスの行を 2 つ書いて閉じる
   - さらに、箇条書きの中に字下げしたフェンスで、同じくチェックボックスの行を 1 つ書く
3. `AI_BOARD_DATA` を指して `npm run dev` と `npm run dev:web` を起動し、ブラウザで `demo-codeblock` のカードの進捗が `1/2` になることを見る（直す前は `1/5`）
4. 一時ファイルの未チェックのタスクを `[x]` にして再読み込みし、進捗が `2/2`（100%）になることを見る
5. 開いたコードブロックの閉じるフェンスを消して再読み込みし、コードブロックの中の行も数えられて 100% でなくなることを見る
6. 段の判定は `git show` でブランチを読むので画面からは見えない。単体テスト（`impl-step.test.ts`）の、コードブロックの中にだけ未チェックの行がある計画が `review` になるケースで確かめる
7. 確かめ終えたら `.ai-board/plans/demo-codeblock.md` を消し、サーバを止める
