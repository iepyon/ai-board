## アイデア

ボードを、React の閲覧専用の画面で見られるようにする。サーバは足さず、人の判断を書く入口も作らない。

- **閲覧だけ。** 画面は `ai-board status --json` の結果を読んで描くだけにする。承認・差し戻し・並べ替えは、今までどおりチャットと CLI（`board-decide` / `ai-board decide`）で行う
- **サーバは足さない。** Vite でビルドした静的な成果物を `.ai-board/local/` に書き出し、ブラウザで開く。`board-view`（ひな形に流し込む静的な HTML）の延長に置く
- **型を共有する。** `status --json` の形は `src/board/` の型とスキーマを正とし、画面はそれを import して props に流す。画面のための型の写しは作らない
- **ステージは持たない。** 画面は `status --json` が返したステージをそのまま描く。画面側でステージを導出し直したり、保存したりしない
- **区画と並びは純関数に任せる。** 区画・出せる判断・並び順は `src/board/services/board-sections.ts` の純関数を使う（ADR 0018 の「ブラウザでも動く」前提）

## 背景

2026-11-28、ボードの画面をリッチにするなら React がよいかを話した。
ADR 0017 で、画面・サーバ・ダッシュボードをいったん外している。今は `board-view` の静的な HTML だけで、見た目を整えるたびにひな形を直すことになる。
一方で、判断を画面から書ける形に戻すと、「人の判断は人だけが書く」という書き込み境界の扱いを作り直すことになる。
そこで、まず閲覧だけの画面を作って使い心地を確かめ、操作が欲しくなってから、ローカルのサーバと書き込みの入口を別のカードで考える。

## 論点

- **ADR。** 画面を戻すのは不変条件に近い判断なので、ADR 0017 を書き直すか、新しい ADR を足すか。`adr` のスキルで書く
- **`board-view` との関係。** 置き換えるか、併存させるか。`board-view` の `render.mjs` とひな形をどこまで使い回すか
- **自動更新。** サーバが無いので、画面は書き出した時点のスナップショットになる。`board-loop` の手の終わりに書き出し直すか、人が `board-view` を呼び直すか
- **フレームワーク。** React でよいか。Preact など軽いものでも足りるか。ビルドと依存を増やす価値があるか
- **置く場所。** `src/web/` を戻すか、別のディレクトリにするか。`src/shared/` を両方でビルドする制約をどう扱うか
- **テスト。** 画面の描画を何で確かめるか（vitest と testing-library、または `render.mjs` の出力の確認）
- **やらないこと。** ローカルサーバ、画面からの書き込み、認証、リアルタイムの更新（SSE など）
