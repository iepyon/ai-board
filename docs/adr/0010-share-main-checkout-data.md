# 0010. ワークツリーからメインのチェックアウトのデータを共有する

- 状態: 採用（一部を [0019](0019-cards-on-data-branch.md) が置き換え）
- 日付: 2026-09-27（PR #22 のマージ）
- 置き換え元: なし
- 置き換え先: なし

## 状況

カードの正本は git に載らない `.ai-board/board.db` だった（[0009](0009-cards-in-sqlite.md)）。
ワークツリーで並列に作業すると、ワークツリーごとに `board.db` ができ、カードの変更が別々の DB に散らばる。
ブランチをマージしてもカードの変更はまとまらない。新しいワークツリーではカードが 1 枚も無いボードが開き、
メインの DB を手でコピーすると、コピーし直したときに画面の並べ替え（`rank`）を上書きして失う。
`config.yaml` も git に載らないので、ワークツリーでは GitHub 連携が「未設定」になっていた。

カード `board-seed` の計画は、同じ日に 3 回書き直された。

1. カードを 1 枚 1 ファイルで git に載せ、DB との間を 3-way で同期する `ai-board sync` を足す（`73b722a`）
2. カードの変更を `.ai-board/changes/*.yaml` のデータのマイグレーションとして git に載せ、マージでまとめる（`6a5fbd4`、計画は PR #19 で main に入った）
3. ワークツリーで起動されたら、メインのチェックアウトの DB を開く（`2bbaaf1`）

2 の案は PR #20 で実装まで進んだ。

## 決定

**データを分けず、ワークツリーで起動されたらメインのチェックアウトのものを開く。** 共有するのは git に載らないものだけにする。

| ファイル      | 置き場所               | 理由                                       |
| ------------- | ---------------------- | ------------------------------------------ |
| `board.db`    | メインのチェックアウト | バックログはブランチに依らず 1 つ          |
| `config.yaml` | メインのチェックアウト | 各自のローカル設定。ワークツリーには無い   |
| `plans/`      | `root`（ワークツリー） | git でブランチに乗る。ブランチの計画を見る |

- メインのチェックアウトは `.git` ファイル → `gitdir` → `commondir` を読んで求め、git コマンドは実行しない。
  読み解けないとき（壊れた `.git`、ベアリポジトリ）は警告してワークツリーの下にとどまる。
- 環境変数 `AI_BOARD_DB` で DB の場所を明示できるようにする。ai-board 自身をワークツリーで開発するとき、共有の DB のスキーマを上げないための逃げ道。
- 同時に開くことは、サーバと CLI が同じ DB を開く今の仕組み（WAL・`busy_timeout`・`data_version`）で足りるとする。

## 検討した代案

- **カードの変更をデータのマイグレーションとして git に載せる（PR #20、閉じた）** — 約 1,500 行になり、差分・再生・適用済みの記録・書き出し忘れの検知と、
  どれも「分かれたデータを後からまとめる」ための部品だった。Claude Code のワークツリーは同じマシンの上にあり、データを分けなければまとめる仕組みは要らない。
- **カードをファイルに書き出し、DB と 3-way で同期する** — 最初に提出した計画。この案を退けた理由は記録に無い。

## 結果

- 新しいワークツリーでも、メインと同じカードと GitHub 連携でボードが開くようになった。
- 計画の Risks に書いたとおり、**別のマシン・別の clone とは共有できない**（Non-Goals）。
- ワークツリーで新しい ai-board を動かすと共有の DB のスキーマが上がり、メインの古い ai-board が開けなくなる。避けるには `AI_BOARD_DB` で別の DB を指す。
- 計画ファイルはブランチごとにあるので、同じカードがワークツリーによって計画レビューにも計画提案中にも見える。
  ボードを動かすチェックアウトから計画が見えない問題は、[0011](0011-plan-review-in-draft-pr.md) で計画を Draft の PR で読む形にして扱った。
- 複数のワークツリーでサーバを起動すると、それぞれが GitHub に問い合わせる。
- [0019](0019-cards-on-data-branch.md) で、共有の対象が `board.db` からメインのチェックアウトの `.ai-board/data/`（データのワークツリー）に変わり、
  `AI_BOARD_DB` は `AI_BOARD_DATA` に置き換わった。メインのチェックアウトを `.git` ファイルから求める解決（`sharedBoardDir`）と、計画は `root` の下を読むことはそのまま残った。
