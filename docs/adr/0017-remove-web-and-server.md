# 17. 画面とサーバをいったん外し、ボードを CLI とチャットとダッシュボードだけで扱う

- 状態: 採用
- 日付: 2026-11-05

## 背景

ボードには React の画面（`src/web/`）と、それを配るサーバ（HTTP API・SSE・ファイル監視・データ用ブランチの取り直し・GitHub の定期のポーリング）があった。
GitHub API の上限対策（`forge-poll-budget`）でサーバのポーリングの減らし方を話すうちに、ポーリング・控えの食い違い・`src/shared/` を両方でビルドする制約など、画面のために考えることが多いと分かった。
判断は既にチャットから `ai-board decide` で書け（ADR 0007）、ボードは `status --html` のダッシュボードで見られた（ADR 0015）。
人は、画面とサーバをいったん消し、後でゼロから作り直すと決めた。

## 決定

- **画面とサーバをまとめて外す。** 画面が無ければ HTTP API・SSE・ファイル監視・取り直し・定期のポーリングを使う者がいないので、片方だけを残さない。
- **GitHub に問い合わせるのは `ai-board` の CLI だけで、1 回の実行で `refresh()` を 1 回だけ行う。** PR 番号の書き戻しと PR の状態の控えも、`status` などの CLI が書く。
- ボードを見るのは `ai-board status`（人向けの数行・`--json`・`--html`）で、人の判断は `ai-board decide`（チャットからは `board-decide`）で書く。
- `ai-board`（引数なし）はサーバを起動せず、使い方を出して終わる。`status` の出力から起動中のサーバの URL（`server`）を消す。
- **API は見本として 2 つだけ残す。** `ai-board serve` で `127.0.0.1` にだけ bind し、`GET /api/board`（`status --json` と同じ形）と `POST /api/cards/:id/reviews`（`decide` と同じ検査）だけを持つ。GitHub には問い合わせず、PR の状態は CLI が書いた控えを読む。
- 区画・出せる判断・並び順の純関数（`src/shared/dashboard-sections.ts` など）は、`status` とダッシュボードと `decide` が使うので残す。

## 結果

- 画面の型の写し、API とエラーのマッピング、SSE とファイル監視、ポーリングの間隔と控えの読み直しを考えずに済む。依存（chokidar・react・vite など）も外れた。
- 常に開いておく画面が無くなり、判断待ちに気付くのは、ループが手の終わりにチャットで伝えるか、人が `status` やダッシュボードを見たときになる。
- ドラッグでの並べ替えと本文のその場の編集が無くなり、`ai-board decide move` / `ai-board card body` か、チャットで頼む形になる。
- 画面を作り直すときは、どこから GitHub を引くか・認証を持たないので `127.0.0.1` にだけ bind することを、改めて決める。

## 退けた案

- **画面だけを消してサーバ（API）をすべて残す** — API を使う者がいなくなり、使われないコードと e2e を保守することになる。見本に要る 2 つだけを残した。
- **画面を表示に徹しさせ、GitHub への問い合わせを `status` に寄せる** — 画面とサーバを残す限り、ファイル監視・SSE・控えの読み直しを考え続けることになる。作り直す前提なら消すほうが考えることが減る。
- **消す前に画面を使わずにしばらく回し、困る操作を確かめる** — 人が取らないと決めた。
