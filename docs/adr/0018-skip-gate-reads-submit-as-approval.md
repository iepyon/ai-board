# 0018. 飛ばす宣言のあるゲートでは 提出 / 再提出 を承認と読み、宣言だけで通過扱いにしない

- 状態: 採用
- 日付: 2026-11-01
- 置き換え元: なし
- 置き換え先: なし

## 状況

飛ばす宣言（`skipGates`）は `board-lanes` で入れた。レビュー列に来てからボタンで 1 回だけ通す方式は、導出の入力が増えるので採らず、frontmatter での事前宣言にした。
`gateState` は、宣言のあるゲートをログを見ずに `approved` と返していた。

plan を飛ばす宣言は、計画は書かせたいが読まずに通してよいカードのため、夜間に `/loop` を回して人が止まる場所を減らすために入れたものだった。
ところが今の読み方では、plan を飛ばすカードは着手した瞬間に plan ゲートが通過済みになり、計画提案中を飛ばして実装中に入る。
計画を書く手が一度も呼ばれず、計画もブランチも Draft の PR もできないまま `implement` が渡り、`board-worker` はブランチが無いので止まる。
さらに着手時刻が無くても実装中に入るので、人が着手を指示していないカードをループが選ぶ。「`startedAt` は人が着手を指示する合図」という決まりとぶつかっていた。
plan の宣言を書く入口は API にしか無く、使っているカードも無かったので、実害は出ていなかった。

## 決定

**宣言のあるゲートでは、そのゲートの最新の記録が 提出 / 再提出 のとき承認と同じに読む。宣言があってもログを見ずに通過済みとしない。**

- エントリが無ければ `none` のまま。否決 / 保留 / 承認 は宣言の無いゲートと同じく効く
- 読み替えは `gateState` の 1 か所で行う。ステージの規則（`RULES`）には手を入れず、plan の宣言のための `if` も着手時刻の条件も足さない
- 後ろのゲートの古いエントリを外す区切り（`currentEntries`）も同じ読み替えにする
- 読み替えはエントリの種別を書き換えない。判断待ちの区画には `plan 提出` のまま見せる（AI が書いたものを人の承認と表示しない）
- **AI の `ai-board card submit` の plan ゲートは、`startedAt` が `null` のカードでは拒む。** 宣言の有無で分けず全カードに効かせる
- plan の 提出 / 再提出 は、plan ゲートが `none` か `rejected` のときだけに絞る（動作確認の後に人が決めた）
- 宣言のあるゲートでも判断のボタンから承認 / 否決を隠さない
- 宣言を書く入口は画面と `board-decide` に足し、CLI には足さない
- 区間の並びも同じ読み替えにし、着手は宣言によらず `planning` を始める

## 検討した代案

- **実装中のルールに着手時刻の条件を足す** — 下限がずれ、Draft の PR があっても着手を戻せてしまう
- **plan の宣言を着手済みのカードに限る** — 事前に宣言できず、着手から宣言までのあいだにループが計画を書き始めうる
- **未着手のカードでは plan の宣言を無いものとする** — 着手の問題は直るが、計画が書かれない問題が残る
- **plan の宣言を無くす** — 夜間に走り抜ける用途が無くなる
- **plan の 提出 / 再提出 をいつでも書けるままにする** — plan を飛ばすカードの 再提出 は承認と同じ区切りになるので、`plan 提出 → verify 提出 → verify 否決 → plan 再提出` で人の `verify 否決` を AI の 1 回の呼び出しで消せる。AI レビューで見つかり、人が絞ると決めた
- **中止したカードを AI の `plan 再提出` で再開できるようにする** — AI の書き込みで人の中止を打ち消せないほうがよいので、絞り込みの結果をそのままにした（2 回目の動作確認の後に人が決めた）

## 結果

- plan を飛ばすカードも、着手するまではアイデアに留まり、着手で計画提案中に入って計画を書く。提出した時点で計画レビューを通らずに実装中へ進む
- 着手を戻せる範囲がふつうのカードと揃った（提出の前は戻せて、後は戻せない）
- 宣言は人の承認を前もって預けるものになった。人は後から否決・保留・承認・中止を書いて止められる
- 提出済みのカードに宣言を入れると、その場で通る。`board-decide` では、待っている提出がそのまま承認と読まれるときだけ確かめる
- 実装中のカードから宣言を外すと、承認のエントリが無いので計画レビューに戻る
- 宣言は今の値で過去を読むので、後から出し入れすると過去の区間の種類も変わる
- verify を飛ばすカードで否決を直した後の `verify 再提出` は承認と読まれ、次の手は `ready` になる。締めの段を通らないので、再提出で足した見送りの指摘は消えない
- plan を飛ばすカードの計画を、提出の後に人へ知らせるしくみは無い（Non-Goals）
- 「提出 / 再提出 を承認と読む」規則が `review-log.ts` の 2 か所と `stage-timeline.ts` にある（AI レビューで見送った）
