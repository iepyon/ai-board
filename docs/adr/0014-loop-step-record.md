# 14. 1 手の記録は本筋のセッションが手の始まりと終わりに書き、時間とトークンは `loop finish` が埋める

- 状態: 採用
- 日付: 2026-11-03（同日に改訂。2026-11-05 にトークンと手順書の版を改訂）

## 背景

監視役がサブエージェントに手を渡していた間は、手の終わりに報告と完了の通知（`usage` にトークンと時間が載る）が別々に届いた。
完了の通知を待って手番を終えると人が聞き直すまでループが止まり、届く順番と記録の取り違えを防ぐ照合の決まりが要った。
ループを本筋のセッションが同期で進める形（[0011](0011-loop-single-session.md)）にしたことで、この順番の問題は無くなった。

## 決定

- **記録の単位は 1 手のまま。** 本筋のセッションが手の始まりに `ai-board loop start`、終わりに `finish` を書く。データ用ブランチの形の版は変えない。
- **時間は CLI が埋める。** `finish` で `--duration-ms` が無ければ、記録の開始から終了までのミリ秒で `durationMs` を埋める（0 未満は 0）。渡されたときはその値を使う。
- **トークンも CLI が数える。** `finish` で `--tokens` が無ければ、`--loop` をセッション ID として Claude Code の会話の記録（本体とサブエージェントの JSONL）を探し、
  記録の開始から終了までの assistant のメッセージ（同じ id は 1 回）の入力・キャッシュの書き込み・キャッシュの読み出し・出力を足して埋める。数えられなければ null。
  レビューの段でも `board-reviewer` の結果の数は写さない（本筋の手と物差しが違い、手順書の版の間で比べられないため）。
- **手順書の版を残す。** `start` が `--root` の `.claude/HARNESS_VERSIONS.md` の先頭の `## v<番号>` を `harness` に残す。項目の無い古い記録と、読めなかった記録は null（版なし）。
  スキーマは知らない項目を落として読むので、形の版は上げない（上げると古い CLI がカードを読めなくなる）。
- `--agent` は `board-reviewer` を立てた手だけに渡す。本筋のセッションが進めた手は null（「—」）。
- `loop start` / `finish` が失敗しても手は止めない。終わっていない記録は、同じループの次の `start` が「途切れた」で閉じる。

## 結果

- どの手にも時間が入り、手ごとの重さは時間で比べられる。
- `durationMs` の意味が「サブエージェントが動いていた時間」から「手の始まりから終わりまで」に変わる（記録を書く時間も含む）。
- 本筋のセッションの手にもトークンが入り、ダッシュボードの「振り返り」で手順書の版ごとに時間・トークン・止まった割合を比べられる（カード `harness-metrics`）。
- トークンはキャッシュの読み出しを含むので 1 手で数十万〜数百万になり、会話が長いほど増える。`board-reviewer` の結果に載る数とは意味が違う。
- 会話の記録の形は Claude Code の内部のもので、変われば黙って「—」に戻る。記録は見るためのものなので、ループは止めない。
- 報告と完了の通知の照合、`ListAgents` の確かめは要らなくなる。

## 退けた案

- **本筋のセッションが時間を測って `--duration-ms` に渡す** — 開始の時刻を持つのは記録だけで、`date` の差を計算させると書き方がずれるか省かれる。
- **後から届いた値で、閉じた記録を書き足す入口を作る** — 「終わった記録を書き換えない」仕様を崩す。記録は見るためのもの（[0008](0008-derive-timeline.md)）なので、止まらないことを優先した。
- **`board-reviewer` の結果のトークンを写し続ける** — 本筋のセッションの手では取れず、取れた分も物差しが違う。
- **`.claude/` のコミットを手順書の版にする** — 手順書へのコミットが多く（11/2 からの記録 76 件に対して 53 回）、1 版 1〜2 件になって比べられない。人が付ける版番号にした。
