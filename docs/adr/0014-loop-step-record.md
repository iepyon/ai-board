# 14. ループの 1 手は、本筋のセッションが手の始まりと終わりにデータ用ブランチの `loop/` へ記録する

- 状態: 採用
- 日付: 2026-11-03（2026-11-07 に 0008 の記録の判断をまとめ、時間・トークン・手順書の版を外した）

## 背景

ループに任せきりにしても、どのカードを触っているか・止まっていないかを人がボードから見たかった。
AI の列にいるカードが、ループに拾われるのを待っているのか作業中なのかは、カードと PR の痕跡からは分からない。
ループを本筋のセッションが同期で進める形（[0011](0011-loop-single-session.md)）にしたことで、手の始まりと終わりを本筋が自分で書けるようになった。

## 決定

- **本筋のセッションが手の始まりに `ai-board loop start`、終わりに `finish` を書く。** データ用ブランチの `loop/` に 1 手 1 ファイルの JSON で置き、終わった記録は書き換えない。
- **記録はカードの属性ではない。** カードの中（`cards/<id>/`）に置かず、ステージ・止まり・次の一手は記録を読まない。`loop-cli.ts` はカードを書けない。
- **データ用ブランチの形の版は上げない。** スキーマは知らない項目を落として読むので、項目を足し引きしても古い記録はそのまま読める。
- `--agent` は `board-reviewer` を立てた手だけに渡す。本筋のセッションが進めた手は null。
- `loop start` / `finish` が失敗しても手は止めない。終わっていない記録は、同じループの次の `start` が「途切れた」で閉じる。

## 結果

- `status` にループが今触っているカードと経過時間が出て、同じ手で止まり続けるカードに印が付く。
- データ用ブランチのコミットが 1 手ごとに 2 つ増え、記録は増える一方。セッションごと落ちると終わらない記録が残る。
- 以前は時間・トークン・手順書の版（`durationMs` / `tokens` / `harness`）も埋めていたが、集計するダッシュボードを外した（[0017](0017-remove-web-and-server.md)）後に読み手が無くなり、外した。古い記録に残る値は読むときに捨てる。

## 退けた案

- **記録をカードの中に置く・形の版を上げる** — カードの書き込み境界と混ざる / 古い CLI がカードを読めなくなる。
- **後から届いた値で、閉じた記録を書き足す入口を作る** — 「終わった記録を書き換えない」を崩す。記録は見るためのものなので、止まらないことを優先した。
