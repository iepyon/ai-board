# 1. ステージを保存せず、実態から導出する

- 状態: 採用
- 日付: 2026-09-11

## 背景

ステージは最初から純関数で導出していたが、手動上書き `stageOverride` が残っていて、実態と食い違うと乖離バッジを出していた。
人の判断（承認・否決）はどこにも痕跡が無く、「すべて導出する」を貫けなかった。

## 決定

- **ステージという値はどこにも保存しない。** `stage-resolver.ts` の純関数だけが決め、`stageOverride` を消す。
  列を動かしたければ、その列を成立させる実態（`startedAt`・成果物・`## レビュー` のエントリ・PR）を作る。
- ルールは `RULES` 配列の順序で表し、最も進んだステージが勝つ。
- **否決の差し戻しに専用ルールを持たない。** 承認とレビューの行が外れ、手前の AI 列へ自然に落ちる。
- **成果物があれば、提出の記録が無くても計画レビューを立てる。** ログの欠落で人待ちを取りこぼさない保険。

## 結果

- 状態はいつでも実態から再計算でき、乖離を見張る仕組みが要らなくなった。
- 列の増減は `RULES` の行の足し引きで済む。探索の 2 列の削除・動作確認の列（[5](0005-verify-gate.md)）でも差し戻しの `if` は増えていない。
- 「計画ファイルがあれば計画レビュー」「空ファイルを無視する条件を足さない」「不正な ID のファイルは警告して読み飛ばす」が `CLAUDE.md` の不変条件になった。
- 区間（[8](0008-derive-timeline.md)）・止まり（[6](0006-ai-review-entries-and-hold.md)）も同じ流儀で保存せず導出している。

## 退けた案

- **否決からの復帰を成果物のハッシュや mtime で検出する** — カードに導出用のキャッシュを持つことになる。mtime はレビューを書くだけで動く。AI が `再提出` を書く形にした。
