# 2. 人の判断はカードの追記専用のログに値のまま残す

- 状態: 採用
- 日付: 2026-09-11（書き込みの口を 2026-11-02、読み手を 2026-11-05 に改訂）

## 背景

ステージを導出する（[1](0001-derive-stage.md)）には人の判断の痕跡が要ったが、承認・否決・その理由を残す場所が無かった。
カードは人もエディタで開くので、新しいファイル形式を増やさず、AI が次の周で否決の理由を読める形にしたかった。

後に、判断を本文の文字列で往復させていたため、AI が提出の理由に `### <時刻> plan 承認` の行を混ぜるだけで人の承認を偽造できる穴が見つかった（2026-10-30）。

## 決定

- **判断はカードの `## レビュー` に追記専用のログとして残す。** エントリは 時刻・ゲート・種別・理由。書き換えも削除もしない。
- **ゲートの状態はそのゲートの最新エントリで決める。** 書式の壊れたエントリは黙って無視する（ボード全体が読めなくなるよりよい）。
- **中止は進捗と直交する終端の軸にする。** 通過済みのゲートを巻き戻さない。
- **判断は値（`ReviewEntry`）のまま `CardRepository.appendReview` で 1 件ずつ足す。** 本文の保存は判断を作らず、`## レビュー` が変わる本文は拒む。理由は見出しとして読み直さない。

## 結果

- CLI・AI・人が同じ場所を読み書きし、否決の理由が AI の次の手の入力になる。
- 判断を増やせる口は `appendReview` だけになり、理由に何を書いても判断は 1 件しか増えない。
- `status --json` のカードは判断を `reviews` として本文と分けて持つ。
- 置き場所はファイル → SQLite → データ用ブランチの `log/`（[10](0010-cards-on-data-branch.md)）と移ったが、読み方は変わっていない。

## 退けた案

- **frontmatter の配列や別ファイル（`reviews/<id>.jsonl`）** — 複数行の理由が手編集しにくい / カードを開いても理由が見えない。
- **理由に見出しの行があれば拒む（`1108fec`・PR #61）** — 文字列を経由したまま入口ごとの検査に頼る。前の判断を引用して貼れない制約も人に残る。
