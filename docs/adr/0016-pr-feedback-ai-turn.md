# 16. PR中 のカードでも、人の指摘の後はループが Ready のまま応え、AI のコメントはフッターで見分ける

- 状態: 採用
- 日付: 2026-11-04（2026-11-05 に改訂）

## 背景

PR中 のカードはすべて判断待ちの区画に並び、人が PR に指摘を書いた後も人を待っているように見えた。
ループのハードルールが PR中 のカードに触ることを禁じていたので、小さな指摘でも人が PR を Draft に戻して「計画から立て直させる」を押すしかなかった。
PR もコメントも人のアカウントで書かれるため、GitHub の Request changes は自分の PR に付けられず、ユーザーでも人と AI のコメントを見分けられない。

## 決定

- **ステージは変えない。** 人の最新のコメントが最新コミットとも AI の最新のコメントとも後にある PR中 のカードを「指摘に応える番」（`awaitsPrFix`）とし、区画と次の一手だけがこれを読む。`stage-resolver.ts` と `SECTION_OF_STAGE` は触らない。
- **AI のコメントは、本文末尾の Claude Code のフッターで見分ける。** フッター付きのコメントは指摘に数えず、最新時刻だけを持つ。`ai-board pr comment` はフッターが無ければ足す。
- **ループは `fix-pr` の手で、PR を Ready のまま修正を push する。** 直すものが無いときだけ、理由を 1 件返信する。どちらでも時刻が逆転して人の番に戻る。
- **指摘に応える番のカードは、AI の区画の先頭に出し、ループも最優先で選ぶ。** マージに最も近いため。
- 質問や承認のコメントも指摘として扱う。判定を細かくせず、直すものが無ければ AI の返信で戻す。

## 結果

- 判断待ちの区画には、本当に人が見るべき PR だけが残る。小さな指摘は Draft に戻さずに往復できる。
- ループのハードルールは「PR中 のカードに触らない」から「`fix-pr` の手でだけ、push と返信 1 件をする」に緩んだ。Ready / Draft の切り替えとマージは人のまま。
- `fix-pr` の手が push の前に `止まった` で終わると、最優先なのでループ全体がそのカードで止まる（人がワークツリーを直すまで止まるのを正しいとした）。push の後に CI で止まると、カードは「再レビュー待ち」で人の番に戻るので、ループは CI の結果を人に伝える。
- 人が「LGTM」と書いても AI の番になり、返信の 1 往復が無駄になる。フッターを付けない道（`gh` で直接）でコメントすると、AI の返信が指摘と読まれる。

## 退けた案

- **GitHub の review の state（`CHANGES_REQUESTED`）で判定する** — 自分の PR には Request changes を付けられない。
- **区画を移すだけにし、直すのは今の Draft に戻す道に任せる** — 区画が AI を示しても誰も動かない。
- **指摘ごとに返信する** — 人が選ばなかった。返信は直すものが無いときの 1 件だけにした。
