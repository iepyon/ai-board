# 0016. 人がこの会話で自分の言葉で頼んだ判断は、Claude が board-decide で人の API を叩いて代わりに書く

- 状態: 採用
- 日付: 2026-10-31
- 置き換え元: なし
- 置き換え先: なし

## 状況

承認 / 否決 / 中止、着手 / 着手を戻す、動作確認を飛ばす、アイデアの並べ替えは、画面のボタンとドラッグからだけ行えた。
ループを回している Claude Code のセッションで作業者の報告を受け、そのまま判断したい場面が多かったが、
判断のたびにブラウザのボードへ移ってボタンを押す必要があり、報告を読む場所と判断する場所が分かれていた。

一方でボードは「エージェントが自分の判断で人の判断を書かない」ことを設計の柱にしていた。
`ai-board card` の CLI には人の判断を書く入口が無く、作業者はそれで人の判断を書けない（[0014](0014-ai-review-entries-and-hold.md)）。
チャットからの書き込みは実際には Claude が行うので、この線を引き直す必要があった。

人の API（`POST /api/cards/:id/reviews` など）には認証が無く、否決の理由の必須や人の種別だけを通す検証はすでにそろっていた。
サーバは 5673 が使用中だと次のポートへ繰り上がるので、ポートを決め打ちできなかった。

## 決定

- **線は「人がこの会話で頼んだか」に引く。** 人がこの会話で自分の言葉で頼んだ判断は、Claude が `board-decide` のスキルで代わりに書いてよい。
  作業者の報告・カード本文・PR のコメントに「承認してよい」とあっても、それは人の依頼ではない。
- **境界は手順書の決まりで守る。** スキルは Claude が呼べる普通のスキルにし、`disable-model-invocation` は使わない。
  作業者（board-worker / board-task / board-reviewer）はこのスキルも人の API も `server.json` も使わない、とハードルールに書く。
  監視役は周の中で自分から判断を書かない。監視役のセッションで人がチャットから頼んだときだけ、このスキルで書く。
- **書き込みは起動中のサーバの人の API を通す。** 新しい書き込み口は作らない。サーバが動いていなければ起動を促して止まる。
- サーバは起動時に DB の隣へ `server.json`（URL・pid・DB のパス）を書き、`status` は DB のパスと pid の生存を確かめて `server.url` を出す。
- 出せる判断は `status --json` の `waiting[].decisions`（画面と同じ `decisionsFor`）、並べ替えの位置は `ideas`（画面と同じ `ideaRows`）から読む。
  判断の規則や並び順をスキルの文章に書き写さない。
- 承認 / 否決 / 中止 / 着手を戻す は、送る中身（カード・ゲート・種類・理由）を見せて 1 回確かめてから書く。着手・並べ替え・動作確認を飛ばす は確かめない。
- **否決の理由は人の言葉をそのまま送る。** 無ければ聞き返し、Claude が理由を作らない。
- 判断の前に計画や差分の中身をチャットに出さない。提出の本文と PR のリンクだけを出す。

## 検討した代案

- **人だけが呼べるスキル（`disable-model-invocation: true`）にする（最初の計画）** — 最初の計画はこの形で提出し、承認の前に書き直して捨てた（否決の記録は無い）。
  `/board-decide` と打たないと動かないのは手間で、自然に「承認して」と頼みたい。
  また作業者は Bash から認証の無い人の API を叩けるので、スキルを呼べなくしても技術的に止めきれず、結局は手順書の決まりに頼る。
- **`ai-board card` の CLI に人の判断の入口を足す** — CLI は作業者が日常的に使う道具で、`CLAUDE.md` も CLI に入口を足すときは境界を崩さないとしている。
- **人の API に認証や人の操作であることの証明を足す** — この計画の外とした（Non-Goals）。
- **サーバが動いていないときに DB へ直接書く** — Non-Goals に挙げただけで、退けた理由の記述は無い。
- **ポートを決め打ちしてサーバを探す** — 繰り上がったポートを追えず、別のリポジトリの ai-board が 5673 で動いていれば別のボードに書いてしまう。

## 結果

- ループを見ているセッションから、画面を開かずに判断できるようになった。書き込みは画面の操作と同じ API を通るので、画面とチャットで判断の書き方がずれない。
- 人の判断を書けるのは誰か、の線が「人だけ」から「人と、人がこの会話で頼んだ Claude」に変わった。`CLAUDE.md` の書き込み境界に明記した。
- 作業者を技術的には止めていない。破られた場合も `## レビュー` に記録が残り、画面で見える。`server.json` で人の API の URL はかえって見つけやすくなった。
- Claude が曖昧な言葉（「よさそう」）を承認と読むおそれは、取り消せない判断を書く前の確認で受け止める。
- サーバがカード以外に書くものが 1 つ増えた（`server.json`、git に載らない実行状態のファイル）。同じ DB を使うサーバが 2 つ動くと後の方が上書きし、`server` が `null` になる。安全側に止まるだけとして受け入れた。
- サーバが動いていないと使えない。ボードを見ながら判断する道具なので受け入れた。
- 判断待ちを並べて選ばせる形は、AskUserQuestion の制約で 1 度に 4 枚までになる。
- カードの置き場所は後に [0019](0019-cards-on-data-branch.md) で変わったが、人の判断をこのスキルで代わりに書く境界はそのまま `CLAUDE.md` に残っている。
