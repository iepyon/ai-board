# 5. PR を見る前に、人が実装を動かして確かめる列（verify ゲート）を置く

- 状態: 採用
- 日付: 2026-10-30

## 背景

人の確かめは計画を読む（計画レビュー）とコードを読む（PR中）の 2 つで、実装を動かす場面はボードの流れに無かった。
差分を読み終えてから動かして意図との違いに気づき、直した後にもう一度差分を読む二度手間が起きていた。

## 決定

- 実装中 と PR中 の間に人の列「動作確認」を置く。ゲートに `verify`、ステージに `verifying` を足す。
- **導出の規則は「plan 承認済み かつ verify 提出済み → 動作確認」の 1 本だけ。** 否決・承認は手前の 実装中 に自然に落ちる。
- AI は AI レビューまで済ませてから、PR を Draft のまま `verify` に提出する。本文に人が動かす手順と自分で動かした結果を書く。
- 次の一手に、否決を直して頼み直す `revise-impl` と、承認の後に Ready にする `ready` を足す。
- verify の承認 / 否決も人だけが書く。飛ばす入口は画面（と `board-decide`）だけで、**CLI には足さない**。

## 結果

- 動作確認では振る舞いを、PR中 ではコードと設計を見る、と役割が分かれた。
- すべてのカードで人を 1 回余計に待つ。小さな変更は「動作確認を飛ばす」で和らげる（読み方は [9](0009-skip-gates.md)）。
- 画面の見た目などは AI が動かせないことがあり、推測で「確かめた」と書かせない。

## 退けた案

- **列を足さず「Ready の前に承認が要る」決まりだけ足す** — 人の番が判断待ちに出ない。
- **`revise-impl` を `implement` に混ぜる** — 「この否決への直しは済んだか」の印が要る。
