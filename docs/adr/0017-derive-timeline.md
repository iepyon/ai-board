# 0017. カードが各工程にいた時間を保存せず、残った痕跡から区間として導出する

- 状態: 採用
- 日付: 2026-10-31
- 置き換え元: なし
- 置き換え先: なし

## 状況

AI 駆動開発のどこがボトルネックか（人の判断待ちか、AI の作業か、差し戻しか）を、ボードから見られるようにしたかった。
研修では受講者がこのリポジトリを fork してループを回すので、回した結果を時間で振り返れることが学びの中心になる。

ボードはカードが「今どの列にいるか」しか出さず、各列にどれだけいたかは、本文の `## レビュー` の時刻を人が目で拾って引き算するしかなかった。
PR を Ready にした時刻はどこにも引いていないので、「Ready にする」と「PR レビュー」の境目も分からなかった。
計測が後回しになると、それまでに回した周のデータが残らない。
一方で、区間の境目になる時刻はほとんどがすでにカードと PR に残っていた（起票・着手・`## レビュー` の各エントリ・PR のマージ・Draft へ戻した時刻）。

ステージは保存せず実態から導出すると決めていた（[0002](0002-derive-stage.md)）。
着手を戻すと `startedAt` は消え、打ち直すと新しい時刻になるので、前の着手は残らない。
着手のボタンを押さずに人がチャットで計画を書かせたカード（`chat-decide`）は、`startedAt` が `null` のままエントリを持っていた。

## 決定

**区間の並び（`timeline`）は保存しない。ステージと同じく、毎回痕跡から純関数で導出する。導出は今の時刻を受け取らない。**

- 区間は種類・担当（人 / AI）・始まり・終わりを持ち、時刻の順に並べる。差し戻しで同じ種類が何度も現れるので、種類をキーにした表にしない
- 区間の種類はカードの表の 9 つに、保留の 2 つと Draft に戻された後を足した 12 種類にする。保留と Draft に戻された後は人を待っているので人の区間にする
- 区間の終わりは次の区間の始まりとする。マージと中止は今の区間を閉じるだけで、次の区間を始めない
- 今いる区間は `end: null` にする。長さを出す側が `generatedAt` までを数える。同じ痕跡からいつでも同じ並びが返る
- **`## レビュー` は `currentEntries` を通さず全部のエントリを読む。** 今効いている判断を選ぶために捨てる古いエントリこそが区間の境目になる
- 遷移は (ゲート, 種別) をキーにした表で引き、`if` を重ねない
- 足りない時刻は PR を Ready にした時刻だけで、`ready_for_review` のイベントの最後のものを `MrState.readyAt` として引く。作成時から Ready の PR はイベントを残さないので、PR の作成時刻で補う
- 時間は実時間で数える。夜や休日も数える
- `startedAt` が無い、または最初のエントリより後にあるカードは、`startedAt` を無いものとして扱う。前の着手を復元しない
- 計画の archive の時刻は、ワークツリーのファイルからは信用できないので痕跡に使わない

## 検討した代案

- **着手が分からないことを表す区間の種類を足す** — グラフの側で扱いが 1 つ増えるわりに得るものが少ないので採らなかった
- **Draft と Ready の行き来をすべて区間にする** — 引くのは最後の Ready と、今 Draft のときの最後に Draft へ戻した時刻だけにした（Non-Goals）
- **営業時間だけを数える** — 人がいないとループは止まることを数字に出すため、実時間で数える
- **作成時から Ready の PR で、補った `readyAt` が最初の `## レビュー` のエントリより前なら区間を始めない（案 B）** — 動作確認の承認で人が今のまま（案 A）と決めた。影響を受けるカードが 0 枚で、ループは必ず Draft で PR を出すため。手で Ready の PR を作る使い方が増えたら案 B に直す
- **補った `readyAt` を最後のエントリより前なら使わない** — verify 承認より前に人が Ready にしたカードまで区間が消えるので採らなかった

## 結果

- `GET /api/board` と `ai-board status --json` の各カードに区間の並びが載り、`MrState` に `readyAt` が増えた。画面には出していない
- **区間を保存しない**ことが、ステージと並ぶ不変条件になった。区間を足すには痕跡を足す
- GitHub への問い合わせが増えた。Ready の PR とマージ済みの PR にもイベントの一覧を引くので、`CLAUDE.md` の「Ready の PR やマージ済みの PR にイベントの問い合わせを足さない」決まりを覆した。増えるのは PR が変化した回数ぶんである
- 区間の境目は痕跡が書かれた時刻で、作業が始まった時刻ではない。AI の区間はループが拾うまでの待ちを含む
- 着手を戻したカードは、1 度目の着手から戻すまでの `planning` が `idea` に数えられる。`startedAt` が `null` のカードでは、`idea` が計画を書いた時間まで含む
- 中止で閉じた後は、`## レビュー` のエントリが来るまで PR の痕跡では区間を開かない（AI レビューの指摘で直した）
- 飛ばす宣言のあるゲートの読み方は [0018](0018-skip-gate-reads-submit-as-approval.md) で変わり、着手は常に `planning` を始めるようになった
- AI の区間を待ちと作業に分けることは別の判断にした（[0024](0024-loop-activity-log.md)）。区間の導出そのものは 1 手の記録を読まない
