# 0002. ステージを保存せず、計画・PR・カードの実態から導出する

- 状態: 採用
- 日付: 2026-09-11
- 置き換え元: なし
- 置き換え先: なし

## 状況

最初のコミット `0e3dd81` から、ステージは `openspec/`・GitLab の MR・カードファイルのフラグ
（`explored` / `implStartedAt`）から純関数 `stage-resolver` で導出していた。
ルールは `RULES` 配列の順序で表し、上から評価して最初に真になったもの（＝最も進んだステージ）を採る。
ただしカードには手動上書き `stageOverride` があり、値があれば導出より優先して列に出し、
食い違えば乖離バッジを出していた。API は値の指定を 400 で拒み、書けるのはファイルの手編集だけだった。

board-lanes の計画は、7 列が「工程がどこまで進んだか」と「いま誰の番か」を 1 本の軸に畳んでいること、
人の判断（承認・否決・理由）がどこにも残らないことを問題にした。
人の判断はファイルシステムにも GitLab にも痕跡を残さないので、「すべて導出する」を貫くには痕跡を作る場所が要った。
カードは人がエディタで直接編集してよいファイルで、手書きの揺れで読めなくなる設計にはできなかった。

## 決定

- **ステージという値はどこにも保存しない。** `stage-resolver.ts` の純関数が唯一の決定点で、
  同じ実態からは常に同じステージを返す。`stageOverride` を削除し、ステージを直接指定する入力口を作らない。
  列を動かしたければ、その列を成立させる実態（`startedAt` の打刻・成果物の作成・レビューログへの追記）を作る。
- **ルールは `RULES` 配列の順序で表し、制御構造にしない。** 最も進んだステージが勝つ。
- **否決の差し戻しに専用ルールを持たない。** ゲートが否決のとき、その工程のレビュー行と承認行が両方外れ、
  1 つ手前の AI 列へ自然に落ちる。
- **成果物の存在を正とし、ログの欠落で人待ちを取りこぼさない。** 成果物（当時は `proposal.md`）があれば、
  plan の提出記録が無くても計画レビューに着地させる。
- 人の判断はカード本文のレビューログに痕跡として残し、導出の入力にする（[0003](0003-review-log-in-body.md)）。

## 検討した代案

- **`stageOverride` を残す** — 人の判断がすべて実態として記録されるようになり、実態と食い違う値を置く動機が消える。
  API はすでに値の指定を拒んでおり、削除しても互換性は落ちない。
- **否決からの復帰を成果物ごとのハッシュの比較で検出する** — カードに導出用のキャッシュを持つことになり、
  「実態から導出する」原則を崩す。AI が `再提出` を追記する方式を採った。
- **否決からの復帰をファイルの mtime で検出する** — レビュー記録を書く行為でカードの mtime が動くため成立しない。

## 結果

- ボードの状態はいつでも実態から再計算でき、食い違いを見張るバッジ（`diverged` / `overridden`）が要らなくなった。
- 人が手で動かせるのは `startedAt` の 1 遷移だけになり、承認 / 否決 / 中止はボタンからの追記になった。
- ステージを増減するときは `RULES` に行を足し引きするだけで済む。探索の 2 列を削ったときも
  差し戻しのための `if` は増えなかった（[0004](0004-drop-explore-lanes.md)）。
- 成果物の存在を正とする規則は、openspec をやめたときに「計画ファイルが存在するだけで計画レビューの列が立つ。
  『空ファイルは無視する』条件を足さない」として CLAUDE.md の不変条件になった（`99cc28a`、[0007](0007-plans-instead-of-openspec.md)）。
  同じとき、ID として不正な名前の計画ファイルは例外にせず警告して読み飛ばす決まりも入った。
- 導出の入力は後に、計画ファイル（[0007](0007-plans-instead-of-openspec.md)）・GitHub の PR だけ（[0008](0008-github-only.md)）・
  Draft の PR（[0011](0011-plan-review-in-draft-pr.md)）・verify ゲート（[0013](0013-verify-gate.md)）へ変わったが、
  保存しない・配列の順序で表す・否決は自然に落ちる、の 3 つは変わっていない。
