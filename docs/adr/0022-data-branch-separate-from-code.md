# 22. カードのデータを、コードの main と履歴が交わらない専用ブランチに置く

- 状態: 採用（[ADR 0021](0021-cards-as-markdown-on-main.md) の「置き場所は main」を置き換える）
- 日付: 2026-11-28

## 背景

ADR 0021 でカードは `main` の `.ai-board/` に置いた。受講チームは fork して始めるが、機能修正の PR とカードの書き込み（CLI の push）が同じ `main` を動かすので、
上流のコードを取り込むときにカードの履歴と混ざり、機能修正とデータの管理を分けて扱えなかった。利用者はまだいない。

## 決定

- **置き場所の既定を `origin` の `ai-board-data`（`store.branch`）にする。** `ai-board store init` が親の無い履歴で作り、push する。コードの `main` とは履歴が交わらない。
- **マージ済みの計画（`cards/<id>/plan.md`）は、コードの `store.planBranch`（既定 `main`）から読む。** 計画はカードのブランチに載せ、PR のマージで `main` に入る。この「`main` にあればマージ済み」を保つため、置き場所とは別に読む。
  置き場所が `store.planBranch` と同じリモート・同じブランチ（`store.branch: main` と書いた同居の形）なら、これまでどおり置き場所の先頭から読む。
- **`store check-branch` は、置き場所のファイルの変更を、カードのブランチと `store.planBranch` の差分で見る。** カードのブランチはコードの `main` から切るので、専用ブランチとは共通の祖先が無い。
- 読み取りは専用の参照 `refs/ai-board/plan-main` へ fetch する（`refs/ai-board/store` と同じく、作業ツリーとほかの fetch に触らない）。取れなければ警告して計画を読み飛ばす（ボード全体を止めない）。

## 退けた案

- **データを別のリポジトリにする（テンプレート）**: 権限や公開範囲を分けられるが、CLI が 2 つのリポジトリを扱い、受講の準備が増える。専用ブランチで足りるので見送った。必要になったら `store.remote` で指せる。
- **計画もデータのブランチへ移す**: PR のマージでステージを導出する仕組みを作り直すことになる。

## 結果

- フォークは 1 回で済み、コードの `main` はカードの書き込みで動かない。
- ステージの導出が 1 回余分に fetch する（コードの `main`）。
- 既存の `main` 同居のボードは、`store.branch: main` と書けばそのまま動く。
