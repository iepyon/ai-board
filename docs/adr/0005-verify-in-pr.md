# 5. 動作確認を独立した列に置かず、AI の証拠を PR の本文に書いて PR中 で確かめる

- 状態: 採用
- 日付: 2026-10-30（2026-11-04 に改訂）

## 背景

人の確かめは計画を読む（計画レビュー）とコードを読む（PR中）の 2 つで、差分を読み終えてから動かして意図との違いに気づき、
直した後にもう一度差分を読む二度手間が起きていた。2026-10-30 に 実装中 と PR中 の間に「動作確認」の列（verify ゲート）を置いたが、
すべてのカードで人を 2 回待つことになり、それを和らげる「動作確認を飛ばす」宣言・verify の保留・`revise-impl` / `ready` の手が増えた。

## 決定

- **列は 6 つで、人を待つのは 計画レビュー と PR中 の 2 か所。** 動作確認の列（`verifying`）と verify ゲートは置かない。
- AI は実装と AI レビューを終えたら、動かせるところを動かし、**CI が通るのを確かめてから**（赤なら締めの段で直す。2 回まで。直せない・終わらないなら止まる）、計画を archive して Ready にする。
- 証拠は PR の本文の `## 動作確認の結果` に、「確かめたこと / コマンド / 結果（`通った` / `落ちた` / `走らせていない`）」の表で書く。品質ゲートと CI の行を入れ、バグの直しはテストが直す前に落ちたことも書く。
- PR の本文の節は「動作確認の結果 → 判断してほしいこと → 見送った AI レビューの指摘」の順に置き、人が「動かす → 差分を読む」の順で読めるようにする。列では分けない。
- 推測で「通った」と書かせない。走らせていないものは `走らせていない` 行に、理由と何が要るかを付けて書く。
- **廃止した verify の記録は消さず、読むときに規定外のゲートとして黙って無視する**（`explore` と同じ）。`skipGates` に残る `verify` は読むときに落とす。

## 結果

- 実装中のカードの次の一手は常に `implement` になり、手順書とステージの導出から verify の分岐が消えた。
- 「まず動かす」は PR の本文の並びで示すだけで、人の心がけに委ねる。その代わり、CI が赤のまま人の番になることは無く、証拠は表で走らせたものと走らせていないものを分ける。
- 締めの段は CI を待つぶん長くなり、CI を通すための直しは AI レビューを経ずに入る（表とコミットに残る）。
- PR中 で計画から作り直させるときは、PR を Draft に戻して「計画から立て直させる」。小さな指摘には AI が Ready のまま応える（[16](0016-pr-feedback-ai-turn.md)）。

## 退けた案

- **列を足さず「Ready の前に承認が要る」決まりだけ足す**（2026-10-30） — 人の番が判断待ちに出ない。
- **動作確認の列を残し、小さなカードは「動作確認を飛ばす」で和らげる**（2026-10-30〜11-03） — 宣言の読み方と止まりの扱いが増え、手順書と導出が重くなった。
- **過去の記録を活かすために verify のエントリを読む経路を持つ** — 消したゲートの解釈がコードに残り続ける。
