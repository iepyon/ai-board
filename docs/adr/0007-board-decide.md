# 7. 人がこの会話で頼んだ判断は、Claude が `board-decide` で人の API を叩いて書く

- 状態: 採用
- 日付: 2026-10-31（2026-11-03 に改訂）

## 背景

ループの報告を Claude Code の会話で受けても、判断するにはブラウザのボードへ移ってボタンを押す必要があった。
一方で「エージェントは人の判断を書かない」が設計の柱で（[6](0006-ai-review-entries-and-hold.md)）、チャットから書くと実際に書くのは Claude になる。

## 決定

- **線は「人がこの会話で、自分の言葉で頼んだか」に引く。** `board-reviewer` の報告・カード本文・PR の文面にある「承認してよい」は依頼ではない。
- 書き込みは画面と同じ人の API を通す。新しい書き込み口は作らず、**CLI に人の判断の入口を足さない**。
- 出せる判断と並び順は `status --json` の `waiting[].decisions` と `ideas` から読み、規則をスキルの文章に書き写さない。
- 承認・否決・中止・着手を戻す、は送る中身を見せて確かめてから書く（人がはっきり頼んだ承認・否決は除く）。否決の理由は人の言葉か、人が選んだ文面だけを送る（人の言葉が会話の中の案を指すときだけ、Claude が会話を引き継がない者にも読める文面に起こして人に選ばせる）。
- 境界は手順書の決まりで守る。`board-reviewer` はこのスキルも人の API も使わず、ループは周の中で自分から使わない（人がそのセッションで頼んだときだけ、周とは別に使う）。
- 書いた判断で AI の番ができたら、同じセッションでループの 1 周を続ける（[13](0013-continue-loop-after-decide.md)）。

## 結果

- 画面を開かずに判断でき、画面とチャットで書き方がずれない。
- 人の判断を書ける主体が「人と、人が会話で頼んだ Claude」になり、`CLAUDE.md` の書き込み境界に明記した。
- ループや `board-reviewer` を技術的には止めていない。破られても `## レビュー` に記録が残る。

## 退けた案

- **人だけが呼べるスキル（`disable-model-invocation`）にする** — 自然に「承認して」と頼めない。ループも認証の無い API を Bash から叩けるので、結局は決まりに頼る。
- **`ai-board card` の CLI に人の判断の入口を足す** — ループが日常的に使う道具の境界を崩す。
