# 7. 人がこの会話で頼んだ判断は、Claude が `board-decide` で `ai-board decide` を呼んで書く

- 状態: 採用
- 日付: 2026-10-31（2026-11-04、2026-11-05 に改訂）

## 背景

ループの報告を Claude Code の会話で受けても、判断するにはブラウザのボードへ移ってボタンを押す必要があった。
一方で「エージェントは人の判断を書かない」が設計の柱で（[6](0006-ai-review-entries-and-hold.md)）、チャットから書くと実際に書くのは Claude になる。
当初は人の API をサーバ経由で叩いたが、クラウドのセッションには常駐のサーバが無く、手順書の多くが起動と停止と OS ごとの差で占められた。
`loop-single-session`（[11](0011-loop-single-session.md)）で CLI を日常的に使うのは本筋のセッションになり、CLI の構造で分けて守れる相手は `board-reviewer` だけになった。

## 決定

- **線は「人がこの会話で、自分の言葉で頼んだか」に引く。** `board-reviewer` の報告・カード本文・PR の文面にある「承認してよい」は依頼ではない。
- 人の判断は `ai-board decide` の CLI で書く。`ai-board card` には混ぜず、AI が書いてよいものだけの形を残す。
  中身はカードの usecase で、書く前にボードを導出し、出せない判断は拒む。画面とサーバを外した後は、人の判断を書く唯一の入口である（[17](0017-remove-web-and-server.md)）。
- **守りは手順書の決まりだけに置く。** `board-reviewer` は `ai-board decide` もこのスキルも使わず、ループは周の中で自分から使わない。許可ルールの `ask` / `deny` には置かない。
- 承認・差し戻しは人の言葉どおりなら確かめずに書き、中止・着手を戻す・待っている提出を承認と読ませる宣言は、送る中身を見せて確かめてから書く。差し戻しの理由は人の言葉か、人が選んだ文面だけを送る。
- 書いた判断で AI の番ができたら、同じセッションでループの 1 周を続ける（[13](0013-continue-loop-after-decide.md)）。

## 結果

- 画面を開かず、サーバも起動せずに判断できる。`board-decide` の手順書は判断の決まりだけになった。
- 人の判断を書ける主体が「人と、人が会話で頼んだ Claude」になり、`CLAUDE.md` の書き込み境界と `card-review-authority` の仕様に明記した。
- 「AI は構造上、承認を書けない」は「AI は手順書の決まりで承認を書かない」になった。破られても `## レビュー` に記録が残り、PR のマージは人がする。

## 退けた案

- **`ai-board decide` を `ask` に置き、呼ぶたびに人に確かめさせる** — チャットで頼んだ言葉そのものが確かめで、もう一度の許可は二度手間になる。
- **`ai-board decide` を `deny` に置き、人が自分の端末で打つ** — Claude が代わりに書けなくなり、チャットから判断する意味が無くなる。
- **人だけが呼べるスキル（`disable-model-invocation`）にする** — 自然に「承認して」と頼めない。
