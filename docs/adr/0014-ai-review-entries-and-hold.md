# 0014. AI がレビューログに書けるのは 提出 / 再提出 / 保留 だけにし、人が止めたカードを止まりとして導出してループに押し進めさせない

- 状態: 採用
- 日付: 2026-10-30
- 置き換え元: なし
- 置き換え先: なし

## 状況

AI が `## レビュー` に書けるのは 提出 / 再提出 だけで、承認 / 否決 / 中止 は人が書く決まりだった（CLI に入口が無いことで守っていた）。
`verify-gate`（PR #37）の AI レビューで、設計の判断が要る指摘が 2 件残った。どちらも、ループが人の判断や操作より自分の規則を優先して同じ手を出し続ける形だった。

1 件目は動作確認で否決されたカード。作業者は直すには大きすぎると判断すると、何も変えずに止まって報告する。
しかし止まったことはどこにも残らず、`next-action.ts` は「verify の最新が否決」だけを見て次の周も `revise-impl` を選ぶ。
1 周に 1 手しか進めないので後ろのカードも動かない。実装中 のカードには判断のボタンが出ず、人が計画から立て直させる入口も無かった。

2 件目は動作確認を承認した後のカード。AI が Ready にした PR を人が Draft に戻すと、カードは 実装中 に落ち、ループは `ready` を選ぶ。
作業者は計画が archive 済みなのを見て「前の周で `gh pr ready` だけが失敗した」と読み、すぐに Ready にし直してしまう。
`mrState.draft` では、まだ一度も Ready にしていない PR と、人が Draft に戻した PR を見分けられなかった。

## 決定

- AI が止まったことは、`## レビュー` に AI が書く 3 つ目の種別 **`保留`** として残す。ゲートの状態に `held` を足す。
  CLI に `ai-board card hold <id> --gate <plan|verify> --reason <text>` を足す。
- **AI が書けるのは 提出 / 再提出 / 保留 だけ。承認 / 否決 / 中止 は人だけが書く。** 人の API は 承認 / 否決 / 中止 だけを受け付けるように絞る。
- **保留はそのゲートの最新が否決のときにだけ書ける。** 理由文は必須にする。
- 保留はゲートの最新エントリとして読む。人が後から書けばそれが最新になり、保留は外れる。保留を解く専用のエントリは作らない。
- ステージの規則は変えない。`held` はどの規則でも前へ進まず、カードは AI の列のままになる。
- 「止まっている」はステージとは別の派生値 `BoardCard.hold` にし、**保存しない**。ステージは工程のどこにいるか、`hold` はその工程で誰を待っているかを表す。
  止まりは verify 保留、plan 保留、判断の後に PR が Draft に戻された、提出済みなのに成果物が見えない、のときに立つ。
- Draft に戻したことは GitHub の `convert_to_draft` のイベントの最新時刻で読み、カードの最新のレビューエントリより新しければ止まりとする。
- ループの選択・`status` の `waiting`・画面の判断待ちの区画は、同じ `hold` を読む。止まっているカードは選ばず、後ろのカードへ進む。
- 「後ろのゲートは、前のゲートの最新の承認より前のエントリを数えない」とする。計画を承認し直したら、前の計画に対する動作確認の判断は効かない。
- 止まっているカードと 動作確認 のカードに「計画から立て直させる」（plan 否決）のボタンを出す。

## 検討した代案

- **止まったことを `## 探索メモ` に残す** — 自由記述で、導出の入力にしないと決めている。
- **PR のコメントに残す** — 作業者のコメントは人の `gh` のログインで書かれ、人のコメントと見分けが付かない。「人が書いた最新のコメント」の判定も狂う。
- **`verify 提出` で代える** — カードが 動作確認 へ上がり、承認を押すと何も直っていないまま `ready` に進む。列の意味とも合わない。
- **`mrState.draft` で見分ける** — 動作確認を頼むあいだも PR は Draft なので、人が戻したかどうかが同じ値になる。

## 結果

- 作業者が否決を直しきれずに止まったカードは判断待ちに出て、ループは後ろのカードへ進む。人は理由を読み、実装を直させる / 計画から立て直させる / 中止 を選べる。
- 人が Draft に戻した PR をループが Ready にし直さなくなった。「archive 済みなら `gh pr ready` だけをやり直す」回復の道も、本当に失敗したときにしか通らない。
- AI が書ける種別が 1 つ増えたが、保留はゲートを先へ進めないので、AI が自分の判断で工程を進める入口にはならない。
- 計画には保留を書ける条件の定めが無かった。AI レビューの指摘を受け、承認の打ち消しと人を待つカードの差し戻しを防ぐため、最新が否決のときに限った。
- ゲートが通らない・未コミットの変更が残る、といった作業者の止まり方は `hold` で残さない。ワークツリーを人が直す話で、判断のボタンでは解けない。
- 作業者が保留を書き忘れれば、今までどおり同じ手が選ばれ続ける。
- open かつ Draft の PR ごとに `issues/{n}/events` を 1 回引くので、GitHub への問い合わせが増える。
- 計画を承認し直すと、前の動作確認の判断は数えられず消えて見える。エントリは本文に残る。
