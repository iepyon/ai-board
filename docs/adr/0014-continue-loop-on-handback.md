# 14. ループはサブエージェントの報告で次の周へ進み、完了の通知を待たない

- 状態: 採用
- 日付: 2026-11-03

## 背景

サブエージェントが手を終えると、監視役には報告（hand-back）と完了の通知（`usage` にトークンと時間が載る）の 2 つが届く。
監視役は `loop finish` にトークンと時間を写すため、報告を受けても「完了の通知を待つ」と言って手番を終えていた。
完了の通知は待っているセッションを起こさず人の次のメッセージに添えられて届くので、loop-resume-after-decide の 1 周では 5 つの手のうち 4 つで、人が聞き直すまでループが止まった。

## 決定

- **続ける合図は報告である。** 報告を受けた最初の手番で `finish` を書き、報告を伝えて次の周へ進む。完了の通知を待って手番を終えない。どちらが先に届いても、`finish` は 1 手につき 1 度だけ書く。
- トークンと時間は、その手番にすでに完了の通知が届いていれば写し、無ければ省く（記録には「—」と出る）。
- `finish` の前に `status --json --only loop` で、開いている自分のループの記録の `agent` が報告したサブエージェントと一致するかを確かめる。自分のループの記録が開いていて別の名前なら、何もしない。後から届いた知らせで次の手の記録を閉じないためである。自分のループの記録が無いとき（`loop start` が失敗していた）と `status` が失敗したときは、`finish` を書かずに報告を伝えて次の周へ進む。記録を書けなくてもループを止めないためで、二重に渡すのは手順 0 の `ListAgents` の確かめが防ぐ。
- 報告を受けた手番から続ける周の手順 0 では、報告を返したサブエージェント自身を `running` に数えない。
- 確かめと続け方は手順書で行い、`loop finish` の CLI の振る舞いは変えない。

## 結果

- 手と手の間で人が聞き直さなくても、`止まった` か `next` が null になるまでループが続く。
- トークンと時間はほとんど「—」になる見込みがあり、手ごとの重さを比べる手がかりが薄くなる。
- 記録の取り違えの防ぎは監視役の手順の照合に頼り、CLI では拒めない（`--card` の食い違いしか見ない）。
- 報告が届かなければ今までどおり止まり、次の cron の周か人の頼みで拾う。

## 退けた案

- **後から届いた完了の通知で、閉じた記録に値を書き足す入口を作る** — 「終わった記録を書き換えない」仕様を崩し、人の依頼の手番に記録の書き込みを毎回挟むことになる。記録は見るためのもの（[0008](0008-derive-timeline.md)）なので、止まらないことを優先した。
- **`loop finish` の CLI に `--agent` の照合を足す** — 確かめは手順書で足りるとして、CLI は今の形のままにした。
