# 8. 工程にいた時間は保存せず痕跡から導出し、ループの 1 手だけを記録として残す

- 状態: 採用
- 日付: 2026-10-31（ループの記録を 2026-11-02 に追加）

## 背景

どこがボトルネックか（人の判断待ちか、AI の作業か）をボードから見たかった。研修では回した結果を時間で振り返ることが学びの中心になる。
区間の境目になる時刻（起票・着手・`## レビュー`・PR の Ready とマージ）は、ほとんどがすでにカードと PR に残っていた。
ただし AI の区間が、ループに拾われるのを待っていたのか作業していたのかは痕跡からは分からなかった。

## 決定

- **区間の並び（`timeline`）は保存せず、ステージと同じく痕跡から純関数で導出する。** 導出は今の時刻を受け取らない。
- `## レビュー` は今効いているものに絞らず全エントリを読む。足りない PR の Ready の時刻だけを `readyAt` として GitHub から引く。時間は実時間で数える。
- **監視役は渡した 1 手ごとに開始と終了を、データ用ブランチの `loop/` に 1 件 1 ファイルで残す。** 終わった記録は書き換えない。
- 記録はカードの属性ではない。ステージ・止まり・次の一手は記録を読まない。書くのは `ai-board loop` を使う監視役だけで、形の版は上げない。
- 区間と記録から AI の区間を「待ち」と「作業」に分ける純関数を別に置く。記録を書けなくても監視役は手を渡し続ける。

## 結果

- `GET /api/board` と `status --json` に区間が載り、画面にはループが今触っているカードと経過時間が出る。
- 区間の境目は痕跡を書いた時刻で、作業を始めた時刻ではない。着手を戻すと前の着手は復元しない。
- データ用ブランチのコミットが 1 手ごとに 2 つ増え、記録は増える一方。監視役ごと落ちると終わらない記録が残る。

## 退けた案

- **営業時間だけ数える** — 人がいないとループが止まることを数字に出したい。
- **記録をカードの中（`cards/<id>/`）に置く・形の版を上げる** — カードの書き込み境界と混ざる / 古い CLI がカードを読めなくなる。
