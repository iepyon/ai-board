# 21. カードの置き場所を git の main の Markdown にし、計画をカードのディレクトリに置く

- 状態: 提案
- 日付: 2026-11-22

## 背景

カードの正本は Artifact の DB に置いていた（[20](0020-cards-in-artifact-db.md)）。しかし使う場では claude.ai が使えず、DB に届かない。
使うのは 3 人で、1 つのボードを共有し、各自のローカル PC で動かす。GitHub は使える。ボードはブラウザで見るだけで、判断はチャットで頼む。

## 決定

- **カードは main の `.ai-board/cards/<id>/card.md`（frontmatter と本文）と `log/`（判断 1 件 1 ファイル）、並び順は `.ai-board/order.yaml` に置く。** CLI は専用の参照へ fetch した main を読み、その上にコミットを作って push する。push が拒まれたら取り直してやり直す。メインのチェックアウトの作業ツリーには触らない。
- **仕様つきの計画は `.ai-board/cards/<id>/plan.md` に置き、カードのブランチから PR でマージする。** 紐付けは名前（ディレクトリ名）で行う。カードのブランチでは置き場所のファイルを変えない（push の前に検査で止める）。
- **main（fetch した参照）に `plan.md` があればマージ済みとする。** `archive/` へ移す手順はなくす。
- **仕様は `plan.md` に差分として書き、`docs/specs/` は同じ PR で書き直し続ける。**
- PR の控えとループの記録は各 PC の `.ai-board/local/` に置き、共有しない。ステージは今までどおり導出する。

## 結果

- 写し・送る箱・送り出しが要らず、人のいない `/loop` からも書ける。同期・楽観ロック・判断の履歴を git が兼ねる。
- main に書き込みのコミットが頻繁に入り、main に直接 push できることが前提になる。エディタでの直接の書き換えは、Claude の `Edit` の deny と push の前の検査で補う。
- 「計画ファイルがあるだけで計画レビュー」の保険（[1](0001-derive-stage.md)）は、GitHub が未設定のボードのブランチの計画だけに縮む。
- ほかの PC のループは見えない。ブラウザで見るには、静的な HTML の出口が要る（[19](0019-board-view-artifact.md) を書き直す）。PC を閉じたままスマホから直す使い方は、クラウドのセッションから main に push できる場合に限られる。
- 採用したら [20](0020-cards-in-artifact-db.md) はこの ADR に吸収して消し、[1](0001-derive-stage.md)・[4](0004-plans-in-draft-pr.md) を今の形に書き直す。

## 退けた案

- **Artifact の置き場所を残し、設定で git と選べるようにする** — 一度はこの形にしたが、2 つの実装と手順書の分岐を保守し続けることになる（人の判断）。
- **カードを GitHub Issues に置く** — 改訂が JSON のコメントになって読みにくく、今の形（seed・計画の Markdown）から遠い。
- **SQLite に置く** — 各自の PC に置くと共有できず、1 台に置いて配ると常駐サーバと認証が要る（[17](0017-remove-web-and-server.md) で外したもの）。
- **ローカルの MCP サーバがボードの HTML を返す** — 描画されるのは MCP Apps に対応したチャットの中で、ブラウザのタブではない。3 人の共有の問題も解けない。

根拠: 置き場所の代替案を話したチャットと、計画 `cards-as-markdown` の差し戻し・計画レビュー（2026-11-22）、PR #116
