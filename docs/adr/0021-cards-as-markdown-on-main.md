# 21. カードの置き場所を git の main の Markdown にし、計画をカードのディレクトリに置く

- 状態: 採用
- 日付: 2026-11-22

## 背景

カードの正本は Artifact の DB に置いていた（DB に届かない CLI は手元の写しを読み、Claude が `ArtifactData` で取り込み・送り出しをしていた）。
しかし使う場では claude.ai が使えず、DB に届かない。使うのは 3 人で、1 つのボードを共有し、各自のローカル PC で動かす。GitHub は使える。
ボードはブラウザで見るだけで、判断はチャットで頼む。一度は Artifact と設定で選べるようにしたが、人が外すと決めた。

## 決定

- **カードは置き場所のブランチ（既定は `origin` の `main`）の `.ai-board/cards/<id>/card.md` と `log/`（判断 1 件 1 ファイル）、並び順は `.ai-board/order.yaml`、形の版は `.ai-board/board.yaml` に置く。**
- **CLI は専用の参照（`refs/ai-board/store`）へ fetch して読み、書き込みはその上のコミットとして push する。** push が先を越されたら取り直して検査からやり直す。メインのチェックアウトの作業ツリーには触らない。置き場所は `DocumentStore` の口に閉じる。
- **計画は `.ai-board/cards/<id>/plan.md` に置き、カードのブランチから PR でマージする。** main にあればマージ済み（[4](0004-plans-in-draft-pr.md)）。カードのブランチでは置き場所のファイルを変えない（push の前に `ai-board store check-branch` で止める）。
- **PR の控えとループの記録は各 PC の `.ai-board/local/` に置き、共有しない。** 置き場所のファイルを変えない書き込みは push しない。
- 仕様は計画に差分として書き、`docs/specs/` は同じ PR で書き直し続ける。ステージは今までどおり導出し、形の版は 3 のまま変えない。

## 結果

- 写し・送る箱・送り出し・`board-store` のスキルが要らず、人のいない `/loop` からも書ける。同期・楽観ロック・判断の履歴を git が兼ねる。
- main に書き込みのコミット（`chore(board): …`）が頻繁に入り、main に直接 push できることが前提になる（PR 必須の保護は入れられない）。
- エディタでの直接の書き換えは止められない。Claude には `Edit` の deny、ブランチには `check-branch` で補う。
- 「計画ファイルがあるだけで計画レビュー」の保険（[1](0001-derive-stage.md)）は、GitHub が未設定のボードのブランチの計画だけに縮む。ほかの PC のループは見えない（[14](0014-loop-step-record.md)）。
- ボードのページは HTML のファイルに書き出す（[19](0019-board-view-artifact.md)）。PC を閉じたままスマホから直す使い方は、クラウドのセッションから main に push できる場合に限られる。

## 退けた案

- **Artifact の置き場所を残し、設定で git と選べるようにする** — 2 つの実装と手順書の分岐を保守し続けることになる（人の判断）。
- **カードを GitHub Issues に置く** — 改訂が JSON のコメントになって読みにくく、今の形（seed・計画の Markdown）から遠い。
- **SQLite に置く** — 各自の PC に置くと共有できず、1 台に置いて配ると常駐サーバと認証が要る（[17](0017-remove-web-and-server.md) で外したもの）。
- **メインのチェックアウトで `.ai-board/` だけを commit・pull・push する** — 人の作業ツリーを CLI が書き換え、別のブランチにいると動けない。

根拠: 置き場所の代替案を話したチャット、計画 `cards-as-markdown` の差し戻し・計画レビュー（2026-11-22）、PR #116
