# 21. カードを main の Markdown に置き、計画を同じディレクトリに並べる

- 状態: 提案
- 日付: 2026-11-22

## 背景

カードの正本は Artifact の DB に置いていた（[20](0020-cards-in-artifact-db.md)）。しかし使う場で claude.ai が使えず、DB に届かないと分かった。
使うのは 3 人で、1 つのボードを共有し、各自のローカル PC で動かす。GitHub は使える。スマホや、PC を閉じたままの操作は要らない。ボードはブラウザで見るだけで、判断はこれまでどおりチャットで頼む。

## 決定

- **カードは main の `.ai-board/cards/<id>/card.md`（frontmatter と本文）に置く。** `## レビュー` は本文の中に残す。並び順はカードごとの `rank` に持ち、1 つのファイルに集めない。最初のアイデアカード（`.ai-board/seed/`）もこの形にまとめる。
- **仕様つきの計画は同じディレクトリの `plan.md` に置く。** 紐付けは今までどおり名前（ディレクトリ名）で行い、紐付けのフィールドは持たない。
- **`card.md` は main に直接 push し、`plan.md` はカードのブランチに載せて PR でマージする。** カードのブランチでは `card.md` を変えず、main では `plan.md` を直接作らない。push の前に検査で止める。
- **main に `plan.md` があればマージ済みとする。** `archive/` へ移す手順はなくす。
- **仕様は `plan.md` に差分として書き、`docs/specs/` は同じ PR で書き直し続ける。**
- ステージは今までどおり導出する（[1](0001-derive-stage.md) は変えない）。CLI は書き込みの前に pull し、書いた後に commit と push を行う。push が拒まれたらやり直す。

## 結果

- 写し・送る箱・`board-store` のスキル・`ArtifactData` の hook が要らなくなり、人のいない `/loop` からも書ける。
- 同期・楽観ロック・判断の履歴を git が兼ねる。改訂（`<ID>~<連番>`）の仕組みは要らなくなる。
- main に書き込みのコミットが頻繁に入り、コードの履歴と混ざる。main に直接 push できることが前提になる。
- エディタでファイルを直接書き換えられる。`ai-board card` の境界は、push の前の検査で補う。
- ボードは GitHub の画面では列にならない。Artifact を使わず、ブラウザで開くための静的な HTML の出口（`ai-board view`）が要る（[19](0019-board-view-artifact.md) を書き直す）。採用したら [20](0020-cards-in-artifact-db.md) はこの ADR に吸収して消し、[4](0004-plans-in-draft-pr.md) を今の形に書き直す。

## 退けた案

- **カードを GitHub Issues に置く** — 改訂が JSON のコメントになって読みにくく、今の形（seed・計画の Markdown）から遠い。
- **SQLite に置く** — 各自の PC に置くと共有できず、1 台に置いて配ると常駐サーバと認証が要る（[17](0017-remove-web-and-server.md) で外したもの）。
- **ローカルの MCP サーバがボードの HTML を返す** — 描画されるのは MCP Apps に対応したチャットの中で、ブラウザのタブではない。3 人の共有の問題も解けない。
- **ディレクトリごと `cards/archive/<id>/` へ移してマージ済みを示す** — PR の中の移動と、main での `card.md` の書き換えがぶつかる。

根拠: 置き場所の代替案を話したチャット（2026-11-22）
