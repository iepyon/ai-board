# 0012. ループは status の次の一手を読む監視役と、まっさらな文脈で 1 手だけ進めるサブエージェントに分ける

- 状態: 採用（一部を [0021](0021-flat-subagents.md) が置き換え）
- 日付: 2026-10-23
- 置き換え元: なし
- 置き換え先: [0021](0021-flat-subagents.md)（一部）

## 状況

人が「着手」を押してもカードは 計画提案中 に移るだけで AI は動かず、人がセッションを開くたびにどのカードを進めるかを指示していた。
ボードには優先順（`rank`）と AI が進めてよい列（計画提案中 / 実装中）が揃っているので、次にやることはボードを読めば決まるはずだった。
ただしステージを知る手段はサーバの `GET /api/board` だけで、`ai-board card list` はステージを出さなかった。
これに頼るとループのためにサーバを立て続けることになり、サーバが落ちればループも止まる。

最初の形（`board-loop-skill`、PR #28）では、`/loop` で回す 1 つのセッションが計画も実装も自分で進めた。
回してみると、複数のカードの計画・実装・レビューで読んだコードや決めた事柄が同じ文脈に積み上がり、
前のカードの前提が残ったまま次のカードの計画を書くことになった。文脈が長くなると自動の要約が走り、どこまでが今のカードの情報かも曖昧になった。
`/clear` はスキルからは実行できず、人はこの画面でループの経過を見続けたかった。

## 決定

- **次の一手はコードで決める。** 判定は純関数 `pickNextAction` に置き、`ai-board status --json` の `next` として出す。
  スキルの文章には「何をするか」を書かず、`next` に従うだけにする。`status` はサーバを起動せずにボードと同じ導出を使う。
- `forge.status` が `connected` でなければ `next` を `null` にし、ループは何もせずに止まる（PR の状態が引けないと、計画レビューや PR中 のカードが手前の AI 列へ落ちて見えるため）。
- ループを回すセッションは**監視役**にする。監視役は `status` の `next` / `waiting` / `forge` だけを読み、1 手をサブエージェントに渡し、返ってきた報告を人に伝える。
  **カード本文・計画・差分は読まない。**
- サブエージェントは `.claude/agents/` の定義にし、**渡すのはカード ID・手の種類・`$MAIN` だけ**にする。要約や補足は添えない。
  サブエージェントはカード・計画・PR を自分で読み直す。
- 人が会話で伝える補足はサブエージェントに届かないので、カード本文の `## 探索メモ` に書く。
- `subagent_type: "fork"` は使わない（呼び出し元の会話をすべて引き継ぎ、切り離す意味が無くなる）。
- 周の最初に `ListAgents` を見て作業中のサブエージェントがいればその周は何もしない。監視役の記憶ではなく `ListAgents` で判定する。
- 1 周で渡す手は高々 1 つ。止まったカードを飛ばす周をまたいだ状態は持たない。

## 検討した代案

- **ステージをサーバの `GET /api/board` から読む** — ループのためにサーバを立て続けることになり、サーバが落ちるとループも止まる。
- **何をするかをスキルの文章に書く** — 周回ごとに解釈が揺れ、テストもできない。
- **1 つのセッションがすべての手を自分で進める（最初の形）** — 文脈に前のカードの前提が積み上がる。これを解くために監視役とサブエージェントに分けた。
- **`plan` / `revise-plan` だけをサブエージェントに渡す** — `implement` もコードと差分と `/code-review` の指摘を文脈に積む。手の種類で分岐させない方が監視役の手順も 1 本で済む。
- **監視役が要約を添えて渡す** — 監視役の文脈にある前のカードの前提がそこから漏れる。
- **1 周ごとに新しいセッションを起動する（launchd から `claude -p "/board-loop"`）** — 監視役ごと毎回まっさらになるが、この画面で経過を見られなくなり、確認なしで動かす権限の設定も要る。

## 結果

- サブエージェントは手のたびにまっさらな文脈で始まり、別のカードの前提を持ち込まない。代わりに手のたびに `CLAUDE.md`・カード・計画を読み直す費用がかかる。
- `status` が `ForgePoller.refresh` を使うので、エージェントが叩く CLI から PR 番号の書き戻しが起きる（サーバと同じ経路で、番号を選んで書ける入口ではない）。
- 進められないカード 1 枚で、人が直すまで毎周同じ手が選ばれる。後に [0014](0014-ai-review-entries-and-hold.md) が、否決を直しきれずに止まったカードを止まりとして導出し、飛ばせるようにした。
- 作業者が固まると、毎周「作業中」と報告するだけになる。人は `TaskStop` で止める。
- 完了の通知を受けた手番では次を渡さない、という形は [0015](0015-separate-ai-reviewer.md) で「通知を受けたら続けて次の手を選ぶ」に変わった。
- 渡し先を 1 つの `board-worker` に固定する形は [0021](0021-flat-subagents.md) が置き換えた。監視役は `next.step` を見て渡し先を選ぶ。
  渡すのが 3 項目だけで監視役が計画を読まないことは変わっていない。
