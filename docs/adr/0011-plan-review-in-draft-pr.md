# 0011. 計画は Draft の PR で読み、ボードは PR へのリンクだけを出す

- 状態: 採用
- 日付: 2026-09-27（PR #24 のマージ）
- 置き換え元: なし
- 置き換え先: なし

## 状況

計画は `.ai-board/plans/<id>.md` に置き、ファイルの存在で計画レビューの列が立っていた（[0007](0007-plans-instead-of-openspec.md)）。
人は詳細パネル（後に判断待ちの区画）で計画の本文を読み、承認 / 否決のボタンを押していた。
本文は `GET /api/plans/:id` で開いたときに個別に引いていた。PR は、AI がタスクを倒して AI レビューまで済ませてから出すもので、計画レビューの時点には無かった。

計画ファイルはブランチに乗るので、メインのチェックアウトで動くボードからは見えない。
ワークツリーからメインのデータを共有した後も、計画だけはワークツリー（ブランチ）のものを読む形だった（[0010](0010-share-main-checkout-data.md)）。
そのため `board-seed` では、計画レビューの列をボードに立てるために、計画ファイルだけの PR を先に main へ入れていた（PR #19、#21）。

## 決定

**計画の本文をボードに持たず、計画と実装を同じ 1 本の PR に載せる。** 人は計画を Draft の PR で読み、承認 / 否決はこれまでどおりボードのボタンで行う。

- AI は計画をコミットした時点で push し、Draft の PR を出す。実装も同じブランチで進め、終えたら Ready にする。
- **Draft の PR も計画の成果物として扱い、計画レビューの列を立てる。** PR中 は「PR が opened かつ Draft でない」で立つ。
- 承認済みで Draft のままなら実装中、否決なら計画提案中へ落ちる。ここに専用の分岐は足さない。
- `GET /api/plans/:id` と計画本文の読み出しを廃止し、判断待ちの区画と詳細パネルは計画の PR へのリンクだけを出す。

## 検討した代案

- **計画の本文をボードの詳細パネルで読ませる（`a85b887` で入れていた形）** — 計画ファイルはブランチにあり、ボードを動かすチェックアウトからは見えないことが多い。

これ以外の案の記録は無い。

## 結果

- 計画レビューの列は、ボードを動かすチェックアウトに計画ファイルが無くても、Draft の PR から立つようになった。計画だけの PR を先に main へ入れる手順は要らなくなった。
- ステージ導出の入力に PR の `draft` が加わった。ポーラは `draft` の変化も更新として扱う。
- 「計画ファイルがあれば計画レビューが立つ」保険（[0007](0007-plans-instead-of-openspec.md)）はそのまま残り、Draft の PR はそれに並ぶもう 1 つの成果物になった。
- 1 本の PR が、計画レビュー・実装・PR中 をまたいで同じ番号で続くようになった。
- 後に、実装を終えた AI が PR を Draft のまま動作確認を頼む形が足された（[0013](0013-verify-gate.md)）。
  Draft の PR が立てる計画レビューのルールは plan ゲートが未判断のときにしか当てはまらないので、動作確認を頼む時点の Draft で計画レビューへは巻き戻らない。
- PR の `draft` だけでは「まだ一度も Ready にしていない」と「人が Draft に戻した」を見分けられず、後者を止まりとして導出する仕組みが後で足された（[0014](0014-ai-review-entries-and-hold.md)）。
- 手順書の `gh pr create --draft` / `gh pr ready` は、後に `ai-board pr` に置き換わった（[0019](0019-cards-on-data-branch.md)）。
