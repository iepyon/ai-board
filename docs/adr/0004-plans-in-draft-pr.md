# 4. 計画は `.ai-board/cards/<id>/plan.md` に置き、Draft の PR で読む

- 状態: 採用
- 日付: 2026-09-27（2026-11-05、2026-11-07 に改訂。2026-11-07 に未設定のボードの締めを足す。2026-11-22 に置き場所をカードのディレクトリに移し、archive をやめた）

## 背景

当初は OpenSpec の change を計画にしていた。archive が `openspec/specs/` を書き換える操作で、遅れた sync が後続の変更を黙って巻き戻す危険があり、
OpenSpec の内部の定数にも追従する義務があった。
計画ファイルに移した後も、計画はブランチに乗るので、メインのチェックアウトで動くボードからは本文が見えないことが多かった。
その後、カードを main の `.ai-board/cards/<id>/` に置くことにし（[21](0021-cards-as-markdown-on-main.md)）、計画も同じディレクトリに並べた。

## 決定

- **計画は `.ai-board/cards/<カード ID>/plan.md` の 1 ファイル。ディレクトリ名で紐付き、カードに紐付けのフィールドを持たない。** OpenSpec は使わない。
- タスクはチェックボックスで書き、進捗の表示にだけ使う（ステージの入力にしない）。
- **計画と実装を同じ 1 本の PR に載せ、人は計画を Draft の PR で読む。** 承認 / 差し戻しは `ai-board decide`（チャットからは `board-decide`）で書く。
- **Draft の PR を計画の成果物として計画レビューを立てる。** PR中 は「opened かつ Draft でない」で立つ。**main（置き場所の参照）に計画があればマージ済み**とする。計画はマージでだけ main に入るので、archive へ移す手順は持たない。
- **締めの段は、計画の末尾に `## 締め` の節を足して Ready にする。** 締め済みの印にし、PR を Ready にし直すだけの段を見分ける。
- **GitHub が未設定（`github:` が無い）のボードでは、Draft の PR の代わりにカードのブランチの計画を読んで計画レビューを立てる。** 締めの段は証拠を `## 締め` の節の下に書き、ブランチの `## 締め` は「ブランチのマージ待ち」の止まりにだけ使う。人が main にマージして push すると、計画が main に入ってマージ済みになる。AI はマージしない。

## 結果

- sync の巻き戻しと外部の定数への追従が構造ごと消えた。1 本の PR が計画レビューから PR中 まで同じ番号で続く。
- カード・計画・判断が 1 つのディレクトリにまとまる。main の計画は作業ツリーではなく置き場所の参照から読むので、メインのチェックアウトがほかのブランチにいてもマージ済みを取り違えない。
- 未設定のボードでは、人は計画をブランチ（`git show <branch>:.ai-board/cards/<id>/plan.md`）で読む。`status` と `decide` は対象のカードの数だけ git を走らせる。
- 未設定のボードには PR中 の列も CI も無い。締めの後に直しを返す口は無く、`decide reject` か人が自分で直す。
- ステージの入力に PR の `draft` が加わった。「まだ Ready にしていない」と「人が Draft に戻した」は `draft` だけでは見分けられず、後で止まりとして扱った（[6](0006-ai-review-entries-and-hold.md)）。

## 退けた案

- **計画の本文をボードの詳細パネルで読ませる（`a85b887`）** — ボードを動かすチェックアウトから計画が見えない。
- **接続済みのボードでもブランチの計画を読む** — Draft の PR を出す前のコミットの時点で計画レビューが立ち、`status` のたびに git を走らせる。
- **ディレクトリごと `cards/archive/<id>/` へ移してマージ済みを示す** — PR の中の移動と、main での `card.md` の書き換えがぶつかる。
