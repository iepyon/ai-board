# 0007. OpenSpec をやめ、計画を `.ai-board/plans/<id>.md` に置いてファイル名でカードに紐付ける

- 状態: 採用
- 日付: 2026-09-26（PR #5 のマージ）
- 置き換え元: なし
- 置き換え先: なし

## 状況

ai-board は「OpenSpec 駆動開発のためのローカル Web カンバン」として始まり、ステージは `openspec/` ディレクトリ・GitLab・カードファイルの実態から導出していた。
カードは `change` フィールドで OpenSpec の change 名を持ち、計画レビューの列は `proposal.md` の存在で立っていた。
change は `/opsx:explore` → `/opsx:propose` → `/opsx:apply` → `/opsx:archive` で回し、スキルとコマンドを `.claude/` に置いていた。

困っていたことは 2 つあった。

- **archive が `openspec/specs/` を書き換える操作だった。** `board-lanes` は MR のマージで `merged` に入ったが、archive されず `openspec/specs/` は空のままだった。
  後続の `drop-explore-lanes` の delta を重ねた後で `board-lanes` を archive すると、sync が `ADDED` の要件を書き戻し、後続の変更を黙って巻き戻す。
  実際には人が sync を飛ばして避けたが、その判断の材料はボードにもファイルにも出ていなかった（カード `archive-sync-gap`）。
- **OpenSpec の実装に追従する義務があった。** archive の日付プレフィックスや tasks の行パターンは `@fission-ai/openspec` v1.13.0 の定数から移植しており、上げるたびに突き合わせが要った。
  change 名が日付で始まると完了判定が外れる既知の未追従（#1309）も残っていた。

PR #5 の本文は、Plan モードで立てた計画をそのまま成果物にした方が工程が短いことも理由に挙げている。

## 決定

OpenSpec への依存を取り除き、計画は `.ai-board/plans/<card-id>.md` の 1 ファイルだけから読む。

- **計画ファイルの名前がそのままカード ID になる。紐付けのためのフィールドはカードに持たない。** カードの `change` フィールドと `ChangeName` 型を廃止する。
- 計画とタスクを 1 ファイルに持つ。タスクはチェックボックスで書き、その集計はカード上のプログレスバーにだけ使い、ステージ導出の入力にしない。
- **計画ファイルが存在するだけで計画レビューの列が立つ。** 本来のゲートは `## レビュー` の `plan 提出` で、ファイルの存在はログの欠落で人待ちを取りこぼさないための保険とする。
- **`archive/` 配下へ移したことがマージ済みを立てる。** archive はファイルを移すだけの操作になる。
- ID として不正な名前のファイルは警告して読み飛ばす（例外を投げるとボード全体が 500 になる）。
- `openspec/`・`/opsx:*` のコマンド・`openspec-*` のスキルを削除し、形式仕様は `docs/specs/` へ移す。既存の change 4 件は計画ファイル 1 本ずつに畳む。

記録なし。

## 結果

- メイン spec・delta・sync が無くなり、遅れた sync が後続の変更を巻き戻す問題は構造ごと消えた。`archive-sync-gap` は前提が無くなったとして中止した。
- 「マージ済みと archive 済みを見分けられない」という困りごとも、archive がマージ済みを立てる実態になったため成立しなくなった。
- OpenSpec の定数に追従する義務が無くなった。
- 「計画ファイルがあれば計画レビューが立つ」「空ファイルを無視する条件を足さない」「不正な名前は警告して読み飛ばす」は、今も `CLAUDE.md` の設計の不変条件に残っている。
- 計画はブランチに乗るファイルなので、ボードを動かすチェックアウトから見えないことがある。同じ PR で足した計画本文の詳細パネル（`GET /api/plans/:id`）は、
  これを理由に [0011](0011-plan-review-in-draft-pr.md) で廃止した。
- 同じ PR #5 で検証中の列も廃止した（`cecbf0b`）。
