# 11. ループは監視役が次の一手を渡し、計画・実装・レビューの 3 役のサブエージェントが進める

- 状態: 採用
- 日付: 2026-11-02（2026-10-23 から段階的に改訂）

## 背景

最初は `/loop` で回す 1 つのセッションが計画も実装も進め、前のカードの前提が文脈に積もったまま次のカードを書いていた。
その後の改訂は、どれも実際に回して出た問題から来ている。

- AI レビューを実装した本人がかけていた。
- クラウドのセッションではサブエージェントがサブエージェントを立てられず、入れ子の形が止まった。
- 1 タスク 1 起動では読み直しがカード全体のトークンの半分を超え、途中でゲートが落ちる計画の切り方とも合わなかった。

## 決定

- **次の一手はコード（`pickNextAction`）で決め、`ai-board status --json` の `next` / `next.step` として出す。** スキルの文章に何をするかを書かない。
- **監視役は `status` だけを読み、カード本文・計画・差分は読まない。** 渡すのはカード ID・手・`$MAIN` だけで、要約を添えない。
- **サブエージェントを立てるのは監視役だけ（入れ子にしない）。** `board-planner`（計画）、`board-worker`（実装。`next.step` が `review` 以外）、`board-reviewer`（レビュー）。
- **まっさらな文脈で分けるのは、別のカードの間と、実装からレビューへの間だけ。** `board-worker` は 1 回の起動で計画の残りの節を全部倒す。
  節の切れ目は品質ゲートが通るところに置き、ゲートとコミットは節ごと。
- **AI レビューは別役の `board-reviewer` が 1 回だけ行い、コードは直さない。** 重要な指摘（誤り・セキュリティ・データの消失・計画やハードルールとの食い違い・テストの欠落）だけを直すタスクにし、見送った指摘は PR の本文に写す。

## 結果

- 手元でもクラウドでも同じ手順で回る。別のカードの前提は持ち込まない。
- 1 回の起動の文脈は膨らむ。自動の要約が入ったら節の区切りで止まり、続きは計画の `[x]` とコミットから読む。
- 実装の役は節の切れ目でゲートを通すため、未チェックのタスクの順番を直してよい（文の書き換えはしない）。変更は PR で人が確かめる。
- 直した後の差分を AI はもう見ない。人が動作確認（[5](0005-verify-gate.md)）と PR で見る。

## 退けた案

- **ステージをサーバの API から読む** — ループのためにサーバを立て続けることになる。
- **監視役が要約を添えて渡す** — 監視役の文脈にある前のカードの前提が漏れる。
- **`review` を `next.action` の種類にする** — 手の種類が CLI や画面に広がる。段は `implement` の中の区切りとして `next.step` に置いた。
