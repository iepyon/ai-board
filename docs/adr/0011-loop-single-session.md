# 11. ループは本筋のセッションが次の一手を自分で進め、AI レビューだけをサブエージェントに切り分ける

- 状態: 採用
- 日付: 2026-11-02（2026-11-04 に改訂）

## 背景

監視役が次の一手を `board-planner` / `board-worker` / `board-reviewer` の 3 役のサブエージェントに渡す形にしていたが、分けた理由（監視役の文脈を膨らませない、前のカードの前提を持ち込まない、要約で前提が落ちても続ける、人の判断を書く口から切り離す）は今のモデルではほとんど効かなくなった。
一方で、サブエージェントの操作が auto モードの分類器に拒まれる、報告と完了の通知の受け渡しの決まりが要る、繋ぎ込みのためのカードが積もる、といった問題が分けたことから出ていた。

## 決定

- **次の一手はコード（`pickNextAction`）で決め、`ai-board status --json` の `next` / `next.step` として出す。** スキルの文章に何をするかを書かない。
- **`/board-loop` を動かした本筋のセッションが、計画・実装・締めの手を自分で進める。** 手順は `board-loop` の `plan.md` / `implement.md` に置く。1 周で進める手は高々 1 つ。PR中 の人の指摘に応える `fix-pr` の手（`fix-pr.md`）も同じく自分で進める（[ADR 0016](0016-pr-feedback-ai-turn.md)）。
- **別の文脈に切り分けるのは AI レビューだけ。** `next.step` が `review` のとき、本筋のセッションが `board-reviewer` を 1 つ前景で立て、`cardId` / `MAIN` の 2 行だけを渡す。入れ子にならないので、クラウドでも動く。
- **AI レビューは 1 回だけで、`board-reviewer` はコードを直さない。** 重要な指摘だけを直すタスクにし、見送った指摘は PR の本文に写す。
- **手を終えたら同じ手番で `status` を読み直して続ける。** カードが変わっても同じセッションのまま続け、`止まった` か `next` が null か、ほかのループが同じカードを触っているときに止まる。
- 節の切れ目は品質ゲートが通るところに置き、ゲートとコミットは節ごと。節の区切りで止まっても、次の周が計画の `[x]` とコミットから続ける。

## 結果

- サブエージェントの受け渡しの決まり（`ListAgents` の確かめ、報告と完了の通知の順番）が要らなくなる。
- 前のカードの前提が次のカードに紛れ込みうる。手順書でカードの前提を読み直させ、計画レビュー・AI レビュー・PR中 の確かめで拾う。
- 書いた者と審査する者の分離はレビューの段だけになる。計画は人が計画レビューで、差分は `board-reviewer` と人が見る。
- 1 つのセッションの文脈が長く伸び、いずれ自動の要約が入る。節ごとのコミットと計画の `[x]` から続きを読む。
- 人の判断を書く口は技術的には止めていない。周の中で人の判断を自分から書かない、を手順書の決まりで守る。

## 退けた案

- **監視役が 3 役のサブエージェントに渡す（前の形）** — 分けた理由が効かなくなり、受け渡しの決まりと分類器の止まりが残った。
- **レビューを別のセッションで行う** — 人がセッションを立てる手間が増え、間隔運転とつながらない。
- **`review` を `next.action` の種類にする** — 手の種類が CLI や記録の語彙に広がる。段は `implement` の中の区切りとして `next.step` に置いた。
