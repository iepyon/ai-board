# 6. AI が書ける判断は 提出 / 再提出 / 保留 だけにし、止まりを導出してループに押し進めさせない

- 状態: 採用
- 日付: 2026-10-30（2026-11-03、2026-11-05、2026-11-07 に改訂）

## 背景

ループが人の判断より自分の規則を優先して同じ手を出し続ける形が 2 つ見つかった。

- 作業者が差し戻された実装を直しきれずに止まっても痕跡が残らず、毎周同じ `revise-impl` が選ばれて後ろのカードも動かない。
- 人が Draft に戻した PR を、ループが「`gh pr ready` だけ失敗した」と読んで Ready にし直す。

## 決定

- **AI が `## レビュー` に書けるのは 提出 / 再提出 / 保留 だけ。承認 / 差し戻し / 中止 は人だけが書く。** CLI は構造でこれを強制する（提出と保留は種別を中で決める専用の usecase だけを通し、`ai-board card` には承認 / 差し戻し / 中止を足す usecase を渡さない）。
- `保留` は差し戻された計画を直しきれないときの痕跡で、**そのゲートの最新が差し戻しのときだけ**、理由付きで書ける。ゲートを先へ進めない。
- 「止まっている」はステージとは別の派生値 `BoardCard.hold` にし、保存しない。
  保留、判断の後に PR が Draft に戻された（GitHub の `convert_to_draft` のイベントで読む）、提出済みなのに成果物が見えない、のときに立つ。
- ループの選択と `status` の判断待ちは同じ `hold` を読む。止まったカードは飛ばす。
  動作確認の列を無くした後（[5](0005-verify-in-pr.md)）は、保留は plan だけに書け、実装中の止まりは Draft に戻された PR だけになった。
- 1 枚の PR だけを GitHub から引けないときも、そのカードを止まりにする（`hold.kind` が `forge`。人の判断で解く止まりは `decision`）。
  接続はまるごと止めず、ほかのカードは進む。列は前に引けた控えで決め、出せる判断を返さない。次に引ければ外れる。
  GitHub が未設定のボードで PR 番号を持つカードも、同じ `forge` の止まりにする（[3](0003-delegate-github-to-gh.md)）。

## 結果

- 止まったカードは判断待ちに出て、ループは後ろへ進む。人は計画を直させる / 計画から立て直させる / 中止 を選べる。
- 人が Draft に戻した PR をループが勝手に Ready にしなくなった。
- 作業者が保留を書き忘れれば、同じ手が選ばれ続ける。Draft の PR ごとにイベントを 1 回余計に引く。
- 1 枚の PR の失敗（422 など）でループ全体が止まらなくなった。認証・上限・ネットワーク・5xx の失敗は今までどおり全体を止める。

## 退けた案

- **止まったことを `## 探索メモ` や PR のコメントに残す** — 前者は導出の入力にしない自由記述、後者は人のコメントと見分けられない。
- **`verify 提出` で代える** — 何も直っていないまま承認から `ready` へ進みうる。
- **引けなかったカードは控えをそのまま使い、止まりにしない** — 控えが古いと、人の指摘や Draft への戻しを見落としたまま進める。
- **全カードが失敗したときだけ接続をエラーにする** — カードが 1 枚のときに見分けられない。失敗の種類（HTTP のステータス）で見分ける。
