# 21. カードの置き場所を GitHub Issue にし、計画だけを git に置く

- 状態: 採用
- 日付: 2026-11-22（2026-11-28 に改訂）

## 背景

カードの正本は Artifact の DB に置いていたが、使う場では claude.ai が使えず、DB に届かない。使うのは 3 人で、1 つのボードを共有し、各自のローカル PC で動かす。GitHub は使える。
一度は main の Markdown（`.ai-board/cards/<id>/card.md`）に置いたが、書き込みのコミットが main に頻繁に入り、main へ直接 push できることが前提になった（PR 必須の保護を入れられない）。
人は、カードを Issue で管理し、ファイルは最初のカードを入れる seed に退けると決めた。

## 決定

- **カードは、リポジトリ（`.ai-board/config.yaml` の `github.repository`）の Issue に置く。** 1 枚 1 Issue。タイトルがカードのタイトル、本文がカードの本文で、ID・作成時刻・ブランチ・PR 番号などは本文の末尾の隠しコメント（`<!-- ai-board:card {...} -->`）に持つ。
- **判断（提出・承認・着手など）は Issue のコメント 1 件 1 判断。** 隠しコメントに ID・時刻・ゲート・種別を持ち、本文が理由になる。並び順と形の版は、専用の Issue（`ai-board:store`）の隠しコメントに持つ。
- **カードの Issue は `ai-board` のラベルで探す。** **Issue の作者とコメントの作者は、`authorAssociation` が OWNER / MEMBER / COLLABORATOR のものだけを読む。** 公開リポジトリで外の人が判断のコメントを偽造できないようにするため。
- **読み書きは `DocumentStore` の口の Issue 実装（`gh api`）が行う。** 書き込みは、ロックを取って読み直してから `op` を走らせ、差分を Issue の作成・更新とコメントの作成として送る。
- **計画は `.ai-board/cards/<id>/plan.md` に置き、カードのブランチから PR でマージする。** main にあればマージ済み（[4](0004-plans-in-draft-pr.md)）。main の計画は、`origin` の `main` を専用の参照へ fetch して読む。
- **`.ai-board/seed/*.md` は最初のカードの種。** `ai-board store seed` が Issue に起票する。起票した後はファイルを正本にしない。
- **PR の控えとループの記録は各 PC の `.ai-board/local/` に置き、共有しない。** 試すときは `AI_BOARD_STORE` に手元のディレクトリを指し、Issue を作らずに済ませる。

## 結果

- main にカードの書き込みのコミットが入らず、main の保護（PR 必須）を入れられる。カードのブランチが置き場所のファイルを変える心配も無くなり、`check-branch` は要らなくなった。
- Issue の画面で、人がカードを読み・コメントでき、ラベルや検索も使える。
- 書き込みは複数の API の呼び出しで、全部か無しにはならない。ロックは手元だけで、同じカードをほかの人が同時に書くと後の書き込みが勝つ（判断はコメントなので重ならない。並び順は後勝ち）。
- GitHub の API の上限と届く必要が増える。読むたびに Issue を引く（1 回の GraphQL で、コメントが 100 件を超えるカードだけ REST を足す）。
- 人が Issue の画面で本文の末尾の隠しコメントを消すと、そのカードは読めなくなる（警告して読み飛ばす）。

## 退けた案

- **Artifact の置き場所を残し、設定で選べるようにする** — 2 つの実装と手順書の分岐を保守し続けることになる（人の判断）。
- **カードを git の main の Markdown に置く（前の形）** — main に書き込みのコミットが頻繁に入り、main への直接 push が前提になる。
- **SQLite に置く** — 各自の PC に置くと共有できず、1 台に置いて配ると常駐サーバと認証が要る（[17](0017-remove-web-and-server.md) で外したもの）。
