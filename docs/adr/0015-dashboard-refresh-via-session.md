# 15. ダッシュボードの更新はボタンから公開したセッションに頼み、CLI で出し直す

- 状態: 採用
- 日付: 2026-11-03

## 背景

「ボードを見せて」で公開するページは `status --html` の写しで、ひとりでには新しくならず、カードが動くたびにチャットで頼み直していた。
クラウドのセッションには常駐のサーバが無く、このページがボードを読むほぼ唯一の手段である。
人からは、ボタン 1 つで最新になること、Claude がその場で集計し直さず、集計とページをコードで生成することを求められた。

## 決定

- **ページの更新ボタンは、ページを公開したクラウドのセッションに `Claude Code Remote` の `send_message` で決まった 1 文を送るだけである。** セッションは `status --html` を走らせ直して同じ URL に公開し直す。
- **集計・グラフ・ページはすべて `status --html` が作る。** 集計は `src/shared/board-metrics.ts` の純関数、グラフは CLI が描くインラインの SVG で、外部のスクリプトを読まない。
- セッション ID は `--session` で渡し、形を確かめてから JSON にしてスクリプトに埋め込む。渡さなければスクリプトもボタンも入れず、チャットで頼む案内だけを出す。
- 更新を頼むメッセージは人の判断の依頼として読まず、ループの 1 周も走らせず、カードにも書かない（`board-dashboard` のスキル）。
- 宣言する機能は `mcp` の `send_message` だけで、ページに状態を持たせない。判断のボタンも置かない。

## 結果

- 人はチャットに何も打たずに最新のダッシュボードを見られ、同じデータからは毎回同じページができる。
- ページを公開したセッションが生きていないと更新できない。アーカイブされたセッションや手元のセッションでは、案内の文で今の手（チャットで頼む）に戻る。
- `mcp` を宣言したページは公開リンクで共有できない。
- ページを見ている人がセッションにメッセージを送れる入口ができる。送れる文はスクリプトの定数に限り、スキルはその文にだけ応える。

## 退けた案

- **ページが GitHub のコネクタでデータ用ブランチと PR を読み、ページの中でステージを導出する** — 導出の核（`stage-resolver.ts`）をブラウザに作り直すことになり、2 か所の導出が食い違ったときにどちらが正しいか分からなくなる。
- **ページから Claude に頼む（`sample`）** — `sample` はボードのデータに届かない。
- **Artifact の型（Dashboard など）に乗せる** — 型はアカウントごとに違い、手元のテストで形を確かめられない。CLI で HTML を全部作るほうが「同じデータから同じダッシュボード」を守りやすい。
