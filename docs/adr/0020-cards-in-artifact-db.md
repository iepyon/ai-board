# 20. カードの正本は Artifact の DB に置き、置き場所を `DocumentStore` の口に閉じる

- 状態: 採用
- 日付: 2026-11-17

## 背景

カードの正本は git の orphan のデータ用ブランチ `ai-board/data` に置いていた（それ以前は SQLite の `board.db`）。
orphan のブランチ・データのワークツリー・push の楽観ロック・`AI_BOARD_DATA`・`init`・`card export` と特殊なやり方が重なり、fork や研修の準備が手間だった。
人は PC とスマホの両方で開発し、PC を閉じたままスマホからも直したい。オフラインの研修（手元モード）は要らなくなった。
node の CLI は Artifact の DB に届かず、DB を読み書きできるのはページと Claude の `ArtifactData` のツールだけである（CLI から起動した `claude -p` は読めるが、書き込みは人の承認で止まり、`allow` の規則でも外せない）。

## 決定

- **カード・判断・並び順・マージ済みの PR の控え・ループの記録の正本を、ボードのページの Artifact の DB に置く。** URL は git に載せた `.ai-board/config.yaml` の `store.url`。
- **CLI は手元の写し（`.ai-board/store/mirror/`）を読み、書き込みは検査してから送る箱（`outbox/`）に積む。** DB との取り込み・送り出しは Claude が `board-store` のスキルで行い、書き込みは人がいる会話のセッションで行う。
- **置き場所の文書は書き換えない。** 変えるたびに `<ID>~<連番>` の改訂を足し、読むときは最新を使う。`out_dir` の書き出しに版が入らないので、版なしで既にある ID を作ると `batch` ごと拒まれることを楽観ロックに使う。
- **リポジトリは置き場所の口 `DocumentStore` だけを使う。** SQLite に切り替えるときは、書き込み系を含む実装を新たに作り、口の約束のテスト（`document-store.contract.ts`）を当てる。その上の usecase・検査・CLI は変えない。
- ボードの置き場所へ `ArtifactData` で書けるのは、送る箱を指す版なしの `set` だけの `batch` に限る（`.claude/settings.json` の hook）。
- 最初のアイデアカードは `main` の `.ai-board/seed/` に置き、`ai-board store seed` で起票する。データ用ブランチは移した後に人が消す。

## 結果

- PC を閉じたまま、スマホのクラウドのセッションから直せる。fork は `config.yaml` の 2 行とページの公開で始められる。
- 書き込みのたびに Claude の送り出しが要る。端末で CLI だけを打っても置き場所に届かず、人のいないセッション（ヘッドレス・定期実行）は送り出せない。
- AI と人の書き込みの境界は、`ai-board card` の構造に加えて hook と手順書になる。DB の権限は人ごとで、Claude は人の権限で書くため。
- 判断の履歴は改訂の文書に残るが、git のコミットは無い。文書の数は書き込みの数だけ増える（上限は 1 つの Artifact で 25000 件。古い改訂の片付けは別のカード）。
- 写しが古いと古いボードで手を選ぶ。既にある文書の書き換えは送るときに拒まれるが、判断の追記は新しい ID なので止まらない。

## 退けた案

- **データ用ブランチを続ける** — 特殊なやり方が多く、fork と研修の準備が手間（人の判断）。
- **SQLite を今入れる** — PC を閉じたままスマホから直せない。口だけを用意した。
- **CLI から `claude -p` を起動して送り出しまで自動にする** — 書き込みは人の承認で止まり、`allow` でも外せない。
- **送る前に `get` で版を読み、取り込んだときの中身と一致を確かめて版を付ける** — 書き込みのたびに読み出しが増え、版の番号を CLI に渡す手順が要る（人の判断）。
