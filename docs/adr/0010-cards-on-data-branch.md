# 10. カードは git のデータ用ブランチ `ai-board/data` に置き、ワークツリーで共有する

- 状態: 採用
- 日付: 2026-11-01（ワークツリーでの共有は 2026-09-27 から。研修用の手元モードは 2026-11-06 から）

## 背景

カードの正本は git に載らない `.ai-board/board.db`（SQLite）だった。ワークツリーで DB が分かれる問題は、
メインのチェックアウトの DB を共有して解いていた（データのマイグレーションを git に載せる案は約 1,500 行になり、PR #20 で捨てた）。
その後、手元の Mac を閉じたままスマホからクラウドのセッションでボードを回したくなった。
クラウドは毎回新しい clone から始まり、push したもの以外は残らないので、カードが見えなかった。
後に、研修をオンラインでもオフライン（GitHub に届かない環境）でも回せるよう、選択肢を残したくなった。書き込みのたびの fetch と push のままでは、オフラインでは何も書けない。

## 決定

- **カードの正本を、コードの履歴とは交わらない orphan のデータ用ブランチ `ai-board/data` のテキストに置く。** 1 カード 1 ディレクトリ、判断は 1 件 1 ファイルの `log/`（追記だけ）。
- **書き込みは ロック → 取り直し → 検査 → コミット → push の 1 操作。push が拒否されたら rebase せず、取り直して検査からやり直す**（楽観ロック）。
- 手元ではメインのチェックアウトの `.ai-board/data/` を 1 か所だけ置き、どのワークツリーもそこを見る。試すときは `AI_BOARD_DATA` で別の clone を指す。
- `stage-resolver` と usecase の入力は変えず、リポジトリの実装だけを差し替える。
- データのワークツリーへの直接の書き込みと直接の push は `.claude/settings.json` の deny ルールで止める。
- **研修用の手元モード。** データのワークツリーの隣の `data-mode.yaml`（git に載せない）に `mode: local` と書くと、読み書きで `origin` に触れず、書き込みはコミットで終える。
  既定（ファイルが無い・`mode: sync`）は上のとおり fetch と push をする。オフラインの研修は 1 台の Mac で完結し、ワークツリーは同じデータのワークツリーとロックを使うので、push が担う「ほかの環境に渡す」「同時の書き込みを 1 つだけ通す」は要らない。
- **手元の commit を黙って捨てない。** 既定のモードの取り直しは、`origin` に無いコミットが手元にあれば `reset --hard` の前に止まる（`DataStoreLocalAhead`）。上げるか捨てるかは人が決める。

## 結果

- clone した時点でカードが揃い、クラウドのセッションだけでボードを回せる。判断ごとにコミットが残る。
- 2 つの clone から同時に書いても 1 つだけ通る。代わりに書き込みのたびに fetch と push が走り、オフラインでは書けない。
- 形の版（`ai-board-data.yaml`）を上げて push すると古い CLI が読めなくなるので、形を変えるコードは `AI_BOARD_DATA` で試す決まりになった。
- 直接の書き換えへの守りは deny ルールだけで、Bash の書き方次第ですり抜けられる。
- 手元モードで書いたものは `origin` に上がらず、クラウドのセッションやほかの clone から見えない。上げる CLI は無く、人が `git push` する。`ai-board init` は手元モードの対象外。
- push の前にプロセスが落ちて残ったコミットも、黙って捨てずに止まるようになった（手元モードのコミットと見分ける印を持たないため）。
- `board.db` からの移行の `ai-board migrate` は `d2380ce` までの版にあり、今の版は SQLite を読まない。空のデータ用ブランチは `ai-board init` で作る。

## 退けた案

- **GitHub Issues に置く** — クラウドでは GraphQL が使えず、並び順を置く Projects が使えない。
- **SQLite のファイルをブランチに載せる** — バイナリは rebase も確かめもできない。
- **push の拒否で rebase する** — 離れた行の編集を git が黙って混ぜ、検査を経ない状態が push されうる。
- **手元モードを環境変数で選ぶ** — 人がファイルの書き込みで選べる形を望んだ（計画の差し戻し）。
- **手元モードの指定をデータ用ブランチの `config.yaml` に置く** — 全員に効き、クラウドのセッションも push しなくなる。
- **fetch に失敗したら自動で手元モードに倒す** — 一時的に切れただけで `origin` と分かれたコミットが黙って積もる。オンラインかオフラインかは人が選ぶ。
