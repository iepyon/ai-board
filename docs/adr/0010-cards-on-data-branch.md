# 10. カードは git のデータ用ブランチ `ai-board/data` に置き、ワークツリーで共有する

- 状態: 採用
- 日付: 2026-11-01（ワークツリーでの共有は 2026-09-27 から）

## 背景

カードの正本は git に載らない `.ai-board/board.db`（SQLite）だった。ワークツリーで DB が分かれる問題は、
メインのチェックアウトの DB を共有して解いていた（データのマイグレーションを git に載せる案は約 1,500 行になり、PR #20 で捨てた）。
その後、手元の Mac を閉じたままスマホからクラウドのセッションでボードを回したくなった。
クラウドは毎回新しい clone から始まり、push したもの以外は残らないので、カードが見えなかった。

## 決定

- **カードの正本を orphan のデータ用ブランチ `ai-board/data` のテキストに置く。** 1 カード 1 ディレクトリ、判断は 1 件 1 ファイルの `log/`（追記だけ）。
- **書き込みは ロック → 取り直し → 検査 → コミット → push の 1 操作。push が拒否されたら rebase せず、取り直して検査からやり直す**（楽観ロック）。
- 手元ではメインのチェックアウトの `.ai-board/data/` を 1 か所だけ置き、どのワークツリーもそこを見る。試すときは `AI_BOARD_DATA` で別の clone を指す。
- `stage-resolver` と usecase の入力は変えず、リポジトリの実装だけを差し替える。
- データのワークツリーへの直接の書き込みと直接の push は `.claude/settings.json` の deny ルールで止める。

## 結果

- clone した時点でカードが揃い、クラウドのセッションだけでボードを回せる。判断ごとにコミットが残る。
- 2 つの clone から同時に書いても 1 つだけ通る。代わりに書き込みのたびに fetch と push が走り、オフラインでは書けない。
- 形の版（`ai-board-data.yaml`）を上げて push すると古い CLI が読めなくなるので、形を変えるコードは `AI_BOARD_DATA` で試す決まりになった。
- 直接の書き換えへの守りは deny ルールだけで、Bash の書き方次第ですり抜けられる。

## 退けた案

- **GitHub Issues に置く** — クラウドでは GraphQL が使えず、並び順を置く Projects が使えない。
- **SQLite のファイルをブランチに載せる** — バイナリは rebase も確かめもできない。
- **push の拒否で rebase する** — 離れた行の編集を git が黙って混ぜ、検査を経ない状態が push されうる。
