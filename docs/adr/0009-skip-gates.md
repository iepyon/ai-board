# 9. 飛ばす宣言のあるゲートは、AI の提出を承認と読む

- 状態: 採用
- 日付: 2026-11-01（2026-11-03、2026-11-05 に改訂）

## 背景

`skipGates` は人が前もって「このゲートは読まずに通す」と宣言するもので、夜間に `/loop` を回して人が止まる場所を減らすために入れた。
宣言のあるゲートはログを見ずに通過扱いだったので、plan を飛ばすカードは着手した瞬間に実装中へ入り、計画が一度も書かれなかった。
着手していないカードもループが選びうるため、「`startedAt` は人の着手の合図」とぶつかっていた。

## 決定

- **宣言のあるゲートでは、最新の記録が 提出 / 再提出 のとき承認と読む。宣言だけで通過扱いにしない。** 差し戻し・保留・承認はふつうに効く。
- 読み替えは `gateState` の 1 か所で行い、`RULES` に `if` を足さない。エントリの種別は書き換えない（`status` には `plan 提出` のまま見せる）。
- **AI の plan の提出は、着手していないカードでは拒む。** 宣言の有無によらない。plan の提出は plan ゲートが未提出か差し戻されたときだけ。
- 宣言を書く入口は `ai-board decide skip`（チャットからは `board-decide`）だけで、`ai-board card` には足さない。

## 結果

- plan を飛ばすカードも、着手で計画提案中に入って計画を書き、提出した時点で実装中へ進む。
- 宣言は人の承認を前もって預けるものになり、人は後から差し戻しや中止で止められる。
- 宣言は今の値で過去を読むので、後から出し入れすると過去の区間の種類も変わる。

## 退けた案

- **実装中のルールに着手時刻の条件を足す** — 導出に分岐が増え、Draft の PR があっても着手を戻せてしまう。
- **plan の提出をいつでも書けるままにする** — 再提出が承認と読まれ、人の差し戻しや保留を経ずに AI の 1 回の呼び出しで計画を出し直せる。
