# card-review-log Specification

## Purpose

人がカードに下した判断（承認・否決・中止）と、AI が成果物を出した事実・手を止めた事実を、
カード本文の追記専用ログとして残す。否決の理由は AI が次の周回で読む唯一の入力になる。

## Requirements

### Requirement: レビューログの書式

システムは カード本文のレビュー見出し配下を追記専用のログとして解釈しなければならない (MUST)。

1 件のエントリは 1 つの見出し行で始まり、書式は `### <ISO 8601 の時刻> <ゲート> <種別>` とする。
見出しに続く本文はそのエントリの理由文として扱わなければならない (MUST)。

ゲートは計画を確かめる `plan` と、実装を動かして確かめる `verify` の 2 つとする。
種別は 提出 / 再提出 / 保留 / 承認 / 否決 / 中止 の 6 つとする。

#### Scenario: エントリを読み取る

- **WHEN** レビュー見出しの下に規定の書式の見出し行がある
- **THEN** 時刻・ゲート・種別・理由文を持つエントリとして読み取られる

#### Scenario: 次の見出しでセクションが終わる

- **WHEN** レビュー見出しの後ろに別の同レベル見出しが現れる
- **THEN** そこから先はレビューログとして読み取られない

#### Scenario: 書式の壊れた見出しは無視する

- **WHEN** 見出し行の時刻が日付として解釈できない、またはゲートや種別が規定外である
- **THEN** そのエントリは無視され、他のエントリの読み取りは続行される

#### Scenario: レビュー見出しが無い

- **WHEN** カード本文にレビュー見出しが無い
- **THEN** エントリは 0 件として扱われる

### Requirement: ゲートの通過判定

システムは 各ゲートの状態を、そのゲートに属するエントリのうち最も時刻の新しいものから
決めなければならない (MUST)。

- エントリが無い場合は未提出とする
- 最新が 提出 または 再提出 なら人の判断待ちとする
- 最新が 承認 なら通過済みとする
- 最新が 否決 なら差し戻し中とする
- 最新が 保留 なら保留中とする。保留中のゲートを先へ進めては SHALL NOT

別のゲートのエントリを判定に混ぜては SHALL NOT。

中止のエントリを判定に含めては SHALL NOT。中止は工程の進捗とは直交する終端の軸であり、
通過済みのゲートを未通過へ巻き戻しては SHALL NOT。

後ろのゲート（`verify`）の判定では、前のゲート（`plan`）の最新の承認より古いエントリを数えては SHALL NOT。
計画を承認し直したなら、前の計画に対する動作確認の判断はもう効かないためである。
前のゲートの承認のエントリが無い場合（前のゲートを飛ばす宣言のカードなど）は、何も除いては SHALL NOT。

#### Scenario: 否決のあとに再提出された

- **WHEN** plan ゲートの記録が 提出 → 否決 → 再提出 の順に並んでいる
- **THEN** plan ゲートは人の判断待ちになる

#### Scenario: 他のゲートは影響しない

- **WHEN** 廃止された `explore` など規定外のゲート名のエントリだけが並んでいる
- **THEN** plan ゲートは未提出のままである

#### Scenario: verify のエントリは plan の判定に混ざらない

- **WHEN** plan ゲートの記録が 提出 → 承認 の順に並び、その後に verify の否決がある
- **THEN** plan ゲートは通過済みのままで、verify ゲートだけが差し戻し中になる

#### Scenario: 中止はゲートの通過を巻き戻さない

- **WHEN** plan ゲートの記録が 承認 → 中止 の順に並んでいる
- **THEN** plan ゲートは通過済みのままである

#### Scenario: AI が保留を書いた

- **WHEN** plan が承認済みで、verify ゲートの記録が 提出 → 否決 → 保留 の順に並んでいる
- **THEN** verify ゲートは保留中になる

#### Scenario: 保留の後に人が判断した

- **WHEN** verify ゲートの記録が 否決 → 保留 → 否決 の順に並んでいる
- **THEN** verify ゲートは差し戻し中になり、保留は外れる

#### Scenario: 計画を承認し直すと前の動作確認の判断は数えない

- **WHEN** 記録が plan 承認 → verify 否決 → verify 保留 → plan 否決 → plan 再提出 → plan 承認 の順に並んでいる
- **THEN** verify ゲートは未提出になる

#### Scenario: plan を飛ばすカードでは verify の記録が外れない

- **WHEN** カードが plan ゲートをスキップすると宣言し、verify の記録が 提出 → 否決 の順に並んでいる
- **THEN** verify ゲートは差し戻し中になる
