# card-gate-skip Specification

## Purpose

人が事前に「このカードのこのゲートは見ない」と決めた宣言を扱う。
宣言したゲートでは、AI の 提出 / 再提出 を人の承認と同じに読み、通過済みとする。

## Requirements

### Requirement: ゲートの事前スキップ

システムは カードに事前に宣言されたゲートでは、そのゲートの最新の記録が 提出 または 再提出 のとき、
人の承認と同じく通過済みとして扱わなければならない (MUST)。宣言できるのは人だけとする (MUST)。

宣言があっても、レビューログを見ずに通過済みとしては SHALL NOT。
エントリが無ければそのゲートは未提出のままであり、否決 / 保留 / 承認 は宣言の無いゲートと同じく効く。
計画を書く手と人の着手の合図を飛ばさずに、人が読む関所だけを飛ばすためである。

宣言できるのは規定のゲート（`plan` / `verify`）だけとする。規定外のゲート名の宣言は受け付けては SHALL NOT。

人が plan ゲートと verify ゲートのそれぞれを飛ばす宣言を出し入れする手段を、画面に提供しなければならない (MUST)。
宣言を書き換えるとき、他のゲートの宣言を変えては SHALL NOT。
AI エージェントが使う CLI に、宣言を書く手段を設けては SHALL NOT。

#### Scenario: 計画レビューを飛ばしても着手するまではアイデアに留まる

- **WHEN** 着手していないカードが plan ゲートをスキップすると宣言し、レビューの記録が無い
- **THEN** plan ゲートは未提出のままで、ステージは `idea` である

#### Scenario: 計画レビューを飛ばすカードも着手すると計画を書く

- **WHEN** plan ゲートをスキップすると宣言したカードが着手され、レビューの記録が無い
- **THEN** ステージは `planning` になり、AI ループの次の一手は計画を書く手になる

#### Scenario: 計画を提出すると計画レビューを通らずに実装中へ進む

- **WHEN** plan ゲートをスキップすると宣言した着手済みのカードで、計画ファイルが存在し、plan ゲートの最新の記録が 提出 または 再提出 である
- **THEN** plan ゲートは通過済みになり、そのカードは `plan-review` に留まらず `impling` になる

#### Scenario: 計画レビューを飛ばしても人の否決は差し戻しになる

- **WHEN** plan ゲートをスキップすると宣言したカードで、plan の提出の後に人が plan の否決を記録した
- **THEN** plan ゲートは差し戻し中になり、ステージは `planning` に戻る

#### Scenario: 計画レビューを飛ばす宣言を入れても他のゲートは保たれる

- **WHEN** verify だけをスキップすると宣言したカードで、画面から plan の宣言を入れる
- **THEN** スキップの宣言は plan と verify の両方になる

#### Scenario: 動作確認を飛ばす

- **WHEN** 計画が承認済みのカードが verify ゲートをスキップすると宣言し、verify ゲートの最新の記録が 提出 または 再提出 である
- **THEN** verify ゲートは通過済みになり、そのカードは `verifying` に留まらない

#### Scenario: 動作確認を飛ばす宣言を外しても他のゲートは保たれる

- **WHEN** plan と verify の両方をスキップすると宣言したカードで、画面から verify の宣言を外す
- **THEN** スキップの宣言は plan だけになる

#### Scenario: 廃止されたゲートは宣言できない

- **WHEN** API でスキップ宣言に `explore` を含めて更新しようとする
- **THEN** 400 が返り、カードは変更されない

#### Scenario: 廃止されたゲートの宣言が DB に残っている

- **WHEN** DB にあるカードのスキップ宣言に `explore` が含まれている
- **THEN** そのカードは規定外の値として警告され、読み飛ばされる。ほかのカードの読み取りは続き、ボード全体は失敗しない
